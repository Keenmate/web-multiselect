EV01 · Events — addEventListener & the on* twin

Every notification is available two ways and both fire for the same action: the bubbling DOM events select / deselect / change, and the JS properties onSelect / onDeselect / onChange. They're events, not callbacks — the return value is ignored. The DOM listener gets the CustomEvent (read e.detail); the on* property receives the detail itself. Events bubble but are not composed. This picker wires both so you can watch them pair up.

[prop] = on* property handler  ·  [event] = addEventListener

EV02 · beforeSelectCallback — block a selection

An interceptor: runs before an option is added with one ctx — { option, selectedOptions, selectedValues, source } — and returns false to block it (nothing = allow; it may also be async). Here Full-time and Part-time are mutually exclusive — picking one while the other is selected is vetoed. The veto is silent (no event fires); the message below is produced by the callback itself.

Try selecting Full-time, then Part-time.

EV03 · beforeDeselectCallback — protect a required item

The mirror interceptor on the way out. Team Lead is pre-selected and required — trying to remove it is vetoed, while the other members can be toggled freely. The veto applies to every interactive removal — including bulk gestures (Clear-All, the inline ✕, the count badge's ×), where it runs per option (ctx.source tells you which) and only the vetoed options stay. Programmatic setSelected() and form reset bypass it.

Team Lead can't be removed; the others can.

EV04 · showMessage() — surface a message over the component

A transient toast the component renders on top of itself. Its reason for being: in the fullscreen overlay (phones) the sheet covers the whole page, so your own toasts / inline messages are hidden behind it. This shows above the panel in both presentations — anchored under the control when floating, pinned over the overlay when fullscreen. It's also how a before*Callback explains a veto (ctx.controller.showMessage(…), then return false — demo 3). Content can be text or an element; options are variant (info / warning / danger / success), autoHideMs and placement. Available as el.showMessage() and on el.controller / every ctx.controller. (For the fullscreen overlay itself, see the Responsive & Mobile page.)

The ⚠ / ⛔ / ✅ options fire a message from beforeSelectCallback — the same toasts the buttons below fire imperatively. Turn on “fullscreen preview”, open the dropdown, then select one — the message appears over the sheet.

EV06 · Add new — turn the picker into a creation tool

With allow-add-new on, a search that finds nothing shows a clickable “Add new …” prompt instead of the empty message. Choosing it (click or Enter) fires the add event. The prompt label is set statically via labels.addNew (the {value} placeholder is the typed text) or dynamically via getAddNewTextCallback({ value }). beforeAddCallback({ value }) is async and cancelable — return a rich option to create + select it, false to abort (try adding a name that already exists, e.g. “Anna”), or nothing to just let the add event fire and create the option yourself.

Try typing “Dana”, then click the prompt (or press Enter).

EV07 · Add new — async creation with a rich option

A real creation usually hits a server. The new option comes back as a rich object (avatar + role subtitle) and renders exactly like the seeded members.

EV05 · Callback vs event — the one rule

The line is drawn by whether the component uses the return value:

  • Event (fire-and-forget, return ignored): onSelect, onDeselect, onChange, onAdd, onAction, onReady (each receives the detail), and the bare DOM select/deselect/change/add/action/ready events.
  • Interceptor callback (one contract: false cancels, nothing continues, a value replaces): before*Callback — beforeSelectCallback, beforeDeselectCallback, beforeSearchCallback, beforeAddCallback, beforeActionCallback, beforeKeydownCallback.
  • Data/behavior callback (return consumed as a value): get*Callback / render*Callback / searchCallback.

Every callback takes one ctx argument (per-option callbacks read ctx.option), and every ctx and event detail carries controller (the same facade as el.controller) and element.
