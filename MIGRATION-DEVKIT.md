# Devkit migration — notes to fold into the CHANGELOG

## Suggested CHANGELOG lines

### Changed
- **Examples site on `@keenmate/web-components-devkit`** (^1.0.0-rc09, Vite 7). The shared
  stylesheet, chapter nav, copy-link buttons, controls persistence, analytics snippet and
  variable-manifest check now come from the devkit; pages are fragment pages
  (`<meta name="kmwc:title">`), the landing page is `renderExamplesIndex({ pages })`. New:
  light / dark / auto theme switch on every page, Ctrl/⌘+K chapter search, short chapter links
  (`examples-theming.html#th07`).
- **Ports**: dev 12100, examples preview 12101, image 12110 (the components.json block; 12200 /
  12210 belonged to web-daterangepicker's block). The dev server is strict and won't hop ports.
- **Build config** from `package.json#kmwc` via `defineComponentConfig()` /
  `definePlaywrightConfig()`; Dockerfile, nginx.conf, Makefile, .dockerignore are generated by
  `kmwc sync` (repo-specific make targets in `Makefile.local`). The image builds the site with
  `npm run build:examples` (FlexSearch bundled; no vendored copy, no sed rewrites).
- **Package contents**: `files` ends with `!**/CLAUDE.md`, `!**/.claude`.

### Fixed
- Example pages follow dark mode: page CSS reads the kit's `--kmwc-*` tokens (incl. the option
  markup drawn by render callbacks); native controls are kit-styled. The theming page's theme
  gallery keeps its fixed colours on purpose.
- `component-variables.manifest.json` lists nine public knobs that were read but never listed:
  `--ms-font-family`, `--ms-option-color-focused-hover`, `--ms-option-color-matched-hover`,
  `--ms-option-color-selected-focused`, `--ms-option-title-color-hover`,
  `--ms-option-title-color-selected-hover`, `--ms-option-subtitle-color-hover`,
  `--ms-option-subtitle-color-selected`, `--ms-option-subtitle-color-selected-hover`.
- Examples: EV4b / EV4c are EV06 / EV07 (valid chapter codes); the logging page no longer needs
  a prior library build (`/dist/multiselect.js` import dropped).

## The published bundle

`dist/` keeps its names: `multiselect.js`, `multiselect.umd.js` (UMD global `MultiSelect`),
`style.css`, `index.d.ts`. With the same toolchain the preset's output is byte-identical to the
old config's, except one string. Against the old Vite 5 build:

- `index.d.ts`: identical.
- `multiselect.js` / `.umd.js` / `style.css`: different bytes. Vite 7 brings a newer esbuild
  (other mangled names) and a newer default target (`?.` kept, `inset` shorthand, `@media(hover:hover)`).
  All of that is still below the README's browser floor (Chrome 119 / Firefox 128 / Safari 18).
  The 24 ES exports are the same.
- `window.components['web-multiselect'].config.repository` is now
  `https://github.com/keenmate/web-multiselect` (was `git+https://…/web-multiselect.git`). The
  devkit normalizes it the same way for every component.

## Still open (not part of this migration)

- `kmwc doctor`: 11 errors, all pre-existing rulebook findings plus one devkit false positive:
  - `[loader]`: false positive at core rc17 (`.ms-loader` IS styled, in animations.css;
    `.ms__loader` is our own "Loading state" container). It matters at the core rc18+ bump,
    though: core then draws `<span class="ms__loader">`, which would pick up the container's
    flex / min-height / padding rules. Rename the container (e.g. `.ms__loading`) in the same
    change that moves to the new core.
  - C-NC-8 / C-CSS-7 `.ms-loader`: core rc17's class (rulebook gaps file #9, fixed in core 6d6b768).
  - C-BV-6: input knobs, rulebook gap (#1 / #15).
  - C-BV-9: 8 of 10 are scope re-declarations or the FOUC rule (gap #16); floating.css:708 and
    tree.css:18 are real rule reads. Fix those two, then record C-BV-9 in VALIDATION-NOTES.md.
  - C-RO-4 (`100vw` → `100dvw`, floating.css), C-CST-4 (cascade / ltree imports),
    C-CST-8 / C-NC-11 (`MessageType`), C-NC-4 (`formatValidityCallback` returns void),
    C-NC-6 (`levelMember`, `parentPathMember`, `hasChildrenMember` have no callback twin):
    these change the CSS or the API, so they're out of scope for a migration that must not
    change the bundle.
