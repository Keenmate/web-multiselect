Every UI string goes through core /locale. Keys are flat <elementType>.<name> (placeholders.search, labels.selectedCount, ariaLabels.removeItem, …) — the full list is the labels property in docs/usage.md. Per key: the instance labels (short or full web-multiselect. key) → the element's own translateCallback → the page-wide translateCallback → the page dictionary window.components.locale.labels → the built-in English. The page-wide toggles (LO02, LO03, LO05, LO06) are page-wide: they change every picker on this page, on purpose.

LO01 · Instance labels

Override texts on ONE element with the labels property (or a JSON labels attribute). A short key (labels.selectedCount, buttons.clearSelection) and a full key (web-multiselect.buttons.selectAll) both work; every key you leave out stays English (open the dropdown: the search placeholder is still Search…). The neighbour picker is untouched.

rendered strings

            

            
el.labels = {
  'labels.selectedCount': '{count} vybráno',          // short key
  'buttons.clearSelection': 'Zrušit výběr',
  'web-multiselect.buttons.selectAll': 'Vybrat vše',  // full key
};
// or declaratively
<web-multiselect labels='{"labels.selectedCount": "{count} vybráno"}'></web-multiselect>

        


        
        
        
        

            
LO02 · Page-wide dictionary

            

                One flat dictionary on window.components.locale.labels — the app's translation JSON as loaded,
                full keys 'web-multiselect.<elementType>.<name>', other components' keys side by side —
                translates every multiselect on the page at once. Assigning window.components.locale re-renders the
                live pickers (selection kept). Keys an instance set itself (LO01) still win.
            

            

                
            

            

                

                    

                        
                        
                    

                    

                        
                        
                    

                

                
rendered strings

            

            
// e.g. const labels = await (await fetch('/i18n/cs.json')).json();
window.components.locale = {
  labels: {
    'web-multiselect.placeholders.search': 'Hledat…',
    'web-multiselect.labels.selectedCount': '{count} vybráno',
    'web-multiselect.labels.moreCount': '+{count} další',
    'web-multiselect.messages.noResults': 'Nic nenalezeno',
    'web-multiselect.buttons.selectAll': 'Vybrat vše',
    'web-multiselect.buttons.clearSelection': 'Zrušit výběr',
    'web-daterangepicker.buttons.apply': 'Použít',          // other components share the same JSON
  },
};

        


        
        
        
        

            
LO03 · translateCallback

            

                An app with its own i18n (i18next, FormatJS, …) answers keys through a callback instead of a dictionary. It gets
                { component, key, template, params, locale } — key is the full
                web-multiselect.<elementType>.<name> — and returns the text, or null = not mine.
                The element's own translateCallback is asked first (German, only labels.selectedCount
                here); its null passes the key on to the page-wide one (a small Slovak i18next-like lookup). A key
                the instance labels set (the second picker's labels.selectedCount) is never sent to any
                callback.
            

            

                
                
            

            

                

                    

                        
                        
                    

                    

                        
                        
                    

                

                
rendered strings

            

            
// an i18next-like lookup: a dictionary + t(key, params)
const sk = { 'web-multiselect.labels.selectedCount': '{{count}} vybraté', 'web-multiselect.buttons.selectAll': 'Vybrať všetko' };
const t = (key, params) => sk[key]?.replace(/\{\{(\w+)\}\}/g, (_, p) => params?.[p] ?? '');
const exists = (key) => key in sk;

// page-wide — every component on the page
window.components.locale = { translateCallback: ({ key, params }) => (exists(key) ? t(key, params) : null) };

// one element — asked BEFORE the page-wide callback; null = not mine
el.translateCallback = ({ key, params }) =>
  key === 'web-multiselect.labels.selectedCount' ? `${params.count} ausgewählt` : null;

        


        
        
        
        

            
LO04 · Screen-reader name / tooltip follow

            

                An ariaLabels.x / tooltips.x nobody set takes the first customized key of the same
                <name>, so translating one string of a pair translates its twin. In multiselect no visible
                caption has an aria / tooltip twin of the same name (the buttons.* action buttons are named by their
                visible text), so the pair shown here is the badge remove (×) button: translate only
                tooltips.removeItem (the hover tooltip, enable-badge-tooltips) and the button's
                accessible name ariaLabels.removeItem — which nobody set — follows. The box below reads
                aria-label from the shadow root.
            

            

                
            

            

                
                
                
accessible name of the first × button

            

            
el.labels = { 'tooltips.removeItem': 'Odebrat {item}' };
// → tooltip "Odebrat Apple" AND aria-label "Odebrat Apple" (ariaLabels.removeItem was never set)
// an explicitly set ariaLabels.removeItem always wins over the twin

        


        
        
        
        

            
LO05 · locale + formatting

            

                Numbers in labels ({count} in labels.selectedCount, the dropdown group-count chip) are
                formatted for the element's language: the locale input → the page
                window.components.locale.locale → the browser. 1,234 options are selected in each picker. Multiselect
                formats no dates — numbers only.
            

            
page locale
                
                
                
                
            

            

                

                    

                        
                        
                    

                    

                        
                        
                    

                

                
rendered strings

            

            
<web-multiselect locale="en-US"></web-multiselect>   <!-- "1,234 selected" -->
<script>
  window.components.locale = { locale: 'de-DE' };       // every picker without its own locale: "1.234 selected"
</script>

        


        
        
        
        

            
LO06 · shouldEscapeLabels

            

                Markup labels (labels.addNew, messages.addNewPending, messages.searching)
                are HTML templates: the template's own <b> renders bold, while the {value} — the
                user's typed text, DATA — is always escaped. That is why the typed <i>Ann</i> shows its
                tags as text instead of turning italic. With
                window.components.security.shouldEscapeLabels the whole label is text: the template's
                <b> shows as characters too (for apps whose translators must not inject markup).
            

            

                
                
            

            

                
                
                
the add-new row: markup → shown text

            

            
el.labels = { 'labels.addNew': 'Add <b>{value}</b>' };
// typed "<i>Ann</i>" → Add <b>&lt;i&gt;Ann&lt;/i&gt;</b>   (bold, tags of the data as text)
window.components.security = { shouldEscapeLabels: true };
// → Add &lt;b&gt;&lt;i&gt;Ann…   (the whole label is text)
