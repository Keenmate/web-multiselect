# Web MultiSelect 2.6.0-rc02 — Release Notes

**Released:** 2026-10-22 · **Pre-release** (`npm install @keenmate/web-multiselect@rc`)

rc02 is the first 2.6 release on npm (rc01 was committed but never reached npm), so these notes cover
everything since **2.5.0**. Two themes: built-in **search** got a real matching model
(accent-insensitive by default, match modes, custom term preparation and a richer
`searchCallback` contract), and **theming** now follows `@keenmate/base-css-variables` 2.0 and the
core theme context, so dark mode works in Firefox and Safari.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/web-multiselect/blob/prod/CHANGELOG.md) (sections
2.6.0-rc01 and 2.6.0-rc02); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone**

- [ ] **Search now ignores accents.** `ces` finds `Český`. If you rely on accent-sensitive
      matching, set `search-behavior="case-insensitive"` (the 2.5 behaviour).
      ([details](#search-ignores-accents-by-default))
- [ ] **Theme on a wrapper element:** if your dark/light signal sits on a `<div>` rather than
      `<html>` / `<body>`, add `theme-source="closest"` (or a selector).
      ([details](#dark--light-is-read-from-the-page-not-any-ancestor))

**Theme authors / custom CSS that reads variables**

- [ ] Rename `--base-*` tokens to the base-css-variables 2.0 names
      ([table](#base-css-variables-20-names)).
- [ ] Drop any of the [44 removed `--ms-*` variables](#removed-variables) you set; they never had
      an effect, most have a live counterpart.
- [ ] Compare light **and** dark mode: outlines, focus, placeholders and disabled states now come
      from the base contract ([visible changes](#visible-changes-without-a-migration)).

**`searchCallback` users**

- [ ] Nothing required. `(term, signal)` callbacks keep working; the new third `context` argument
      is optional to use ([details](#your-own-search-context-entries)).

## Behaviour changes

### Search ignores accents by default

Built-in search used to lowercase and compare, so `ces` never found `Český`. The new
`search-behavior` attribute defaults to `normalized`: case **and** diacritics are ignored.

| `search-behavior` | `ces` → `Český` | `čes` → `Český` | `CES` → `Český` |
|---|---|---|---|
| `normalized` (new default) | ✅ | ✅ | ✅ |
| `case-insensitive` (2.5 behaviour) | ❌ | ✅ | ❌ |
| `exact` | ❌ | ❌ | ❌ |

```html
<!-- keep 2.5 matching -->
<web-multiselect search-behavior="case-insensitive"></web-multiselect>
```

It applies to built-in search only. A `searchCallback` does its own matching.

### Dark / light is read from the page, not any ancestor

The component no longer uses `:host-context()` (unsupported in Firefox, partial in Safari). It
reads `data-context-theme`, which `@keenmate/web-components-core` sets after detecting the page
theme once: `data-theme`, `data-bs-theme`, or `.dark` / `.light` on `<html>` or `<body>`. A
per-instance `data-theme` still wins.

A theme signal on a wrapper `<div>` is no longer picked up on its own:

```html
<div class="dark">
  <web-multiselect theme-source="closest"></web-multiselect>   <!-- nearest ancestor with a signal -->
</div>
```

### base-css-variables 2.0 names

| Was | Now |
|---|---|
| `--base-accent-color[-hover\|-active]` | `--base-primary-color[-hover\|-active]` |
| `--base-accent-color-light[-hover]` | `--base-primary-bg-subtle[-hover]` |
| `--base-text-color-on-accent`, `--base-text-on-<role>` | `--base-on-<role>-text-color` |
| `--base-input-color` | `--base-input-text-color` |
| `--base-input-clear-*` | `--base-input-icon-color` / `-icon-bg-hover` |
| `--base-tooltip-color` | `--base-tooltip-text-color` |
| `--base-<role>-bg` (messages) | `--base-<role>-color` |
| `--base-highlighted-*` (selected option) | `--base-selected-*` |

The component's own `--ms-*` names are unchanged, so `--ms-accent-color` overrides still work.
When you override `--ms-accent-color`, also set `--ms-text-color-on-accent`: the text on accent
fills is picked for the base primary, not for your colour.

### Removed variables

44 `--ms-*` variables were declared but nothing read them, so setting them never did anything.
Among them: the `--ms-font-size-*` / `--ms-font-weight-*` / `--ms-spacing-*` scales,
`--ms-badge-bg*` and `--ms-badge-gap` (use `--ms-badges-gap`), `--ms-more-badge-*` and
`--ms-counter-bg*` / `-color` (use `--ms-counter-badge-*`), `--ms-action-btn-*` (use
`--ms-action-button-*`), `--ms-tooltip-color` (use `--ms-tooltip-text-color`). The full list is in
the 2.6.0-rc01 CHANGELOG section.

## New features — search

### Where the term matches: `search-match`

| `search-match` | Matches | Example |
|---|---|---|
| `contains` (default) | anywhere | `kru` → `Český Krumlov` |
| `equals` | the whole value | `haxkl324` → `HAxKL324`, not `HAxKL3245` |
| `starts-with` / `ends-with` | start / end of the whole value | `town` → `Townsend` / `Old Town` |
| `word-starts-with` / `word-ends-with` | start / end of any word | `town` → `Old Town` and `Townsend` |
| `regex` | the term is a pattern | `^(Ústí\|Nové)` |

Case and accents follow `search-behavior` in every mode except `regex`: a regex runs on the
**raw** value, so case and accents are up to the pattern. An unfinished pattern keeps the last
valid result while the user types. Both `search-behavior` and `search-match` are live: change them
from a page-level switch and the open search re-runs in place.

### Preparing the term: `getSearchTermCallback`

```js
// "ha-324/56" finds "HA 324-56", "HA32456" and "HA-324/56"
el.getSearchTermCallback = (term) =>
  new RegExp(term.split(/[^a-z0-9]+/i).filter(Boolean).join('[^a-z0-9]*'), 'i');
```

For built-in search it returns a string (used as-is) or a `RegExp`. `context.target` tells it
whether it's preparing for built-in search (`'internal'`) or your `searchCallback` (`'callback'`).

### Your own search: `context.entries`

`searchCallback(term, signal, context)` gets a third argument:

- `context.searchTerm`: what `getSearchTermCallback` returned (any shape, objects included).
- `context.entries`: every option paired with its search value, which may now be an object.

```js
import { normalizeSearchText } from '@keenmate/web-multiselect';

el.getSearchValueCallback = (c) => ({ title: normalizeSearchText(c.label), zip: c.zip.replace(/\s/g, '') });
el.getSearchTermCallback = (t, ctx) =>
  ctx.target === 'callback' ? { zip: t.replace(/\s/g, ''), text: normalizeSearchText(t) } : t;
el.searchCallback = (t, signal, { searchTerm, entries }) =>
  entries.filter((e) => e.searchValue.zip.startsWith(searchTerm.zip)
                     || e.searchValue.title.includes(searchTerm.text)).map((e) => e.item);
```

`entries` is built on first access and stays the **same array** until the options change, so a
search engine (FlexSearch, …) can key its index on it. Results may be returned synchronously.

### Search values are prepared once

Each option's search value is read and normalized once, then cached. A keystroke over 2,000
options is 2,000 lookups, where it used to re-read and re-lowercase every value. Replacing
`options`, `refresh()`, or changing a member / callback re-prepares.

`normalizeSearchText(text, behavior = 'normalized')` is exported, so custom search can normalize
exactly the way built-in search does.

## New features — theming

- **Theme API re-exported** from core: `setThemeMode('light' | 'dark' | 'auto')`, `getThemeMode()`,
  `getThemeContext()`, `observeThemeContext()`. `setThemeMode` switches every Keenmate component
  on the page at once.
- **Item states match the tree components:** selected and focused options read the shared
  `--base-selected-*` / `--base-focused-*` tokens, with new `--ms-option-bg-selected-hover`,
  `--ms-option-color-selected`, `--ms-option-outline-selected` and
  `--ms-option-title-color-focused` / `-selected`.
- **`--ms-border-width`** (from `--base-border-width`) drives every border; shadows take their
  colour from `--base-shadow-color`; stacking follows `--base-z-dropdown` / `-popover` / `-tooltip`.

## Visible changes without a migration

- **Focused option:** a 1px inset outline, no grey background fill (was 2px plus a fill).
- **Controls:** the input, Select All / Clear All and the count pill use the control outline
  (`--ms-input-border-color`) instead of the faint divider. The focused input shows the soft
  focus halo pure-admin inputs use.
- **Placeholder and hint** use text step 3 (step 4 was too faint, about 2:1).
- **Primary as text** (badge text, "add new", the fullscreen info icon) reads
  `--base-primary-text-color`, at least 4.5:1.
- **Disabled controls** fade by `--base-disabled-opacity` (0.65 with the contract).
- **Standalone accent** is `#0ea5e9` (was `#3b82f6`), matching the contract default.
- **Group headers are about 4px taller**, so the per-group count chip fits with padding.
- **Phone sheet** scale is `1.2 × --ms-rem` (was a fixed 12px), so it's always larger than the
  floating dropdown.

## Fixes

- `mobile-presentation="fullscreen"` closed itself the moment it opened in Firefox and Safari.
- Declarative `<option>` children rendered as "[N/A]" (regressed in 2.5.0).
- Warning / error / success messages were unreadable under the base theme (text matched its
  background).
- A disabled checked checkbox lost its tick; a disabled field showed the accent hover border.
- Fullscreen virtual rows were 12× too tall with `--base-rem` set.
- `search-mode="navigate"` with virtual scrolling didn't scroll to a match below the fold.
- The per-group count chip's `[N]` touched its top and bottom edges.
- Flat-list search didn't trim the term, so `york ` (with a trailing space) missed `New York`.
