# Web MultiSelect 3.0.0-rc02 — Release Notes

**Released:** 2026-11-04 · **Pre-release** (`npm install @keenmate/web-multiselect@rc`)

These notes cover the changes since **3.0.0-rc01**, the last version on npm. Upgrading from 2.x?
Read the [3.0.0-rc01 notes](3.0.0-rc01.md) first — that is the big migration; this rc is smaller.

Three things can break code written for rc01: `@keenmate/web-components-core` rc18 validates
attribute values strictly, the loader CSS classes are renamed, and `search-input-mode` is gone.
Everything else is fixes and behaviour you get for free.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/web-multiselect/blob/prod/CHANGELOG.md) (section
3.0.0-rc02); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone (HTML attributes)**

- [ ] Pixel attributes take a bare integer: `badge-height="24"`, not `"24px"`
      ([details](#strict-attribute-values)). Invalid numbers are now refused, not truncated.
- [ ] `search-input-mode` is gone — use `enable-search="false"`
      ([details](#search-input-mode-removed)).

**Page CSS / `custom-styles`**

- [ ] `.ms-loader` → `.ms__loader` (the spinner); the old `.ms__loader` loading-state container →
      `.ms__loading` ([details](#loader-classes)).
- [ ] `.ms__input--hidden` is gone (it belonged to `search-input-mode="hidden"`).

**JS API users**

- [ ] `window.components.renderLoaderCallback` → `window.components.renderLoadingCallback`.
- [ ] If you relied on `el.x = undefined` being rejected: it now resets the input to its default.
- [ ] If you assign `on*` handlers dynamically: a non-function is now refused (warning) and the
      previous handler kept; use `null` to clear.
- [ ] TypeScript: the `SearchInputMode` type is no longer exported.

## Breaking changes

### Strict attribute values

Core rc18 parses inputs strictly. What used to be silently truncated is now refused: a warning, an
`input-rejected` event, and the previous value kept.

| Before (rc01) | rc02 |
|---|---|
| `badge-height="24px"` → 24 | refused — write `badge-height="24"` |
| `virtual-scroll-item-height="1.5"` → 1 | refused |
| `badge-tooltip-offset="1e1"` → 1 | refused |
| `search-mode="NAVIGATE"` → refused | accepted as `navigate` (enums are case-insensitive and trimmed) |
| `el.badgeHeight = undefined` → refused | resets to the default (like removing the attribute) |

Listen for `input-rejected` (or `onInputRejected`) to catch these in development;
`setAttributes()` returns the rejections.

### `search-input-mode` removed

`search-input-mode` / `searchInputMode` and the `SearchInputMode` type are gone; the attribute is
now ignored.

| Before | rc02 |
|---|---|
| `search-input-mode="readonly"` | `enable-search="false"` |
| `search-input-mode="hidden"` | `enable-search="false"` + `labels='{"selectPlaceholder":""}'` |
| `search-input-mode="normal"` | drop it |

`readonly` repeated `enable-search="false"` (plus an untypeable search box in the fullscreen
header); `hidden` was the same with an invisible input, which in single-select also hid the
selected label. `enable-search="false"` itself got better in this rc — see
[the search-off picker](#the-search-off-picker).

### Loader classes

| Before | rc02 |
|---|---|
| `.ms-loader` (the default spinner) | `.ms__loader` |
| `.ms__loader` (the dropdown's loading-state container) | `.ms__loading` |

`.ms__loading-text`, the `--ms-loader-*` tokens and the `ms-loader-spin` keyframes keep their names.

## Behaviour changes

### Arrow keys skip disabled options

↑ / ↓, Home / End, Page Up / Page Down and navigate-mode Ctrl + ↑ / ↓ never land on a disabled
option — nor does the first search result, the first navigate match, or the selected option on
open. Previously the highlight stopped on a disabled row and its focus ring vanished under the
disabled style. Same rule as core's menus and the MUI / Radix / React Aria defaults.

### Dropdowns inside modals and popovers

The dropdown is a node of core's overlay tree: opening a multiselect inside an open modal /
popover / dropdown registered with core no longer dismisses that container, and closing the
container closes the dropdown. The standalone engine (no `container`) mounts its panels in the
nearest open modal `<dialog>` / `:popover-open` element instead of `<body>`, so they are no longer
inert behind a modal.

### Motion, logging, scroll lock (core rc18)

- **Page-wide motion** is written to `<html data-motion>`, so a nearer `<section data-motion>` now
  wins over `window.components.motion`.
- **Log levels coalesce closest first:** element → `window.components['web-multiselect'].logging`
  → `window.components.logging` → `warn`. Every warning now goes through the loggers, so
  `disableLogging()` silences them all.
- **The fullscreen sheet locks body scroll on iOS Safari** too (core `lockBodyScroll()` pins
  `<body>`); the page doesn't jump on close.

## New API

| Surface | What |
|---|---|
| `input-rejected` event / `onInputRejected` | Every refused attribute / property write (detail: `configKey`, `attribute?`, `value`, `reason?`, `kept`, `source`) |
| `resetLogging()` export, `el.resetLogging()` | Clear the type's / element's own log levels so it follows the next level up |
| `setCategoryLevel(category, null)` | Clear one category |
| `InputRejection` type | Re-exported |

## Fixes

### The search-off picker

`enable-search="false"` is now a proper picker:

- The input is natively read-only — no caret, no soft keyboard on phones — and the shown value can
  be selected and copied (Ctrl+C / Ctrl+A were swallowed before). In single-select you could type
  over the shown label while the dropdown was closed.
- Escape closes in one press (it used to erase the single-select label first).
- In the fullscreen sheet the ✕ sits at the trailing edge, vertically centred (it fell to the
  leading edge, ~1rem high).

### Visible fixes

- **Option tooltips survive a pick** with the dropdown open (multi-select); they stopped showing
  until a reopen. A value such as `option-0` no longer takes over another tooltip.
- **`checkbox-align="top"`** puts the checkbox on the first text line (first baseline), so a
  custom-rendered first row (bigger title, icon, pill) no longer leaves it above the text.
- **Disabled / readonly controls** no longer draw a remove ✕ on badges (removal was already
  blocked); a disabled control's badges dim with the field.
- **The fullscreen search clear** uses the field-clear ✕ (`--ms-icon-clear` →
  `--base-icon-clear`), so themes reach it; it was a fixed magnifier-with-x.
- **Search highlighting** never puts `<mark>` inside a tag or entity (`amp` on `Tom &amp; Jerry`).
- **The "+N more" remove tooltip** follows `labels.removeHiddenItems` (it was hardcoded English).

### Data and security

- **A quote in an option value** (`say "hi"`) broke selection and badge removal; option values and
  tree paths are now escaped in attributes.
- **The security notice was wrong:** only option values and tree paths are escaped. Display value,
  full title, `getBadgeDisplayCallback`, subtitle and icon are HTML by design — sanitize untrusted
  data first.

### Smaller

- `collapse-badges-below` reads the layout width, so a `transform: scale()` no longer confuses it.
- `component-variables.manifest.json` lists nine public knobs that were read but never listed.
