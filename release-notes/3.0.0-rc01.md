# Web MultiSelect 3.0.0-rc01 — Release Notes

**Released:** 2026-11-03 · **Pre-release** (`npm install @keenmate/web-multiselect@rc`)

These notes cover the changes since **2.6.0-rc03**, the last version on npm (2.6.0-rc04 was never
published; its changes are folded in here). Upgrading from 2.5? Read the
[2.6.0-rc02](2.6.0-rc02.md) and [2.6.0-rc03](2.6.0-rc03.md) notes first.

This is a **major release: breaking, with no aliases.** Callbacks, events and action buttons
follow the shared KeenMate interaction model, and inputs follow one naming vocabulary across the
KeenMate components (`@keenmate/web-components-core` 1.0.0-rc17). Code written for 2.x needs
updating: the old names are gone (`mobile-presentation="fullscreen"`, for example, is now an
unknown attribute). A `^2.x` range will not pull this version.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/web-multiselect/blob/prod/CHANGELOG.md) (section
3.0.0-rc01); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone (HTML attributes)**

- [ ] Rename attributes ([table](#attributes-and-properties)): `mobile-presentation` →
      `presentation`, `disabled-member` → `is-disabled-member`, `badges-max-visible` →
      `max-visible-badge-count`, `option-height` → `virtual-scroll-item-height`,
      `virtual-scroll-buffer` → `virtual-scroll-overscan`, `should-keep-search-on-close` →
      `keep-search-on-close`, `sticky-actions` → `actions-sticky`,
      `tab-behavior="select-highlighted"` → `tab-behavior="select-focused"`.
- [ ] Move every UI string into `labels` ([table](#ui-strings--labels)): `search-placeholder`,
      `select-placeholder`, `empty-message`, `loading-message`, `add-new-text`, … are gone.
- [ ] `initial-values` → `value` attribute, parsed per `value-format`
      ([details](#initial-selection-and-form-value)). `value-format="csv"` → `value-format="text"`.
- [ ] `show-debug-info` is gone — use `el.enableLogging()` ([details](#removed)).
- [ ] Data with a `group` / `icon` / `subtitle` / `disabled` field is now grouped / iconed /
      disabled by it ([details](#member-defaults-for-all-data)).
- [ ] Check your browser support matrix ([requirements](#requirements)).

**JS API users**

- [ ] Rename properties ([table](#attributes-and-properties)): `isMultipleEnabled` → `isMultiple`,
      `isCloseOnSelect` → `shouldCloseOnSelect`, `formFieldId` → `name`, `initialValues` →
      `defaultValue`, `deferRender` → `shouldDefer`, …
- [ ] Selection state is properties now ([table](#selection-state-and-methods)):
      `getSelected()` → `selectedOptions`, `getValue()` → `selectedValue`, `selectedItem` →
      `selectedOption`, `searchText` → `searchTerm`, `controller.clearAll()` →
      `el.controller.clearSelection()`.
- [ ] `el.ready()` → `el.release()`; `is-ready` → `ready` ([details](#defer-ready-destroy)).
- [ ] `el.value` is now the live submitted value, not the initial selection
      ([details](#initial-selection-and-form-value)).
- [ ] `scrollToIndex()` / `scrollToValue()` / `scrollToGroup()` return `Promise<boolean>`.
- [ ] Drive the element through `el.controller`; `WebMultiSelect` → `MultiSelectEngine`
      (standalone use only) ([details](#controller-and-exported-types)).

**Callback authors**

- [ ] Every callback takes one `ctx`; per-option callbacks read `ctx.option`
      ([table](#callbacks-take-one-ctx)).
- [ ] `getDisabledCallback` → `getIsDisabledCallback`, `customStylesCallback` →
      `getCustomStylesCallback`, `addNewCallback` → `beforeAddCallback`, `keydownCallback` →
      `beforeKeydownCallback` (return `false` to suppress, was `true` = handled).
- [ ] `beforeSelectCallback` no longer vetoes on a returned string — return `false` and show a
      message yourself ([details](#before-hooks)).
- [ ] A `get*Callback` now always beats its member.

**Event listeners**

- [ ] `on*` properties receive the **detail**, not the `CustomEvent`
      ([details](#events)). `addEventListener` code is unchanged.
- [ ] Events are `composed: false`: listen on the element or an ancestor of it.
- [ ] `'clear-all'` (action id, `ctx.source`) → `'clear-selection'`.

**Action button users**

- [ ] `{ action: 'custom', … }` → `{ id: '…', … }`; `onClick(ms, ctx)` → `onClick(detail)`
      ([table](#action-buttons)).
- [ ] Button text is inserted as text, not HTML.

**Form users**

- [ ] `form.reset()` now restores the initial selection instead of clearing it, and fires no
      `deselect` / `change` ([details](#form-reset)).
- [ ] `value-format="csv"` → `value-format="text"` (+ `value-separator`).

**Theming / CSS users**

- [ ] `--ms-transition-fast` is gone — use `--ms-transition-normal` or `motion="none"`
      ([details](#motion-and-reduced-motion)).
- [ ] The component no longer has its own `prefers-reduced-motion` block.
- [ ] To recolor the field border set `--ms-input-border-color`; `--ms-border-color` is dividers
      and panel edges only ([details](#css)).
- [ ] Disabled option rows are tinted standalone — `--ms-option-disabled-bg: transparent` for the
      old look.
- [ ] `:host([defer]:not([is-ready]))` → `:host([defer]:not([ready]))` or `:state(ready)`;
      `.ms__badge[data-action="show-selected"]` → `[data-ms-action="show-selected"]`.
- [ ] Remove `--ms-debug-*` and `.ms__debug-*` overrides.
- [ ] `badge-height` has no default any more: the selected-items popover's virtual rows (100+
      selected) are `--ms-badge-height` (27px; was 36px). Set `badge-height="36"` to keep the old rows.

## Breaking changes

### Callbacks take one `ctx`

Every callback takes ONE `ctx` argument. `item` is reserved for action items, so the option a
per-option callback is about is `ctx.option`; there is no bare `index`; search text is `term`.
Every `ctx` (and every event detail) also carries `controller` (the public facade, also
`el.controller`) and `element` (the host) — both non-enumerable, so `JSON.stringify`, logs and
LiveView `pushEvent` see only the data — and the presentation flags (`presentation`,
`isFullscreen`, `isModal`).

```js
// 2.x
el.getDisplayValueCallback = (item) => item.name;
// 3.0
el.getDisplayValueCallback = ({ option }) => option.name;
```

| Old | New |
|---|---|
| `getValueCallback(item)`, `getDisplayValueCallback(item)`, `getIconCallback(item)`, `getSubtitleCallback(item)`, `getGroupCallback(item)`, `getFullTitleCallback(item)`, `getSearchValueCallback(item)`, `getSelectedOrderCallback(item)`, `getPathCallback(item)` | same names, `(ctx)` → read `ctx.option` |
| `getDisabledCallback(item)` | `getIsDisabledCallback({ option })` |
| `getIsSelectableCallback(node)` | `getIsSelectableCallback({ option, node })` |
| `getBadgeDisplayCallback(item, ctx?)`, `getBadgeClassCallback`, `getSelectedItemClassCallback`, `getBadgeTooltipCallback`, `getRemoveButtonTooltipCallback` | `(ctx)` — `{ option, displayMode, isInPopover }` (always complete now; outside a render `displayMode` is the configured mode, `isInPopover` false) |
| `renderOptionContentCallback(item, ctx)`, `getOptionTooltipCallback(item, ctx?)` | `(ctx)` — `{ option, optionIndex, isSelected, … }` (`index` → `optionIndex`) |
| `renderBadgeContentCallback(item, ctx)`, `renderBadgeCallback(item, ctx)`, `renderSelectedItemContentCallback(item, ctx)` | `(ctx)` — `{ option, displayMode, isInPopover }` |
| `renderSelectedContentCallback(item, ctx)` | `(ctx)` — `{ option }` |
| `renderGroupLabelContentCallback(groupName, ctx)` | `(ctx)` — `ctx.groupName` |
| `getCounterCallback(count, moreCount?)` | `getCounterCallback({ count, moreCount? })` |
| `getCountLabelCallback(selected, total)` | `getCountLabelCallback({ selectedCount, totalCount, groupName? })` |
| `getValueFormatCallback(values)` | `getValueFormatCallback({ selectedValues, selectedOptions })` |
| `getAddNewTextCallback(value)` | `getAddNewTextCallback({ value })` |
| `getSearchTermCallback(term, { target, behavior, match })` | `getSearchTermCallback({ term, target, behavior, match })` |
| `searchCallback(term, signal, { searchTerm, entries })` | `searchCallback({ term, signal, entries })` |
| `searchCallback` `entries[i].item` | `entries[i].data` (core `SearchEntry`) |
| `customStylesCallback()` | `getCustomStylesCallback(ctx)` |
| `selectedOrderCompareCallback(a, b)` | `selectedOrderCompareCallback({ a, b })` (`SelectedOrderCompareContext`) — returns a sort number as before |

In `searchCallback`, `term` is the `getSearchTermCallback` result for `target: 'callback'` when
that callback is set, else the typed text (`MultiSelectSearchContext<T, TTerm>`); the separate
`searchTerm` field is gone.

```js
el.searchCallback = async ({ term, signal }) => {
  const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });
  return await response.json();
};
```

### Before-hooks

One contract for every before-hook: `false` cancels, nothing continues, a value replaces. They may
be async (except keydown); a throw cancels (and is logged).

| Old | New |
|---|---|
| `beforeSelectCallback(option, selectedOptions)` → `false` / a string (veto + toast) | `beforeSelectCallback({ option, selectedOptions, selectedValues, source })` → `false` vetoes. A returned string **no longer vetoes**. May be async. |
| `beforeDeselectCallback(option, selectedOptions)` | `beforeDeselectCallback(ctx)` — same shape and contract |
| bulk gestures bypassed the vetoes | each option goes through the veto (see below) |
| `beforeSearchCallback(term)` → string / `null` | `beforeSearchCallback({ term })` → a string replaces the term, `false` skips the search (was `null`) |
| `addNewCallback(value)` → option / `null` cancels | `beforeAddCallback({ value })` → the option (appended + selected), `false` cancels (was `null`), nothing → only the `add` event fires (create it yourself) |
| `keydownCallback(ctx)` → `true` = handled | `beforeKeydownCallback(ctx)` → `false` suppresses the built-in handling (synchronous). `ctx.controller` is the one public controller (focus methods included); `ctx.selectedValues` holds the real values (was strings). |
| — | `beforeActionCallback(detail)` → `false` cancels an action item (its `onClick`, the `action` event and the built-in) |

To explain a veto, show a message and return `false`:

```js
el.beforeSelectCallback = ({ selectedOptions, controller }) => {
  if (selectedOptions.length >= 5) {
    controller.showMessage('Pick at most 5', { type: 'warning' });
    return false;
  }
};
```

**Bulk gestures now go through the vetoes.** Select-All, Clear-selection, the group checkbox, a
tree-cascade toggle, the inline ✕, the count × and the "+N more" × used to bypass
`beforeSelectCallback` / `beforeDeselectCallback`. Now each option is checked, with `ctx.source`
one of `select-all` / `clear-selection` / `group` / `clear` / `badge` / `option`; vetoed options
are skipped and the rest apply in ONE change. `setSelected()` and form reset stay veto-free.

`true` from `beforeAddCallback` or `beforeSearchCallback` means "go ahead" (see [Fixes](#fixes)).

### Events

| Old | New |
|---|---|
| `el.onSelect = (e) => e.detail.option` (all `on*` props got the CustomEvent) | `el.onSelect = (detail) => detail.option` — `onSelect`, `onDeselect`, `onChange`, `onAdd`, `onAction`, `onReady` receive the **detail** |
| `ready` detail `undefined` | `{ controller, element, presentation… }` |
| `MultiSelectEventDetail` (one catch-all type) | `SelectEventDetail`, `DeselectEventDetail`, `ChangeEventDetail`, `AddEventDetail`, `ReadyEventDetail`, `MultiSelectActionEventDetail` |
| events `composed: true` | `composed: false` (dispatched on the host and bubbling — listeners on the element or its ancestors are unaffected) |
| remove-hidden ("+N more" ×) fired one `change` per removed item | one `change` |
| engine option `onAddNew({ value, option })` | `onAdd(detail)` |

`addEventListener('select', (e) => e.detail…)` is unchanged. New events (`action`, `open`,
`close`, `value-format-error`) are under [New features](#new-features).

### Action buttons

Action buttons are core action items.

| Old | New |
|---|---|
| `{ action: 'custom', text, onClick }` | `{ id: 'export', text, onClick }` (`action` is only for built-ins; custom items are identified by `id`) |
| `onClick(multiselect, ctx)` | `onClick(detail)` — the `action` detail (ctx + `action`, `id`, `item`, `source`, `sourceEvent`, `triggerElement`, `dataset`) |
| `getTextCallback(ms, ctx)`, `getIsVisibleCallback`, `getIsDisabledCallback`, `getClassCallback`, `getTooltipCallback` | `(ctx)` — the ctx is the selection snapshot (`selectedValues`, `selectedOptions`, `options`, `selectedCount`, `optionCount`, `isOpen`, `searchTerm`) |
| `ctx.button` | gone — at activation the clicked item is `detail.item` |
| `onClick` only ran for `custom` buttons | runs for built-ins too, before the built-in |
| action id `'clear-all'` | `'clear-selection'` |
| button text inserted as HTML | text and icon are inserted as text |
| `data-button-index` on the button | `data-ms-item-index`; `data-action` = built-in name or `custom`, `data-id` = the item `id` |

```js
el.actionButtons = [
  'select-all',
  'clear-selection',
  { id: 'export', text: 'Export', onClick: (detail) => exportValues(detail.selectedValues) },
];
```

**Internal controls use `data-ms-action`** (`data-action` / `data-id` are reserved for action
items): the add-new prompt, `show-selected`, `clear-count`, `remove-hidden`. A
`renderBadgeCallback` remove control is now `data-ms-action="remove"` (or `.ms__badge-remove`).
CSS that targeted `.ms__badge[data-action="show-selected"]` → `[data-ms-action="show-selected"]`.

Config keys carry the suite prefixes (`is*` / `should*`), attributes are derived from them

`name`.

| Old (property / attribute) | New (property / attribute) |
|---|---|
| `isMultipleEnabled` / `multiple` | `isMultiple` / `multiple` |
| `isCloseOnSelect` / `close-on-select` | `shouldCloseOnSelect` / `close-on-select` |
| `formFieldId` / `name` | `name` / `name` |
| `disabledMember` / `disabled-member` | `isDisabledMember` / `is-disabled-member` |
| `badgesMaxVisible` / `badges-max-visible` | `maxVisibleBadgeCount` / `max-visible-badge-count` |
| `optionHeight` / `option-height` | `virtualScrollItemHeight` / `virtual-scroll-item-height` |
| `virtualScrollBuffer` / `virtual-scroll-buffer` | `virtualScrollOverscan` / `virtual-scroll-overscan` |
| `shouldKeepSearchOnClose` / `should-keep-search-on-close` | `shouldKeepSearchOnClose` / `keep-search-on-close` |
| `isKeepOptionsOnSearch` / `keep-options-on-search` | `shouldKeepOptionsOnSearch` / `keep-options-on-search` |
| `isIconSlotReserved` / `reserve-icon-slot` | `shouldReserveIconSlot` / `reserve-icon-slot` |
| `isOptionTooltipFollowCursor` / `option-tooltip-follow-cursor` | `shouldOptionTooltipFollowCursor` / `option-tooltip-follow-cursor` |
| `isPruneMissingSelectionEnabled` / `prune-missing-selection` | `shouldPruneMissingSelection` / `prune-missing-selection` |
| `isPlacementLocked` / `lock-placement` | `shouldLockPlacement` / `lock-placement` |
| `fullscreenAutofocus` / `fullscreen-autofocus` | `shouldFullscreenAutofocus` / `fullscreen-autofocus` |
| `isActionsSticky` / `sticky-actions` | `isActionsSticky` / `actions-sticky` |
| `mobilePresentation` / `mobile-presentation` | `presentation` / `presentation` (values unchanged: `auto` \| `floating` \| `fullscreen`) |
| `initialValues` / `initial-values` | `defaultValue` / `value` ([details](#initial-selection-and-form-value)) |
| `deferRender` / `defer` | `shouldDefer` / `defer` |
| `tab-behavior="select-highlighted"` | `tab-behavior="select-focused"` (focus = the keyboard cursor) |

**`presentation` and breakpoints.** The core type is `Presentation` (was `MobilePresentation`);
core's deprecated `resolveMobilePresentation()` is gone. Breakpoint defaults follow the base
tokens: the `mobile` width bucket ends at **768px (was 640)**, `tablet` at 1024px, overridable
page-wide with `--base-breakpoint-mobile` / `--base-breakpoint-tablet` or
`configureBreakpoints()`. Device class (`classifyDevice`, the `auto` presentation) is unchanged.

### UI strings → `labels`

Every visible text and ARIA label is a key of the one `labels` map — a property (partial object)
or a JSON attribute. Unset keys fall back to English. The per-string inputs are removed.

```html
<!-- 2.x -->
<web-multiselect search-placeholder="Search…" empty-message="Nothing"></web-multiselect>
<!-- 3.0 -->
<web-multiselect labels='{"searchPlaceholder":"Search…","noResults":"Nothing"}'></web-multiselect>
```

| 2.x | 3.0 `labels` key |
|---|---|
| `search-placeholder` / `searchPlaceholder` | `searchPlaceholder` (+ `filterPlaceholder` / `navigatePlaceholder` for the mode-aware default with `show-search-mode-toggle`) |
| `select-placeholder` / `selectPlaceholder` | `selectPlaceholder` |
| `no-data-placeholder` / `noDataPlaceholder` (closed-input placeholder for an empty list, default off) | `noDataPlaceholder` |
| `empty-message` / `emptyMessage` | `noData` (`No data` — there are no options at all) or `noResults` (`No results found` — options exist, the search matched nothing; also the fullscreen "no matches" counter) |
| `loading-message` / `loadingMessage` (`Loading...`) | `searching` (`Searching…`) — an async `searchCallback` search in flight |
| `search-hint` / `searchHint` | `searchHint` |
| `add-new-text` / `addNewText` | `addNew` (`{value}`) |
| `add-new-pending-text` / `addNewPendingText` | `addNewPending` (`{value}`) |
| `remove-button-tooltip-text` / `removeButtonTooltipText` (`{0}`) | `removeItem` (`{item}`) — one text for the × aria-label and its tooltip |
| `selected-popover-title` / `selectedPopoverTitle` | `selectedPopoverTitle` (`{count}`) |
| `labels.groupSelectedLabel` | `labels.groupSelected` |
| `labels.clearAll` (action button text) | `labels.clearSelection` (default still `Clear all`) |
| `labels.clearSelection` (inline ✕ aria-label) | `labels.clearAllSelections` (one key for both ✕ clear buttons) |
| hard-coded `N selected` / `+N more` / `N of M` / `N matches` / `Switch to … mode` | `selectedCount`, `moreCount`, `matchPosition`, `matchCount` / `matchCountOne`, `switchToFilterMode` / `switchToNavigateMode` |
| hard-coded `[N/A]` for an option without a display value | `noDisplayValue` (default `[N/A]`); the value fallback stays `[N/A]` |

New keys with no 2.x counterpart: `selectAll` (built-in button text) and `valueFormatError`.

- Defaults use a single `…` character: `Pick an option…` / `Search…` (were `...`).
- A label set to `''` is now deliberately empty (renders nothing): `labels.selectPlaceholder: ''`
  no longer falls back to the search placeholder.
- A `labels` change rebuilds the picker (the selection is kept).

### Selection state and methods

Real state is a same-named property on the element AND on `el.controller` — no `get*()`
duplicates.

| Old | New |
|---|---|
| `controller.clearAll()`, engine `clearAll()` | `controller.clearSelection()`, engine `clearSelection()` — on `el.controller`, not on the element |
| `SelectionSource` `'clear-all'` (before-callback `ctx.source`) | `'clear-selection'` |
| `el.getSelected()`, `controller.getSelected()` | `el.selectedOptions`, `controller.selectedOptions` |
| `el.getValue()`, `controller.getValue()` | `el.selectedValue`, `controller.selectedValue` |
| `el.selectedItem` | `el.selectedOption`, `controller.selectedOption` |
| `controller.getOptions()` | `controller.options` |
| `el.searchText` | `el.searchTerm`, `controller.searchTerm` |
| `scrollToIndex()` / `scrollToValue()` / `scrollToGroup()` → `boolean` (element) / `void` (controller) | → `Promise<boolean>` (resolves once scrolled; `false` when closed / not in the visible list) |
| `el.options` returned the assigned array | after the first build, the LIVE option list (same as `controller.options`: whatever source fed it, plus added-new options); the assigned array before the build / while a write is pending |

| Old | New |
|---|---|

### Defer, ready, destroy

Ready / defer / destroy now come from core `BlissElement`.

| Old | New |
|---|---|
| `defer` attribute, `deferRender` property | `defer` attribute, `shouldDefer` property (core) |
| `el.ready()` | `el.release()` (removing `defer` still releases too) |
| `is-ready` host attribute, CSS `:host([defer]:not([is-ready]))` | `ready` host attribute + `:state(ready)` (core) |
| — | `el.whenReady(): Promise<void>` |
| `el.destroy()` (own) | core `el.destroy()`: the element stays inert afterwards (re-inserting it does not rebuild) |

### Initial selection and form value

The rule shared by the KeenMate form components: `el.value` is exactly what the form submits; the
`value` attribute is `defaultValue`. Priority: `getValueFormatCallback` > `value-separator` >
`value-format`.

| Old | New |
|---|---|
| `initial-values` attribute / `initialValues` property | `value` attribute / `defaultValue` property — the initial selection and the `form.reset()` target (the live selection stays `selectedValue`) |
| `initial-values` always JSON-or-CSV | `value` is parsed per `value-format`: `json` (default) / `array` → `["a","b"]` (bare `a,b` still accepted), `text` → `a,b` (split on `value-separator`) |
| `value-format="csv"` | `value-format="text"` (`text \| json \| array`; default stays `json`) — the values joined by the new `value-separator` (default `,`) |
| no `value` property | live `el.value` — get: the submitted value (`string` for `json` / `text` / `getValueFormatCallback`, `string[]` — one per `name[]` field — for `array`; works without `name`). Set: the same form, parsed like the `value` attribute, applied silently (no select / deselect / change); the `value` attribute is not touched |
| `getValueFormatCallback` ignored by `value-format="array"` | the callback wins over every format: one field, also for `array` |

```html
<!-- 2.x -->
<web-multiselect name="tags" initial-values="a,b" value-format="csv"></web-multiselect>
<!-- 3.0 -->
<web-multiselect name="tags" value="a,b" value-format="text"></web-multiselect>
```

### Form reset

`form.reset()` **restores the initial selection instead of clearing it**: the `value` attribute /
`defaultValue` property or declarative `<option selected>` children, like a native `<select>`.
With no initial values the selection is cleared as before. Selecting from JS never rewrites
`value` / `defaultValue`, so it stays the reset default. A reset no longer fires `deselect` /
`change` (it is not a user action, and a native `<select>` doesn't fire them either).

### Member defaults for all data

- `value` / `label` / `group` / `icon` / `subtitle` / `disabled` are now the real member defaults
  (`valueMember`, `displayValueMember`, `groupMember`, `iconMember`, `subtitleMember`,
  `isDisabledMember`) for every data source, not only declarative `<option>` children.
  `ms.options = [{ value: 1, label: 'Prague' }]` works with no configuration (before, it rendered
  `[N/A]` and `selectedValue` returned `null`).
- Data that happens to carry a `group` / `icon` / `subtitle` / `disabled` field is now grouped /
  iconed / disabled by it — set the member to `null` (property) to opt out. Removing a `*-member`
  attribute resets it to the default instead of clearing it.
- **A `get*Callback` now always overrides its member.** Before, the member won when the option had
  that property and the callback was only a fallback.
- Primitive option arrays (`['Prague', 'Brno']`, `[10, 20]`) work: each option is its own value
  and label (they rendered `[N/A]` before).

### Motion and reduced motion

- **One duration:** `--ms-transition-normal` is `var(--base-duration-normal, 0.15s)` and times
  every transition. `--ms-transition-fast` is removed (it was `150ms` — the same speed — and its
  uses read `--ms-transition-normal` now).
- **No reduced-motion block of its own:** the component's `@media (prefers-reduced-motion:
  reduce)` block is gone. Core applies the OS setting on every page, with or without
  base-css-variables (`--base-duration-*: 0s`, `--base-scroll-behavior: auto`), and it beats every
  motion level. The loader no longer slows to 1.5s on its own: that comes from base-css-variables'
  `--base-loader-duration` (without it the loader keeps 0.8s).
- **Motion off:** `motion="none"` ([motion level](#motion-level)), `--ms-transition-normal: 0s`
  on the element, or `--base-duration-*: 0s` page-wide.

### Removed

- **`show-debug-info` / `showDebugInfo`** (deprecated) and the in-component "Debug Info" panel,
  with `.ms__debug-info` / `.ms__debug-stats`, `src/css/debug.css` and the `--ms-debug-*`
  variables. Use per-instance logging instead: `el.enableLogging()`, or the page-wide
  `window.components['web-multiselect'].logging`.
- `--ms-transition-fast`, the own `prefers-reduced-motion` block (above).
- `.ms__add-new-spinner` and `@keyframes ms-spin` (the add-new pending state uses the
  [shared loader](#shared-loader)).

### CSS

- **Disabled option rows get a tinted background standalone:** `--ms-option-disabled-bg` is
  `var(--ms-disabled-bg)` (was `transparent`). Set `--ms-option-disabled-bg: transparent` to keep
  the old look.
- **The field outline is its own token:** standalone `--ms-input-border-color` is the contract's
  control outline (text mixed 45% / 35% into the bg), no longer `--ms-border-color` (the divider) —
  as it already was with the contract loaded. **To recolor the field border, set
  `--ms-input-border-color`**; `--ms-border-color` recolors dividers and panel edges. The checkbox
  border follows the field outline (was a fixed `#8f8f8f`).
- The browser floor (Chrome/Edge 119+, Firefox 128+, Safari 18+) comes from the relative-colour
  syntax in the standalone fallbacks.

## New features

### Motion level

A new `motion` attribute / property (from core, on every component): `none` | `snappy` |
`smooth` | `auto` (default). Also `data-motion="…"` on any ancestor and `window.components.motion`
page-wide. A level sets the `--base-duration-*` speeds and `--base-scroll-behavior`, which
`--ms-transition-normal` / `--ms-scroll-behavior` read.

```html
<web-multiselect motion="none"></web-multiselect>
<section data-motion="snappy">…</section>
```

### The list scrolls, never the page

Keyboard moves, the open-time jump to the selected option and `scrollToIndex()` /
`scrollToValue()` / `scrollToGroup()` scroll only the dropdown's own list (core
`scrollIntoContainer()`), where `scrollIntoView()` also scrolled every scrollable ancestor, page
included. With no scroller in the dropdown (the list fits) it falls back to the page.

New `--ms-scroll-behavior` (`var(--base-scroll-behavior, smooth)`; `auto` under reduced motion and
`motion="none"`): programmatic jumps in the floating dropdown read it (was always `smooth`).

### Responsive rules

Every `<web-multiselect>` takes partial configs per device class / window width (core SPEC §6.7):

- page-wide: `window.components.responsive` / `.responsiveCallback`
- per tag: `window.components['web-multiselect'].responsive` / `.responsiveCallback`
- per instance: `el.responsive` / JSON attribute `responsive`, `el.responsiveCallback`

Precedence: page rules < the element's own attributes / properties < the instance's rules.
Overrides never reflect. A map has two explicit axes: `device` (device class by touch capability)
and `breakpoint` (window width), each keyed `mobile` / `tablet` / `desktop`; device wins on the
same key. Own widths or combinations → `responsiveCallback`.

```js
window.components.responsive = { device: { mobile: { presentation: 'fullscreen' } } };

el.responsive = {
  device:     { tablet: { presentation: 'fullscreen' } },
  breakpoint: { mobile: { badgesDisplayMode: 'count' } },
};
```

Types: `MultiSelectResponsiveMap` / `MultiSelectResponsiveCallback` (core generics over the new
`MultiSelectElementConfig` = `MultiSelectConfig` + element-only inputs); core `ResponsiveMap` /
`ResponsiveCallback` / `ResponsiveContext` / `Presentation` are re-exported. See
`examples-responsive.html` and the "adaptive" section of `examples-action-buttons.html`.

### `disabled` and `readonly`

`disabled` / `readonly` (`isDisabled` / `isReadonly`, reflected):

- **disabled** — no interaction, not focusable, not submitted. An ancestor
  `<fieldset disabled>` disables it too (via core).
- **readonly** — no selection change and no dropdown, but focusable and submitted.

### New events

- **`action`** (+ `onAction`): every action button, built-in or custom, and every `data-action`
  element in rendered option content (`source: 'option'`, `detail.option`), badge content
  (`source: 'badge'`) or a `showMessage` element (`source: 'message'`). Order:
  `beforeActionCallback` → `onClick` → built-in → `action`. The event is a **notification after
  the fact**: it sees the state the built-in left, and the detail's selection snapshot
  (`selectedValues`, `selectedCount`, …) is re-read before it fires, so `select-all` reports the
  new selection. To prevent a built-in use `beforeActionCallback`.
- **`open` / `close`** (+ `onOpen` / `onClose`): the dropdown opened / closed, for any reason.
  `detail` is the context (`controller`, `element`, presentation flags).
- **`value-format-error`** (+ `onValueFormatError`; `ValueFormatErrorEventDetail`) — see below.

### Form validity

A throwing `getValueFormatCallback` no longer propagates. The error is logged (`MULTISELECT:DATA`,
error level), `''` is written into the hidden input (and returned by `el.value`), and the host is
marked invalid through core `setFormatError()`: `validity.customError`, `validationMessage` = the
new `labels.valueFormatError` (default "The value could not be formatted."), so the form refuses
to submit (`<form novalidate>` submits `''`). The `value-format-error` event fires with
`{ error, value }`. The next successful format clears the validity. `el.validity` /
`validationMessage` / `willValidate` / `checkValidity()` / `reportValidity()` come from core.

### Lookup and message state

- `getOptionByValue(value) → option | null` (element + controller): lookup by value (compared as
  strings); also finds a selected option no longer in `options`.
- `isMessageShown` (element + controller), next to `showMessage()` / `hideMessage()`.

### Action items

- String shorthand: `actionButtons: ['select-all', 'clear-selection']` (default text from
  `labels.selectAll` / `labels.clearSelection`).
- `icon`, `isDanger`, `isToggled` / `getIsToggledCallback` (toggle state ON → `aria-pressed`,
  `.ms__action-btn--toggled`; named `isToggled`, not `isActive`, per core), `getIconCallback`.
- `onClick` runs for built-ins too, before the built-in; `beforeActionCallback` can cancel any item.
- CSS: `--ms-action-button-danger-color`, `--ms-action-button-toggled-color`,
  `--ms-action-button-icon-gap`; `.ms__action-btn--danger`, `.ms__action-btn--toggled`,
  `.ms__action-btn-icon`, `.ms__action-btn-label`.

### Shared loader

Every loading state draws through core `renderLoader()`: the async-search loader (context
`search`) and the async add-new pending prompt (context `add-new`). Before, the search state
rendered a `.pa-loader` that never drew inside the shadow root, and add-new had its own border
spinner.

- **Accessible:** the loader slot (`.ms__loader-slot`) gets `role="status"` + `aria-label` =
  `labels.searching` / `labels.addNewPending` as plain text; the visible "Searching…" text is
  `aria-hidden`.
- **Tokens:** `--ms-loader-icon` / `--ms-loader-rotate` / `--ms-loader-duration` /
  `--ms-loader-size`, chained to `--base-loader-*`. The default `.ms-loader` is a `currentColor`
  mask. It never stops; under reduced motion base-css-variables slows it to 1.5s.
- **`renderLoadingCallback`** (property): draw the loader yourself —
  `ctx = { component, context, containerElement, element, label }`, optional cleanup return.
  Beats the page-wide `window.components.renderLoaderCallback`. Its context type is core's
  `LoaderRenderContext`, now exported.

### Exported types

Every callback ctx has a type: `MultiSelectContext`, `ItemContext`, `TreeNodeContext`,
`CounterContext`, `CountLabelContext`, `ValueFormatContext`, `AddContext`, `BeforeSearchContext`,
`SearchTermCallbackContext`, `MultiSelectSearchContext`, `BeforeSelectContext`,
`BeforeDeselectContext`, `SelectedOrderCompareContext`, `SelectionSource`, `KeydownContext`,
`MultiSelectAction`, `MultiSelectActionItem`, `MultiSelectActionEventDetail`, `OpenEventDetail`,
`CloseEventDetail`, `ValueFormatErrorEventDetail`, `MessageType`, `MessageOptions`. Also exported:
`ActionsLayout`, `ActionsPosition`, `ActionsAlign`, `LoaderRenderContext`.

## Visible changes without a migration

**Standalone colours follow the contract** (no visible change with base-css-variables loaded).
Without `@keenmate/base-css-variables` the component used hand-picked fallbacks that had drifted
from the contract. Now inputs fall back to the contract's defaults and everything derived from them
to the contract's formula on the `--ms-*` token, so a standalone `--ms-accent-color` override
brings its hover, tint and text along.

- **Accent:** `--ms-accent-color` is blue `#3b82f6` again (2.6.0-rc03 had sky `#0ea5e9`).
  `--ms-accent-color-hover` = accent 15% toward black (light) / white (dark);
  `--ms-accent-color-light` = accent 10% / 20%; `--ms-text-color-on-accent` = black or white by
  APCA (was always white). New `--ms-accent-text-color` (the accent as text: 45% toward black /
  25% toward white) for badge text, the add-new row and the fullscreen info icon.
- **Surfaces / text:** new `--ms-main-bg` (`#ffffff` / dark `#1e293b`, was `#1a1a1a`),
  `--ms-elevated-bg`, `--ms-disabled-bg`, `--ms-shadow-color`; `--ms-text-color-1` is the
  contract's slate (`#334155` / `#f1f5f9`, was `#111827` / `#f5f5f5`); text levels 3 / 4,
  `--ms-border-color`, `--ms-primary-bg` (hover), tooltip and on-status-fill text are the contract
  formulas.
- **Scales:** standalone z-index = the contract's (dropdown 7500, popover 7600, tooltip 9000, were
  9999 / 10000 / 10000); disabled opacity 0.65 everywhere (was 0.4 / 0.5 / 0.6); shadows use one
  shadow colour (15% light / 40% dark; dropdown `0 8px 16px`); the info icon is the contract's
  glyph.

**Motion and layout**

- **Tree indent:** the per-level step is `calc(var(--base-tree-indent, 1.6) * var(--ms-rem))` —
  **16px (was 12.5px)**, one step with both treeviews and the grid's tree column. The phone
  overlay's `--ms-fullscreen-tree-indent` uses the same multiplier on `--ms-fullscreen-rem` (was
  `1.2 ×`); the first-level `--ms-*-tree-base-indent` padding is unchanged.
- **Keyboard scrolling is always instant** (arrow keys, navigate-mode typing; was `smooth`). The
  fullscreen sheet keeps its instant scroll.
- The dropdown / popover fades were `200ms`, now `0.15s`.
- Reduced motion zeroes the speeds (before: only the add-new spinner slowed down).
- `--ms-disabled-input-opacity` follows `--ms-disabled-opacity` (both read
  `--base-disabled-opacity`, 0.65 — no visual change); the fullscreen nav button reads
  `--ms-disabled-opacity`.

## Fixes

- **Stale hidden form inputs:** a picker rebuild (any reinit input — `labels`, `multiple`, `name`,
  `data-options`, …), a removal or `destroy()` left the previous `<input type="hidden">` fields in
  the light DOM, so the form submitted the old value next to the new one (and under the old
  `name`). `destroy()` now also clears a `value-format-error` validity.
- **Initial selection not submitted:** a `value` attribute / `defaultValue` / `<option selected>`
  is now written to the hidden form input(s) on build — before, a form submitted nothing until the
  first interaction or options update.
- **Selection lost or resurrected on a rebuild:** a `value` assigned before the first build was
  reset by the next rebuild, and a selection the user had cleared came back as the default. A
  rebuild now keeps the live selection (an empty one included, and values whose option isn't
  loaded yet); only a changed `value` attribute replaces it. Selected "add new" options stay
  selected when the option source is re-parsed.
- **DOM moves keep the picker:** moving the element (reorder, into a `<dialog>`, a portal) rebuilt
  it and reset the selection to the default. A move now only closes the dropdown; the picker is
  released when the element stays detached, and re-attaching restores its selection. While
  detached, `value` / `selectedValue` / `selectedOptions` report the held state.
- **Loader stuck on:** clearing the search (Escape, `clearSearch()`, closing, "add new") or a
  `beforeSearchCallback` veto while an async `searchCallback` was in flight left "Searching…" up on
  every later open. Dropping the term now aborts the request (and a pending debounce).
- **A torn-down picker kept acting:** an async `before*Callback` / `beforeActionCallback` that
  resolved after a rebuild or `destroy()` still selected and fired `select` / `change` / `action`.
  It now does nothing. A teardown while open fires `close` (no unpaired `open`).
- `el.value = 'a,b'` / `setSelected([...])` on a single-select held several values.
- Enter on a pending "add new" prompt ran `beforeAddCallback` again and duplicated the option.
- `beforeAddCallback` returning `true` added an option `true`, and `beforeSearchCallback`
  returning `true` searched for `"true"`. `true` now means "go ahead" in both; a non-string term
  from `beforeSearchCallback` is ignored with a warning.
- A tree-cascade toggle with an async `beforeSelectCallback` / `beforeDeselectCallback` could flip
  the subtree back when clicked twice while the veto was pending.
- Changing `search-input-mode` live made a `readonly` control typeable.
- `search-input-mode="hidden"` opened only from the chevron, and Tab skipped the control: the
  hidden input took no clicks and no focus. It is now transparent and read-only — a click on the
  field opens / closes the dropdown, and focus, arrows and Enter work.
- The input's focus ring flashed on every option click (the row's checkbox took focus for a
  moment); with single-select / `close-on-select` focus was lost for good. A press on an option no
  longer moves focus; the input keeps it.
- The selected-items popover's virtual rows (100+ selected) were a fixed 36px — no other badge is —
  and ignored a themed `--ms-badge-height`; in the fullscreen sheet they didn't match its larger
  badges, and a live presentation switch kept the old height. They now measure
  `--ms-badge-height` in the popover itself (`badge-height` still forces a height).
- `scrollToIndex` / `scrollToValue` / `scrollToGroup` with `{ block: 'end' }` in virtual-scroll
  mode put the row at the top; it now lands at the bottom edge.
- A disabled control still ran consumer `data-action` triggers (rendered badges, messages).
- `badges-display-mode` changed while `collapse-badges-below` had collapsed the badges undid the
  collapse until the next resize; the new mode now lands when the box widens.
- `el.options = …` skipped the source precedence: with `<option>` children it showed the assigned
  list until the next rebuild switched back; `el.options = []` blanked out a `data-options` list.
  It now resolves exactly like a build (`<option>` > `options` > `data-options`).
- `form.reset()` while deferred or detached was ignored — a `value` assigned earlier was applied
  on release.
- `min-search-length` was ignored by the built-in (local) search: one character filtered the list
  even with `min-search-length="2"`. Below the threshold the term now counts as empty in both
  filter and navigate mode, flat and tree; changing the attribute live re-runs the typed term.
  The term is counted as typed on both paths (`" b"` passes a minimum of 2) — trimming is
  `getSearchTermCallback`'s job; return `''` from it (or `false` from `beforeSearchCallback`) to
  refuse a term.
- `data-action` markup inside rendered option content was hijacked as an action button (a
  `select-all` there ran Select-All, anything else did nothing); it now fires the `action` event
  and never toggles the row.
- The `actionButtons` description promised default Select-All / Clear buttons when unset; none
  render (and none did).
- Docs: the space reservation before upgrade (`web-multiselect:not(:defined)` in `style.css`) only
  works when `style.css` is linked in `<head>`; `docs/usage.md` said the JS import "includes
  styles". The usage docs now explain this and suggest `modulepreload`, and the example pages link
  the stylesheet so they no longer jump on load.
