# Web MultiSelect 3.0.0-rc04 — Release Notes

**Released:** 2026-11-24 · **Pre-release** (`npm install @keenmate/web-multiselect@rc`)

These notes cover the changes since **3.0.0-rc03**, the last version on npm. Upgrading from 2.x?
Read the [3.0.0-rc01 notes](3.0.0-rc01.md) first, then [3.0.0-rc02](3.0.0-rc02.md) and
[3.0.0-rc03](3.0.0-rc03.md).

This rc moves the picker's text, icons, phone sheets and accessibility onto
`@keenmate/web-components-core`'s shared modules (core rc26, the final v1 names): every UI string
resolves through core `/locale` (flat `<elementType>.<name>` keys whose templates read the text's
context as `{ctx.*}`, a page-wide dictionary, `translateCallback`, a `locale` input that also drives
text sorting), every icon — the picker's own glyphs included, now replaceable by name through the
`icons` map — through core `renderIcon`, the phone sheets are modal through core `startModalSession`,
every render callback gets the shared render `ctx` (`labels`, `isReadonly`, `isDisabled`), and the
search field is an ARIA combobox over a listbox. New: `max-selected-count`, `min-selected-count` and
`required` with form validity.

These can break rc03 code: the `labels` keys are renamed and their templates read `{ctx.*}`; icon
strings follow core's icon order; the picker's own icons are child elements instead of `::before`;
`MultiSelectEngine` is no longer exported; `el.setAttributes()` is now `el.setProperties()`; render
callbacks returning `null` now draw the built-in content; the option row's `ctx.isDisabled` is now
`ctx.isOptionDisabled`; the single hidden form input lost its `id`; and the four JS-written CSS
variables are private (`--_ms-*`). There are no aliases.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/web-multiselect/blob/prod/CHANGELOG.md) (section
3.0.0-rc04); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Everyone (HTML attributes)**

- [ ] Rename every key in a `labels` attribute / property to its `<elementType>.<name>` key —
      `noResults` → `messages.noResults`, `searchPlaceholder` → `placeholders.search`, …
      ([table](#labels-keys-are-flat-elementtypename)).
- [ ] Where one old key fed both an `aria-label` and a tooltip (`removeItem`, `removeHiddenItems`,
      `switchToFilterMode`, `switchToNavigateMode`), set `ariaLabels.<name>`; the `tooltips.<name>`
      twin follows it unless you set it too ([details](#labels-keys-are-flat-elementtypename)).
- [ ] Rewrite label templates to read the context: `{count}` → `{ctx.count}`, `{item}` →
      `{ctx.displayValue}`, `{value}` → `{ctx.value}`, `{position}` / `{total}` → `{ctx.position}` /
      `{ctx.total}`; `labels.matchCountOne` is gone (`labels.matchCount` covers every count)
      ([details](#label-templates-read-the-texts-context-ctx)).
- [ ] With `show-search-mode-toggle`, set `placeholders.filter` / `placeholders.navigate` —
      `placeholders.search` no longer pins one text over the mode texts
      ([details](#the-placeholder-key-follows-the-mode-toggle)).
- [ ] Check option `icon` / action-button `icon` strings: a one-word name that is not a core
      built-in now becomes an icon-font class `<i class="ms__icon name">`
      ([details](#icon-strings-follow-cores-icon-order)).

**JS API users**

- [ ] Replace `new MultiSelectEngine(…)` with a `<web-multiselect>` element driven through
      `el.controller` / `el.setProperties({ … })` ([details](#multiselectengine-is-no-longer-exported)).

- [ ] Rename `el.setAttributes({ … })` to `el.setProperties({ … })`
      ([details](#elsetattributes-is-now-elsetproperties)).

**Callback authors**

- [ ] `getIconCallback` results follow the same icon order as `icon` — return markup, a built-in
      name, or an icon-font class string ([details](#icon-strings-follow-cores-icon-order)).
- [ ] Render callbacks (`renderOptionContentCallback`, `renderGroupLabelContentCallback`,
      `renderBadgeContentCallback`, `renderSelectedItemContentCallback`, `renderBadgeCallback`) that
      return `null` / `undefined` to leave a slot empty: return `false` instead
      ([details](#render-callbacks-null-draws-the-built-in-content)).
- [ ] `renderOptionContentCallback` / `getOptionTooltipCallback` that read the row's
      `ctx.isDisabled`: read `ctx.isOptionDisabled` — `ctx.isDisabled` is now the component's
      effective disabled state ([details](#the-option-rows-ctxisdisabled-is-now-ctxisoptiondisabled)).
- [ ] `getCounterCallback` for the "+X more" badge: `ctx.count` is now the hidden items (=
      `ctx.moreCount`); the selection count is `ctx.selectedCount`
      ([details](#label-templates-read-the-texts-context-ctx)).
- [ ] A `translateCallback` that read `params.count` / `params.item` / `params.value`: read
      `params.ctx.count` / `params.ctx.displayValue` / `params.ctx.value`
      ([details](#label-templates-read-the-texts-context-ctx)).

**Form users**

- [ ] Code that found the hidden input by `id` (`getElementById('tags')`, `<label for>`): select it
      by name — `form.elements.namedItem('tags')` ([details](#the-hidden-form-input-has-no-id)).

**Page CSS / `custom-styles`**

- [ ] Rules aimed at the picker's own glyphs as `::before` (`.ms__toggle::before`, the badge ✕, the
      inline clear, the pager / mode buttons, …): target the child glyph
      (`.ms__toggle > .ms__glyph--toggle`, or `.ms__glyph--<name>`) — or re-skin through the
      `--ms-icon-*` tokens / replace it by name with `icons` ([details](#the-pickers-own-icons-are-child-elements)).
- [ ] A stylesheet that read `var(--ms-input-current-width)`, `--ms-option-height`,
      `--ms-badge-height-virtual` or `--ms-tree-depth`: they are private (`--_ms-*`) — drop the
      `var()` (both panel widths already default to the field width)
      ([details](#runtime-css-variables-are-private)).
- [ ] Rules or test selectors that read the group count chip's text: target
      `.ms__group-count-text` ([details](#group-count-chip-is-spoken)).
- [ ] Rules targeting the virtual list's wrapper / viewport: the rows now sit in
      `.km-virtual-spacer` → `.km-virtual-window.ms__virtual-scroll-viewport`
      ([details](#virtual-lists-on-core)).
- [ ] Rules that relied on the fullscreen sheet being above page tooltips / toasts: it is now the
      modal tier, `--base-z-modal` (7000) ([details](#the-phone-sheet-is-the-modal-tier)).

**Tests / tooling**

- [ ] A test that matched the "sheet trapped by a transformed ancestor" console warning: the text
      is core's now (`the full-screen sheet is trapped in <tag#id> (…)`)
      ([details](#the-phone-sheets-are-modal)).

**Event listeners**

- [ ] Nothing required: no event was renamed and no event detail changed.

## Breaking changes

### Labels keys are flat `<elementType>.<name>`

Every `labels` key now has core `/locale`'s shape (rulebook D-NC-24): a flat
`<elementType>.<name>` key, the element type chosen by where the text is shown. A string that fed
both an `aria-label` and a tooltip / `title` is split into an `ariaLabels.*` and a `tooltips.*` key
with the same `<name>`; core lets an unset twin follow a customized one, so translating one
translates both. A control named by its visible text has no `ariaLabels.*` key (the `select-all` /
`clear-selection` buttons are named by `buttons.*`). English defaults are unchanged apart from the
counts ([next section](#label-templates-read-the-texts-context-ctx)). The instance
`labels` accepts short keys (`messages.noResults`) or full ones (`web-multiselect.messages.noResults`).

| Before (rc03) | rc04 |
|---|---|
| `selectPlaceholder` / `searchPlaceholder` / `filterPlaceholder` | `placeholders.select` / `.search` / `.filter` |
| `navigatePlaceholder` / `noDataPlaceholder` | `placeholders.navigate` / `.noData` |
| `noData` / `noResults` / `searching` / `addNewPending` | `messages.noData` / `.noResults` / `.searching` / `.addNewPending` |
| `noDisplayValue` / `searchHint` / `addNew` | `labels.noDisplayValue` / `.searchHint` / `.addNew` |
| `selectedCount` / `moreCount` | `labels.selectedCount` / `.moreCount` |
| `matchPosition` / `matchCount` / `matchCountOne` | `labels.matchPosition` / `.matchCount` (one key for every count) |
| `selectedPopoverTitle` | `headers.selectedPopover` |
| `selectAll` / `clearSelection` | `buttons.selectAll` / `buttons.clearSelection` |
| `close` / `clearAllSelections` / `clearSearch` | `ariaLabels.close` / `.clearAllSelections` / `.clearSearch` |
| `showFullLabel` / `groupSelected` / `prevMatch` / `nextMatch` | `ariaLabels.showFullLabel` / `.groupSelected` / `.prevMatch` / `.nextMatch` |
| `removeItem` | `ariaLabels.removeItem` + `tooltips.removeItem` |
| `removeHiddenItems` | `ariaLabels.removeHiddenItems` + `tooltips.removeHiddenItems` |
| `switchToFilterMode` | `ariaLabels.switchToFilterMode` + `tooltips.switchToFilterMode` |
| `switchToNavigateMode` | `ariaLabels.switchToNavigateMode` + `tooltips.switchToNavigateMode` |
| `andMore` | `tooltips.andMore` |
| `valueFormatError` | `errors.valueFormat` |

```html
<!-- rc03 -->
<web-multiselect labels='{"noResults":"Nic","searchPlaceholder":"Hledat…"}'></web-multiselect>
<!-- rc04 -->
<web-multiselect labels='{"messages.noResults":"Nic","placeholders.search":"Hledat…"}'></web-multiselect>
```

### Label templates read the text's context (`{ctx.*}`)

A dynamic text hands its context to the label as `{ ctx }` (rulebook D-NC-24), and a template reads it
with a dotted path: `{ctx.count}`, `{ctx.value}`, `{ctx.displayValue}`. The context is the same object
the text's callback gets, where it has one — `labels.selectedCount` / `labels.moreCount` read the
`CounterContext` of `getCounterCallback`, `labels.addNew` the `AddContext` of `getAddNewTextCallback`,
`tooltips.removeItem` the `RemoveItemContext` of `getRemoveButtonTooltipCallback` — and every
`placeholders.*` key gets a `PlaceholderContext` (`selectedCount`, `totalCount`, `searchMode`, `isOpen`,
`key`). Each key's context type is in the `MultiSelectLabels` JSDoc and the usage guide.

`ctx.count` is the number the text's noun agrees with: the selection for `labels.selectedCount`, the
hidden items for `labels.moreCount` and the "+N more" remove button, the matches for
`labels.matchPosition` ("2 of 12" agrees with 12). A `translateCallback` gets the context raw as
`params.ctx`, so one generic bridge pluralizes every key:

```js
el.translateCallback = ({ key, params }) => {
  const options = { ...params, count: params.ctx?.count };   // ctx.count → i18next's plural count
  return i18next.exists(key, options) ? i18next.t(key, options) : null;   // exists() needs count too (plural keys)
};
```

| Key | rc03 template | rc04 |
|---|---|---|
| `labels.addNew` / `messages.addNewPending` | `{value}` | `{ctx.value}` |
| `labels.selectedCount` / `labels.moreCount` / `headers.selectedPopover` | `{count}` | `{ctx.count}` |
| `ariaLabels.groupSelected` / `tooltips.andMore` | `{count}` | `{ctx.count}` |
| `ariaLabels.removeItem` / `tooltips.removeItem` | `Remove {item}` | `Remove {ctx.displayValue}` |
| `ariaLabels.removeHiddenItems` / `tooltips.removeHiddenItems` | `Remove {count} hidden items` | `Remove hidden items: {ctx.count}` |
| `labels.matchPosition` | `{position} of {total}` | `{ctx.position} of {ctx.total}` |
| `labels.matchCount` + `labels.matchCountOne` | `{count} matches` / `{count} match` | `labels.matchCount` = `Matches: {ctx.count}` |

The English defaults put no plural noun after a number, so one template fits every count — real
plurals come from your i18n library through `params.ctx.count`. `getCounterCallback`'s `ctx` gained
`selectedCount`, and its `count` for the "+X more" badge is now the hidden items (`moreCount`), not
the selection. `getCountLabelCallback`'s `ctx` gained `count`, `getRemoveButtonTooltipCallback`'s
`displayValue`. There are no aliases for the old `{count}` / `{item}` / `{value}` templates.

### The placeholder key follows the mode toggle

With `show-search-mode-toggle` the placeholder is `placeholders.filter` / `placeholders.navigate` by
mode; without it, `placeholders.search`. A set `placeholders.search` no longer overrides the mode
texts — no label layer is special. The placeholder is recomputed on every selection change (open or
closed), so a template like `Picked {ctx.selectedCount} of {ctx.totalCount}` stays live.

### Icon strings follow core's icon order

Option `icon`, `getIconCallback` results and action-button `icon` strings are rendered by core
`renderIcon` (SPEC §12.33), one rule for every Keenmate component. Before, an option icon was
inserted as HTML and an action-button icon was escaped as text. Now a string resolves in this
order:

| String | rc04 renders |
|---|---|
| Markup (starts with `<`: `<svg>`, `<img>`, `<i class="…">`) | inserted raw, as before |
| A core built-in name (`check`, `close`, `settings`, `delete`, … — core `BUILT_IN_ICON_NAMES`) | the `--base-icon-<name>` glyph, masked in `currentColor` (`.km-icon`) |
| Anything the element's `renderIconCallback`, then the page-wide one, answers | that markup (`''` = no icon) |
| ASCII class names (`fa-solid fa-flag`, `star`) | `<i class="ms__icon fa-solid fa-flag" aria-hidden="true">` |
| Anything else (an emoji, `1 < 2`, an HTML entity without `<`) | escaped text |

So `'star'` — not a built-in — is now an icon-font class, and a plain word used as an action-button
"icon" (`'Save'`) renders an empty `<i class="ms__icon Save">`. Use a built-in name, markup, or map
your names in `renderIconCallback` ([details](#rendericoncallback)).

### The picker's own icons are child elements

The glyphs web-multiselect draws itself (the chevron, the inline clear ✕, the badge ✕, the floating
popover ✕, the phone sheet's clear-search / mode toggle / match pager / ⓘ, the "add new" +) were the
button's `::before`. They now render through core `renderIcon` under a name, as a child element of
their button or slot: `<span class="ms__glyph ms__glyph--toggle">` inside `.ms__toggle`, and so on.
Unmapped they look the same — still masked from their `--ms-icon-*` token and sized by the slot's
`--ms-*-icon-size` token, the chevron / pager rotations kept — but custom CSS that targeted
`.ms__toggle::before` & co. now targets the child:

```css
/* rc03 */
.ms__toggle::before { background-color: var(--brand); }
/* rc04 */
.ms__toggle > .ms__glyph--toggle { background-color: var(--brand); }
```

To replace a glyph rather than restyle it, map its name in `icons`
([details](#the-icons-map)). The checkbox mark stays CSS (`--ms-icon-check` / `-indeterminate`).

### `MultiSelectEngine` is no longer exported

`MultiSelectEngine` drew the same UI without the custom element; it is gone from the package's
exports (rulebook C-CA-37). Use `<web-multiselect>`: set config as properties or with
`el.setProperties({ … })`, and call methods through `el.controller`. The config, option, context and
event-detail types stay exported.

### `el.setAttributes()` is now `el.setProperties()`

The batched property write is core's (`BlissElement`), and core rc26 renamed it — it takes typed
property values by `configKey`, never attribute strings, so the old name misled. Same arguments, same
single coalesced update, same returned `input-rejected` list; no alias. Attribute strings in one
update stay `el.batch(() => { el.setAttribute(…); … })`.

```js
// rc03
el.setAttributes({ multiple: true, maxSelectedCount: 5 });
// rc04
el.setProperties({ multiple: true, maxSelectedCount: 5 });
```

### The option row's `ctx.isDisabled` is now `ctx.isOptionDisabled`

Every render / display callback's `ctx` now carries the shared render context — `labels`,
`isReadonly` and `isDisabled`, the component's effective state — the same fields every Keenmate
component's render ctx has ([details](#render-callbacks-get-labels-isreadonly-and-isdisabled)). The
option row's own disabled flag in `OptionContentRenderContext` (`renderOptionContentCallback`,
`getOptionTooltipCallback`) therefore moved to `isOptionDisabled`:

```js
// rc03
el.renderOptionContentCallback = (ctx) => ctx.isDisabled ? `<s>${ctx.option.name}</s>` : null;
// rc04
el.renderOptionContentCallback = (ctx) => ctx.isOptionDisabled ? `<s>${ctx.option.name}</s>` : null;
```

`SelectedContentRenderContext` is an interface now (was an alias of `ItemContext`); its fields are a
superset of the old ones.

### The hidden form input has no `id`

The single `<input type="hidden" name="…">` written for `value-format` `json` / `text` /
`getValueFormatCallback` no longer gets `id = name`. Two pickers with the same `name`, or
`<web-multiselect id="tags" name="tags">`, put duplicate ids in the page, so a `<label for="tags">`
or `getElementById('tags')` found the hidden input. The `array` format never had one, nor do the
other Keenmate components' hidden inputs. Select it by name: `form.elements.namedItem('tags')` or
`input[type=hidden][name="tags"]`.

### Runtime CSS variables are private

The four custom properties the component writes from JS as internal state follow the private
`--_ms-*` convention (core's `--_km-*`): `--ms-input-current-width` → `--_ms-input-current-width`
(the live field width on the host), `--ms-option-height` → `--_ms-option-height` (the virtual-scroll
row height), `--ms-badge-height-virtual` → `--_ms-badge-height-virtual` (the virtual
selected-popover row height) and `--ms-tree-depth` → `--_ms-tree-depth` (a tree row's indent depth).
None was a knob — JS overwrote any value you set — and none was in the variable manifest. The public
knobs stay: `--ms-dropdown-width` / `--ms-selected-popover-width` still default to the field width,
`--ms-tree-indent` / `--ms-tree-base-indent`, the `virtual-scroll-item-height` / `badge-height`
attributes. A stylesheet that read `var(--ms-input-current-width)` drops the `var()`.

## Behaviour changes

### Render callbacks: `null` draws the built-in content

`renderOptionContentCallback`, `renderGroupLabelContentCallback`, `renderBadgeContentCallback`,
`renderSelectedItemContentCallback` and `renderBadgeCallback` follow core's one result contract
(`renderSlotHtml`): a string is HTML (as before); `null` / `undefined` draws the built-in content —
the option's icon / title / subtitle, the group name + count, the badge text — where it used to
leave the slot empty (a group label printed `null`); `false` leaves the slot empty
(`renderBadgeCallback`: no badge for that item). A returned element is serialized as before —
markup only; its listeners and properties don't survive.

### Counts in labels are locale-formatted

Counts in labels (`labels.selectedCount`, `labels.moreCount`, `headers.selectedPopover`,
`ariaLabels.removeHiddenItems`, `ariaLabels.groupSelected`, `tooltips.andMore`, the fullscreen match
counters) and the default `[N]` count chip are formatted for the effective locale (`1 234` in
Czech, `1,234` in en-US). A `translateCallback` and a `getCountLabelCallback` still receive the raw
numbers. Pin the old output with `locale="en-US"`.

### The phone sheet is the modal tier

The fullscreen sheet stacks at `--base-z-modal` (7000, core `Z_INDEX`: dialogs, sheets, drawers)
instead of 9001, so the page's toasts (8000) and tooltips (9000) stay visible over it. The
truncated-label reveal inside it uses the tooltip tier, the `showMessage()` toast the toast tier
(`--base-z-toast`).

### The phone sheets are modal

Both phone sheets (the fullscreen dropdown and the fullscreen selected-items popover) run through
core `startModalSession` ([details](#modal-sessions-and-cores-sheet-frame)). What changes for the
user: the page behind is `inert`, Tab cycles inside the sheet — **in the dropdown sheet Tab no
longer closes it** — Escape closes it (the dropdown sheet clears a typed search first, like the
floating dropdown), page scroll is locked, and opening a sheet dismisses the page's open dropdowns /
popovers / menus. A keyboard close returns focus to the control's input (without reopening); a touch
close or Back leaves focus alone, so the soft keyboard stays down. The "sheet trapped by a
transformed ancestor" warning is core's now — once per instance, text `the full-screen sheet is
trapped in <tag#id> (…)`.

### Labels, locale and translators re-render in place

A change of `labels`, `locale`, `translateCallback` or the page-wide `window.components.locale` no
longer rebuilds the picker: the texts re-resolve where they are, and the selection, the search term,
an open dropdown and its scroll are kept. The render callbacks re-run too (they read
`ctx.labels`), and a disabled flip now re-renders the list and badges.

### Text sorting follows the locale

`selected-order="label-asc"` / `"label-desc"` / `"member"` (text keys) and the tree's sibling order
sort with core `getCollator(locale, { numeric: true })` instead of `localeCompare()` with the
browser's default collation. The `locale` input (→ page-wide `window.components.locale` → browser)
decides the order (`cs-CZ` sorts "ch" after "h"), and numbers inside text sort numerically ("item 2"
before "item 10"). Pin a locale with `locale="…"` if the order must not follow the browser.

### Option tooltips hide once a scroll moves their row

A hover-shown option tooltip hides on any scroll around its row (core `createTooltip`
`shouldHideOnScroll`), and only once the row actually moved (3px or more) — a scroll event alone no
longer hides it.

### `dropdown-max-width` is read when the dropdown opens

The cap is applied through core `anchor({ maxWidth })` (`min(cap, available width)`) instead of
being re-written every frame, so a change while the dropdown is open applies on the next open.

### A key cancelled by `beforeKeydownCallback` is left alone

A key the callback cancels (returns `false`) is no longer `preventDefault`'ed, so the browser's own
handling of that key runs.

## New features — localization

### Page-wide labels and `translateCallback`

The instance `labels` wins. For any key it didn't set, the element's `translateCallback` is asked,
then the page-wide one; when neither answers, the page-wide flat dictionary, then English. Assigning `window.components.locale` re-renders live
pickers with the selection kept; `window.components.security.shouldEscapeLabels` applies.

```js
window.components.locale = {
  labels: { 'web-multiselect.messages.noResults': 'Nic nenalezeno' },
  translateCallback: ({ key, template, params, locale }) => i18n.t(key) ?? null,
};
el.translateCallback = ({ key }) => myDict[key] ?? null; // this element only, asked first
```

`translateCallback` gets `{ component, key, template, params, locale }` with the full
`web-multiselect.<elementType>.<name>` key and raw params (`params.ctx` = the text's context); return a string, or `null` /
`undefined` for "not mine". It is never asked for a key the instance `labels` set.

### `locale`

`locale="cs-CZ"` (attribute / property, BCP-47) sets the instance locale for the numbers in labels
and the count chip: instance → page-wide `window.components.locale` → the browser language. `auto`
or no attribute = unset. A change re-renders the labels, selection kept.

## New features — icons

### `renderIconCallback`

`el.renderIconCallback = (name, ctx) => …` maps an icon string that is not markup and not a
built-in name, before the page-wide `window.components.renderIconCallback`. Return markup (`''` = no
icon) or `null` / `undefined` for "not mine". `ctx` is `{ component, element, prefix: 'ms' }` plus
`option` (an option icon) or `item` (an action button) — the page-wide hook gets the same `ctx` now.
Changing either hook after the picker rendered repaints the icons in place (core `iconsChanged()`),
keeping the selection, the search term, the scroll and an open dropdown — so the page hook may load
after the components.

### The `icons` map

The glyphs web-multiselect draws itself have names, and the new `icons` input (property / JSON
attribute, `MultiSelectIcons`) replaces one by name — like `labels`, for icons. Page-wide,
`window.components.icons` does the same (`'web-multiselect.<name>'` before `'<name>'`); the element's
map wins.

| Name | Where |
|---|---|
| `toggle` | the dropdown chevron |
| `clearSelection` | the inline clear ✕ (`show-clear`) |
| `removeItem` | the ✕ on a badge |
| `closePopover` | the ✕ of the floating selected-items popover |
| `clearSearch` | the ✕ in the phone sheet's search field |
| `navigateMode` / `filterMode` | the phone sheet's search-mode toggle |
| `prevMatch` / `nextMatch` | the phone sheet's match navigator |
| `showFullLabel` | the ⓘ on a truncated phone-sheet row |
| `addNew` | the + on the "add new" row |

```html
<web-multiselect icons='{"toggle":"fa-solid fa-caret-down","removeItem":"close"}'></web-multiselect>
<script>
  window.components.icons = { 'web-multiselect.clearSelection': '<svg …>…</svg>' };
</script>
```

A mapped value is read by the same icon order (markup, a built-in name, the hooks, class names). The
order for a name (core rc26): markup → `icons` → `window.components.icons` → built-in → the
`renderIconCallback` hooks → ms's glyphs → class names → text — so the hooks see ms's names too. A
change repaints every icon in place. The chevron / pager rotations apply to a replacement, and the
slot's `--ms-*-icon-size` token sizes it. See
[docs/examples.md → ms's own icons](../docs/examples.md#mss-own-icons-icons) and card CR11.

## New features — custom rendering

### Render callbacks get `labels`, `isReadonly` and `isDisabled`

Every render / display callback's `ctx` (`MultiSelectRenderContext`, the web-treeview shape) carries
`labels` (`ctx.labels.text(key, params)` / `ctx.labels.html(key, params)` — instance `labels` → the
`translateCallback`s → page-wide labels → English), `isReadonly` and `isDisabled` (the effective
state, a disabled `<fieldset>` included): `renderOptionContentCallback`, `getOptionTooltipCallback`,
`renderBadgeContentCallback`, `renderBadgeCallback`, `renderSelectedItemContentCallback`,
`renderSelectedContentCallback`, `renderGroupLabelContentCallback`, `getBadgeDisplayCallback`,
`getBadgeClassCallback`, `getSelectedItemClassCallback`, `getBadgeTooltipCallback`,
`getRemoveButtonTooltipCallback`, `getCounterCallback`, `getCountLabelCallback`,
`getAddNewTextCallback` (and `beforeAddCallback`). `renderLoadingCallback` keeps core's
`LoaderRenderContext`.

```js
el.renderOptionContentCallback = ({ option, labels, isReadonly, isDisabled }) =>
  `<span class="${isReadonly || isDisabled ? 'muted' : ''}">${option.name}</span>`
  + (option.isDraft ? ` <small>${labels.html('labels.addNew', { ctx: { value: option.name } })}</small>` : '');
// el.isReadonly = true / el.labels = {…} / window.components.locale = {…} → the rows re-render in place
```

A change of `labels`, `locale`, a translator, `isReadonly` or the effective disabled state re-runs the
rendered callbacks in place. See card CR12 (`examples-custom-rendering.html`).

## New features — phone sheets

### Modal sessions and core's sheet frame

The fullscreen dropdown and the fullscreen selected-items popover are modal through core
`startModalSession` (rulebook C-CA-19): `role="dialog"` + `aria-modal="true"`, an inert page, a Tab
trap, Escape / the phone Back gesture close, a scroll lock, and the dropdown sheet shrinks above the
soft keyboard. A sheet opened by a press swallows that tap's trailing click (core ghost-click guard).
The behaviour changes are listed [above](#the-phone-sheets-are-modal).

The frame is core's `.km-sheet` (`SHEET_CHROME_CSS`) — same geometry, plus core's slide-in. Closing
(✕, Escape, Back, a pick that closes, `el.close()`) now plays core's exit animation (`animateOut`,
`km-sheet--closing`, inert while it runs); `motion="none"` / OS reduced motion close at once, and
reopening mid-exit shows a fresh sheet immediately. The dropdown sheet's header is core's
`createSheetHeader` (the search field is its content) with the same classes
(`km-sheet-header ms__fullscreen-header`, `km-sheet-close ms__fullscreen-close`).
`--ms-fullscreen-bg`, `--ms-fullscreen-text-color` and `--ms-z-index-fullscreen` keep working; unset,
a page-wide `--km-sheet-*` now applies.

## New features — accessibility

### Combobox / listbox

The search field is a `role="combobox"` (`aria-expanded`, `aria-autocomplete="list"`,
`aria-controls`) over a `role="listbox"` of `role="option"` rows with `aria-selected` /
`aria-disabled`. `aria-activedescendant` follows the keyboard highlight (core `/a11y`) while focus
stays in the field; the row checkboxes are decorative (`aria-hidden`, `tabindex="-1"`). Typing is
IME-safe: composing doesn't search, and the Enter that confirms a candidate doesn't pick. See
[docs/accessibility.md → Combobox pattern](../docs/accessibility.md#combobox-pattern).

## New features — selection

### `max-selected-count`

`max-selected-count="5"` caps the user's picks in multiple mode. At the limit the other options are
`aria-disabled` (`ms__option--limit`, dimmed) and can't be picked by click, keyboard, a group checkbox,
"add new" or `controller.selectValue()`; Select All picks only up to the limit, in display order; reaching
it is announced (`messages.limitReached`). A programmatic value (`el.value`, `setSelected()`) is not
truncated. The placeholder reads the picks left:

```html
<web-multiselect multiple max-selected-count="5"
  labels='{"placeholders.search": "Select up to {ctx.remaining} more"}'></web-multiselect>
```

`ctx.count` is the remaining picks then, so a `translateCallback` plural agrees with it ("Vyberte ještě
1 položku / 2 položky / 5 položek" with `Intl.PluralRules('cs')`). See
[docs/usage.md → Selection limit](../docs/usage.md#selection-limit-max-selected-count) and the
localization page LO07–LO09. A value set above the limit from code makes the control invalid
(`rangeOverflow`, below).

### `required`, `min-selected-count` and form validity

`required` makes an empty selection invalid: `validity.valueMissing`, `:invalid`, the form won't
submit, and the browser's validation bubble points at the control's input. `min-selected-count="3"`
flags a selection of 1–2 as `rangeUnderflow` (an empty one is `required`'s business, like a native min
rule), and a value set above `max-selected-count` from code is `rangeOverflow`. Each rule is its own
flag, so `el.validity` tells "empty" from "too few" / "too many"; readonly and disabled controls are
never invalid. `required` also sets `aria-required` and `:state(required)`.

```html
<form>
  <web-multiselect name="team" required min-selected-count="3" max-selected-count="5"
    labels='{"placeholders.search": "{ctx.selectedCount} of 3–5 picked"}'></web-multiselect>
</form>
```

The messages are labels — `errors.required` (`Select an item.`), `errors.minSelected` (`Select at
least {ctx.min}.`), `errors.maxSelected` (`Select at most {ctx.max}.`) — and `{ctx.missing}` (the picks still
missing) fits `errors.minSelected`, which shows only while it is 1 or more. See [docs/usage.md → Required and validation](../docs/usage.md#required-and-validation)
and the data-api page API11.

## Visible changes without a migration

- **Tooltip motion** — badge and option tooltips fade + slide toward their anchor on show **and** on
  hide (was a fade-in, then gone at once), timed by `--base-duration-fast`, instant under
  `motion="none"` or OS reduced motion; the tooltip carries `data-placement`. The fullscreen
  truncated-label reveal keeps its own fade-in.
- **`showMessage()`** fades out on hide instead of vanishing, and is announced to screen readers
  through core `announce()` (polite, assertive for `warning` / `danger`).
- **`.ms__icon`** — an icon-font `<i>` sits like the masked built-in glyph (`flex: none`, inherited
  font size).
- **Phone sheets** slide in and out with core's sheet motion (instant under `motion="none"` / OS
  reduced motion) — [details](#modal-sessions-and-cores-sheet-frame).
- **Field width** — the field width that `--ms-dropdown-width` / `--ms-selected-popover-width`
  default to is the rendered width (`getBoundingClientRect`), not the rounded `offsetWidth`.

## Internal

### Virtual lists on core

Virtual lists (options, selected-items popover) run on core `createVirtualWindow`; the rows sit in a
`.km-virtual-spacer` → `.km-virtual-window.ms__virtual-scroll-viewport` (translateY) instead of an
absolutely positioned wrapper / viewport. Each row is still a fixed-height `.ms__virtual-item`.

- Hidden form inputs via core `createFormInputs` / `formatFormValue` (same output; reused instead of
  re-created), async search via `createAsyncRunner`, `el.controller` via `createControllerFacade`
  (now frozen), ids via `createId`, CSS lengths via `readCssLengthPx` / `readScrollBehavior`.
- The JS wheel guard on the dropdown is gone; `overscroll-behavior: contain` keeps the page still.
- The own label resolver is replaced by core `createLabels`.
- Built on core `1.0.0-rc26`'s final names: `fitToVisibleViewport`, `observeTextInput`,
  `RenderLoadingCallback`, `getEngineConfig()`, `escapeHtml` from the main entry, and the `*Callback`
  option fields.
- The internal engine no longer reads ~30 settings (each with its own default) off its container's
  `data-*` attributes; settings and the initial selection come from config only, one source of
  defaults (`MultiSelectConfig` gains the engine-wiring member `initialSelection`).
- The dev-mode custom-CSS variable lint is core's `createCustomStyles({ lintCssVars })` (DEV only);
  the message text is core's.
- Option tooltips hide on scroll through core `createTooltip`; ms's own `hideOptionTooltips()` is gone.
- The `dropdown-max-width` cap and the field-width variable go through core `anchor` options
  (`maxWidth`, `referenceWidthVar`); the inline-geometry sweep on a floating → fullscreen switch is
  reduced to ms's own min-width.
- The phone sheets' own scroll lock / Back entry / keyboard-inset wiring is replaced by core
  `startModalSession`.
- `component-variables.manifest.json`: the 31 unset-by-design knobs are marked `"input": true`.
