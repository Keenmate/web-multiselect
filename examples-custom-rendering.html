CR03 · Fully Restyled Badges (make them sexy)

Own the whole pill's look without a special hook — three callbacks working together. The wrapper (.ms__badge) and the remove × stay component-owned so removal keeps working; you own the content and the styling.

Pill-shaped badges with avatars; VIPs get a gradient fill. The remove button still works.
The pill is two layers
The visible fill is split between .ms__badge-text (--ms-badge-text-bg) and .ms__badge-remove (--ms-badge-remove-bg). For a continuous gradient, paint it on the wrapper .ms__badge and make those two transparent (the wrapper has overflow: hidden, so it clips into one clean pill). 
// 1) Own the badge CONTENT (rendered inside .ms__badge-text)
el.renderBadgeContentCallback = (item) =>
  `<img class="ava" src="${item.avatar}" alt=""><span>${item.name}</span>`;

// 2) Tag special items so their pill can be styled
el.getBadgeClassCallback = (item) => item.vip ? 'badge--vip' : '';

// 3) Inject CSS into the shadow DOM (page CSS can't reach the pill)
el.customStylesCallback = () => `
  .ms__badge { border-radius: 999px; }                 /* pill shape */
  .ms__badge-text { gap: .4rem; padding-inline-start: .35rem; }
  .ms__badge .ava { width: 20px; height: 20px; border-radius: 50%; object-fit: cover; }

  /* VIP: one continuous gradient across the whole pill */
  .ms__badge.badge--vip { background: linear-gradient(135deg, #7c3aed, #ec4899); }
  .ms__badge.badge--vip .ms__badge-text,
  .ms__badge.badge--vip .ms__badge-remove {
    background: transparent; color: #fff; border-color: transparent;
  }
`;

CR04 · Whole-Badge Render (icon-pack picker)

renderBadgeCallback replaces the entire badge (not just its content), so a selection can become a full card. Here it's an icon-pack builder: pick icons from the combobox and each one drops in as a card with its glyph, a Filled/Outline chip, available sizes, and its own big Remove button — imagine the selection is what gets zipped and downloaded.

Each selected icon renders as a card; the card's Remove button deselects it.
Removal contract
The component wraps your markup in .ms__badge--custom carrying data-value, and delegates removal to any element inside with data-action="remove" (or the built-in .ms__badge-remove). So you just add a remove control — no event wiring. Return null to fall back to the default pill for an item. 
el.renderBadgeCallback = (item) => `
  <div class="icard">
    <div class="icard__tile">${item.svg}</div>
    <div class="icard__title">${item.name}</div>
    <button type="button" class="icard__remove" data-action="remove">Remove</button>
  </div>`;
// data-value is stamped on the wrapper by the component; the click on
// [data-action="remove"] resolves it and deselects — no manual event.

CR05 · Own the Whole Selection UI (external container)

When you want to own the selection's layout — not just each badge's look — you don't need a special hook. Hide the built-in badges with badges-display-mode="none", keep just the in-field [N] counter (show-counter="true"), and turn off the selected-items popover with enable-selected-popover="false" (pointless once you render your own list). Then render your own panel from the change event and route removal back through setSelected(). The component stays the source of truth; your panel is plain light-DOM markup styled by your app's own CSS — no shadow-DOM injection. Here it also shows the running total duration, an aggregate the built-in badges can't express.

The field shows only a [N] counter; the playlist below is entirely yours.
Why no hook is needed
The main badges area isn't virtualized, so a custom container costs nothing extra — but rendering in your own light DOM buys full control (layout, aggregates like the total, empty state, ordering) and your app's CSS reaches it directly. Removal calls el.setSelected(remaining, { notify: true }), which re-fires change so the same render path repaints the panel — whether the change came from the dropdown or from your own ✕ buttons. 
<web-multiselect badges-display-mode="none" show-counter="true"
                 enable-selected-popover="false"></web-multiselect>

const el = document.getElementById('playlist');   // just [N] in the field
const panel = document.getElementById('playlist-panel');

// One render path — repaint from whatever the component currently holds.
const render = (items) => { panel.innerHTML = items.length ? myMarkup(items) : emptyState; };
el.addEventListener('change', (e) => render(e.detail.selectedOptions));

// Removal/clear route back through the component (it owns the state).
panel.addEventListener('click', (e) => {
  const x = e.target.closest('[data-remove]');
  if (x) {
    const remaining = el.getSelected().map(i => i.id)
      .filter(id => String(id) !== x.dataset.remove);
    el.setSelected(remaining, { notify: true });   // re-fires change → render()
  } else if (e.target.closest('[data-clear]')) {
    el.setSelected([], { notify: true });
  }
});

CR07 · Combined Callbacks

Examples demonstrating how to combine multiple rendering callbacks for sophisticated customization. These examples show how renderOptionContentCallback and renderBadgeContentCallback work together to create different displays for the same data in different contexts (dropdown vs badges vs popover).

11. Context-Aware Rendering

Combines 3 callbacks: renderOptionContentCallback (rich dropdown with status, priority, tags), renderBadgeContentCallback (compact "▶️ Name" in main area, detailed "▶️ Name [priority]" in popover using context.isInPopover), and getBadgeDisplayCallback (plain text "Name - status (priority)" for tooltips).

12. Priority-Based Badge Styling

Uses renderBadgeContentCallback for compact badge display and renderSelectedItemContentCallback for detailed popover display. Uses getBadgeClassCallback to add priority-based CSS classes (badge-urgent, badge-important, badge-normal, badge-low). Uses customStylesCallback to inject CSS into Shadow DOM for styling those classes. Demonstrates separate callbacks for badges vs. selected items popover and solving Shadow DOM CSS isolation.
