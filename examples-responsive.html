Responsive & Mobile

Everything responsive in one place. First, how the dropdown presents on phones — a fullscreen overlay with its own search header, the soft-keyboard policy, and a touch stand-in for keyboard match-stepping. Then how it reacts to its own box in a narrow column (independent of the device), and RTL mirroring of the whole thing.

RS01 · mobile-presentation — floating vs fullscreen

The mobile-presentation attribute decides how the open dropdown is presented:

  • auto (default) — a floating panel on desktop, a fullscreen sheet on phones (detected from the environment: touch-primary + a short viewport side under the tablet boundary).
  • floating — always anchor to the input, even on a phone.
  • fullscreen — always present the sheet, even on desktop (handy for previewing the mobile UI, which is what the toggles on this page do).

Because it's usually a phone-only look, every demo below defaults to auto and offers a Preview as fullscreen toggle so you can see the overlay right here on desktop. Close the sheet with the ✕ in its header.

~50 grouped options — on a phone this opens fullscreen automatically.
Show code 
<!-- auto (default): floating on desktop, fullscreen on phones -->
<web-multiselect></web-multiselect>

<!-- force one presentation everywhere -->
<web-multiselect mobile-presentation="floating"></web-multiselect>
<web-multiselect mobile-presentation="fullscreen"></web-multiselect>

RS02 · fullscreen-autofocus — soft keyboard on phones

By default the keyboard stays closed when the fullscreen sheet opens — it shows the list first, so you can browse long lists and reach the bottom action buttons without the keyboard covering half the screen. The keyboard appears only when you tap the search field. Set fullscreen-autofocus="true" to focus the search on open instead (type-to-filter immediately, like a native picker).

Both pickers use mobile-presentation="auto": a normal floating dropdown here on desktop, a fullscreen sheet on a phone — where the keyboard difference actually shows. Tick Preview as fullscreen to see the overlay on desktop.

On a phone: the list shows, search is not focused.
On a phone: search is focused, keyboard pops on open.
Show code 
<!-- default: keyboard stays closed until the user taps the search field -->
<web-multiselect></web-multiselect>

<!-- opt in to auto-focus + soft keyboard on open -->
<web-multiselect fullscreen-autofocus="true"></web-multiselect>

// or via property
el.fullscreenAutofocus = true;

RS03 · filter vs navigate — live switch

search-mode decides what typing does. In filter (the default) non-matches are hidden and the list shrinks to the results. In navigate the list stays whole and typing jumps focus between matches instead. On desktop you step through matches with Ctrl+↑/↓ — but touch has no such shortcut, so in the fullscreen overlay a match navigator appears under the search box: a N of M count plus prev/next buttons that walk the matches. It shows only in navigate mode, only once you type, and the buttons disable when nothing matches.

Type (e.g. e) to feel the difference in the same overlay. There are two ways to switch here: the built-in toggle — the leading icon in the overlay's search bar (magnifier = navigate, funnel = filter), enabled with show-search-mode-toggle — flips the mode in place without closing the sheet; the host-page radios below do the same by setting the search-mode attribute. The picker uses mobile-presentation="auto", so on desktop it's a normal floating dropdown — tick Preview as fullscreen to force the overlay and reveal the built-in toggle.

Search mode:
Fullscreen: tap the leading icon in the search bar to switch. navigate: type, then use the ↑/↓ next to the count to jump. filter: the list narrows to matches.
Show code 
<!-- navigate mode + a built-in in-overlay mode toggle (fullscreen only) -->
<web-multiselect search-mode="navigate" show-search-mode-toggle></web-multiselect>

<!-- show-search-mode-toggle adds a clickable icon at the search field's leading
     edge in the fullscreen sheet; tapping it flips filter<->navigate in place. -->

<!-- Or switch from the host page — it's just an attribute -->
picker.setAttribute('search-mode', 'filter');   // or 'navigate'

<!-- On phones (fullscreen overlay) navigate mode adds a count + prev/next
     navigator under the search box automatically. Desktop uses
     Ctrl+ArrowUp / Ctrl+ArrowDown for the same jumps. -->

RS04 · Responsive rendering — rich on desktop, lean on the phone

renderOptionContentCallback receives a presentation field ('floating' or 'fullscreen', plus an isFullscreen convenience) resolved from the same device/viewport check that chooses the overlay. So a single callback can render a rich row on the anchored desktop dropdown — price, popularity, a category chip — and a leaner one in the phone fullscreen sheet where there's less room. No matchMedia in your page; it's reactive, so flipping presentation re-renders the rows with the new value.

Open it, then toggle fullscreen: the desktop rows show price · ⭐ popularity · chip; the phone rows drop to just the name + price.
Show code 
picker.renderOptionContentCallback = (item, ctx) =>
  ctx.isFullscreen
    ? `<div class="row-lean"><strong>${item.label}</strong>
         <span>${item.price}</span></div>`                       // lean on the phone sheet
    : `<div class="row-rich"><strong>${item.label}</strong>
         <small>${item.price} · ⭐${item.popularity} · ${item.tier}</small></div>`; // rich on desktop

RS05 · RTL — right-to-left, overlay included

Give the element (or any ancestor) dir="rtl" and the whole component mirrors: the toggle icon and in-input counter move to the left, checkboxes sit on the right of each row, the matched-item accent bar flips sides, badges reverse, and — the part that used to be left-behind — the fullscreen overlay mirrors too (search + close swap sides, and the navigate-mode match navigator flips count vs. prev/next). It's all driven by CSS logical properties off the inherited direction, so there's nothing to configure beyond dir.

Tick Preview as fullscreen and open the picker to see the overlay mirror too — including the navigate-mode match navigator (this one uses search-mode="navigate").

Checkbox on the right, toggle on the left, navigator mirrored.
Show code 
<!-- on the element… -->
<web-multiselect dir="rtl"></web-multiselect>

<!-- …or inherited from any ancestor -->
<div dir="rtl">
  <web-multiselect></web-multiselect>
</div>

RS06 · Own box vs. the window

The sections above react to the device / viewport — a phone opens the sheet. That's the wrong signal when the picker sits in a narrow column on a wide screen: the window is 2560px, but the control's box is 300px. collapse-badges-below keys off the element's own border box instead, via the core resized lifecycle hook (backed by a single page-wide ResizeObserver, so a page of N pickers pays for one observer).

When set to a pixel width, the control watches its box and switches badges-display-mode to count ("N selected") while it's narrower than that — then restores your configured mode when it widens back. It's an opt-in: leave the attribute off and nothing changes.

CSS container queries first
Purely visual reflow (padding, font-size, hiding a label) belongs in a @container query — native and cheaper. Reach for this JS hook only for a structural change like swapping the badge display, which can't be expressed in CSS.

RS07 · Drag the box — collapse-badges-below="360"

Grab the handle at the bottom-right corner of the dashed frame and drag it narrower. Below 360px the four badges collapse to a single "4 selected" count; widen it back and the pills return. The window never changes — only the picker's box does.

picker box: —
Preselected with 4 so the collapse is visible. Threshold: 360px.
Show code 
<!-- opt in: below 360px of its OWN width, badges collapse to a count -->
<web-multiselect collapse-badges-below="360"></web-multiselect>

// or via property
el.collapseBadgesBelow = 360;

// clear it to turn the behavior off (restores your badges-display-mode)
el.collapseBadgesBelow = null;

RS08 · A picker in a narrow sidebar (window stays wide)

Here the page is full-width but the picker lives in a fixed 260px sidebar. A viewport check would call this "desktop" and leave the badges to overflow; the own-box check collapses them because the box is narrow. This is exactly the case the window signal gets wrong.

260px column · threshold 300px → collapsed.

Main content area — plenty of room here, but the sidebar picker still collapses because it reacts to its box, not the page.

RS09 · How it resolves

Box width collapse-badges-below Effective badges mode
any unset (default) your badges-display-mode (unchanged)
≥ threshold e.g. 360 your badges-display-mode
< threshold e.g. 360 count (forced, live)
  • Non-destructive. The override is applied to the live picker; your badges-display-mode config is never rewritten, so widening restores it exactly — including custom modes like compact or partial.
  • Throttled. The resized hook coalesces a drag to ~30ms (leading + trailing), so a resize reflows a bounded number of times.
  • Survives rebuilds. Changing a structural attribute rebuilds the picker; the collapse is re-asserted from the current box afterward.
Two independent axes
mobile-presentation (§1) picks floating vs. fullscreen from the device; collapse-badges-below picks the badge display from the element's box. They compose — a phone can open fullscreen while a desktop sidebar collapses badges. For a third pattern — swapping a whole config (e.g. a different actionButtons set) by device — see the device-adaptive actions demo on the Action Buttons page.
