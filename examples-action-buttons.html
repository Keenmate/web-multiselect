AB03 · Custom Actions with onClick

Build your own buttons with an id (no action — that's only for the built-ins) and an onClick(detail) handler. detail is the action event detail: the selection snapshot (selectedValues, options, …) plus id, source and controller, which drives the component (setSelected, selectAll, selectedValue, …). Here: pick popular languages, invert the selection, or pick two at random — plus the built-in Clear All. Every activation also fires the action event (el.onAction), and beforeActionCallback(detail) can cancel it by returning false.

AB04 · Icon Buttons — Unicode Glyphs vs Font Awesome (font)

Each button has an icon field (and a dynamic getIconCallback(ctx)), rendered in a .ms__action-btn-icon span before the .ms__action-btn-label. Both icon and text are inserted as text, never HTML — so the icon is a glyph: a Unicode symbol / emoji works with zero setup, and a Font Awesome icon works as its code-point character, provided the @font-face lives at document level (a <link> in the page <head>) and the icon span gets the font via getCustomStylesCallback. Inline SVG / <i class="fa-…"> markup is no longer possible. Flip the switch to compare.

AB06 · Device-Adaptive Actions

Twelve action buttons fit one row on a wide desktop, but there's no room on a phone, a tablet, or a narrowed window. The fix isn't a CSS trick: define your action sets and let a responsive rule pick the right one. A per-tag responsiveCallback on window.components['web-multiselect'] returns a partial config for the current device class / viewport width; the component re-runs it on every device-class flip and (callbacks only) every viewport-width change, and applies only what changed — no app-side viewport observer, no "did it change" bookkeeping. The rule is page-wide, so it opts in by a marker attribute (data-adaptive-actions); anything set explicitly on a picker still wins over it.

  • Desktop, wide (> 600px): all twelve buttons, one row (nowrap).
  • Desktop, narrowed (≤ 600px): all twelve, flowed onto two rows (wrap). A mouse device stays desktop at any width, so this is a width check (ctx.env.viewportWidth), not a device class.
  • Tablet: all twelve wrapped — a single row would run beyond the edge.
  • Phone: the three essentials only, wrapped.

AB07 · Summary

Static Properties

action?: 'select-all' | 'clear-selection'             // Built-ins only (or the string shorthand 'select-all')
id?: string                                     // Identifies a custom item (reported in the action event)
text?: string                                   // Plain text (default for built-ins: labels.selectAll / clearSelection)
icon?: string                                   // Plain-text glyph, rendered before the text
row?: number                                    // Optional (default: 1) — which button row
tooltip?: string                                // Optional
cssClass?: string                               // Optional
isVisible?: boolean                             // Optional (default: true)
isDisabled?: boolean                            // Optional (default: false)
isDanger?: boolean                              // Destructive styling (default: false)
isToggled?: boolean                             // Toggle state (ON) → aria-pressed (default: false)

Dynamic Callbacks

onClick?: (detail) => void | Promise<void>      // Runs for built-ins too, before the built-in
getIsVisibleCallback?: (ctx) => boolean          // Dynamic visibility
getIsDisabledCallback?: (ctx) => boolean         // Dynamic disabled state
getIsToggledCallback?: (ctx) => boolean          // Dynamic toggle state
getTextCallback?: (ctx) => string                // Dynamic text
getIconCallback?: (ctx) => string                // Dynamic icon
getClassCallback?: (ctx) => string | string[]    // Dynamic CSS classes
getTooltipCallback?: (ctx) => string             // Dynamic tooltip

// ctx    = { selectedValues, selectedOptions, options, selectedCount, optionCount, isOpen, searchTerm, controller, element }
// detail = ctx + { action, id, item, source, sourceEvent, triggerElement, dataset }

beforeActionCallback?: (detail) => false | void  // element-level: false cancels onClick, the action event and the built-in
onAction / 'action' event                        // every activation — order: beforeActionCallback → onClick → action → built-in

Layout attributes

actions-position  // 'top' (default) | 'bottom'
actions-layout    // 'nowrap' (default) | 'wrap'
actions-align     // 'stretch' (default) | 'left' | 'center' | 'right' | 'space-between'

Priority Rules

When both static and callback are defined:
  • getIsVisibleCallback > isVisible > default true
  • getIsDisabledCallback > isDisabled > default false
  • getTextCallback > text
  • getClassCallback > cssClass
  • getTooltipCallback > tooltip
