BU03 · Groups

Group options under headers with a group member. Each group header shows a count of that group's selected items (in any mode — open the dropdown to see it). Turn on per-group select-all (group-select-mode="cascade") to also put a tristate checkbox on each header that toggles the whole group — the group name is never itself a value. Turning on custom labels renders the header via renderGroupLabelContentCallback, whose ctx carries the per-group selection — here it writes GROUP — N remaining (selectableCount − selectedCount).

BU04 · Declarative Usage (No JavaScript)

For simple cases you don't need any script at all — put plain <option> / <optgroup> children inside the element and the component parses them once from the light DOM. It reads each option's value, its text, the selected attribute, and data-icon / data-subtitle and disabled (the option stays visible but can't be picked). Single-select is multiple="false". Even custom styling stays script-free — the custom-styles attribute injects raw CSS into the shadow DOM (the declarative twin of getCustomStylesCallback).

BU06 · Scroll-to API — scrollToGroup / scrollToValue / scrollToIndex

Imperative commands that bring an option or group into view. Pair with open() for an "open + jump" gesture. They work in floating, mobile fullscreen, virtual-scroll and tree modes, and return false when the target isn't in the current filtered list. clearSearch() reveals a filtered-out option so you can then scroll to it.

block: where the target lands; nearest moves only if it's out of view
--ms-scroll-behavior: the motion level / reduced motion also set it; virtual scroll always jumps
scrollToGroup brings the group header into view.
Virtual mode scrolls by index math — the row need not be rendered yet.

el.open();
el.scrollToGroup('backend');   // header at the top (or the group's first row in virtual mode)
el.scrollToValue('redis', { block: 'center' });   // → Promise if filtered out by the current search
el.scrollToIndex(0, { block: 'nearest' });       // start (default) | center | end | nearest

// Smooth or instant: --ms-scroll-behavior (smooth by default; auto under reduced motion / motion="none")
el.style.setProperty('--ms-scroll-behavior', 'auto');

// Reveal a filtered-out option, then scroll to it:
el.clearSearch();
el.scrollToValue('jp');

BU07 · Search

Filter mode hides non-matches; navigate mode keeps every option visible and jumps focus between matches (Ctrl/Cmd + ↑/↓). Add a search hint and require a minimum number of characters before searching. (search-debounce applies to an async searchCallback only. See DA04 · Async Search.)

search-mode:

Drive it from code. search(term) applies a query exactly as if the user typed it (the mode above, min-search-length, beforeSearchCallback, an async searchCallback) but does not open the dropdown; searchTerm reads the current query; clearSearch() resets it. There's no separate "filter" method: search-mode decides what the query does. Handy for deep-links ("open with a query pre-filled"), syncing an external field or restoring saved state.

searchTerm = ""

When to use each mode:

  • Filter: large lists you want to narrow down (product catalogs, user lists).
  • Navigate: quick selection from a known list (country / state selectors).

BU08 · Search matching — search-behavior & search-match

Two independent switches for the built-in search. search-behavior decides how text is normalized: normalized (the default) ignores case and accents, so zurich finds Zürich; case-insensitive ignores case only; exact ignores nothing. search-match decides where the term must appear. Both are live: flip them with a term typed and the list re-filters in place. Each option's search value is normalized once and cached, not on every keystroke.

search-behavior:

Things to try (all typeable on any keyboard):

  • zurich / sao / krakow: match under normalized (accents ignored); switch to case-insensitive and they're gone.
  • PARIS: found by normalized and case-insensitive; exact needs Paris.
  • new york with equals: only the whole value counts (and case doesn't), so york finds nothing.
  • de: contains finds Bordeaux too; word-starts-with only Rio de Janeiro / New Delhi; starts-with nothing.
  • io: ends-with finds nothing; word-ends-with finds Rio de Janeiro (the word "Rio").
  • ^(San|Santa) with regex. Keep typing an unfinished pattern like ^(San and the last valid result stays.

Regex skips normalization: the pattern runs against the raw text, so search-behavior doesn't apply. ^Sao finds nothing; ^S.o finds São Paulo (the . matches the ã).

The same normalization for your own code — normalizeSearchText() 
import { normalizeSearchText } from '@keenmate/web-multiselect';
normalizeSearchText('Český Krumlov');   // 'cesky krumlov'

BU09 · Preparing the term — getSearchTermCallback

getSearchTermCallback turns what the user typed into what search should look for. Return a string (used as-is) or a RegExp. Here part numbers are written with all sorts of separators; the callback turns ha-324/56 into a pattern that ignores them, so it finds HA 324-56, HA32456 and HA-324/56. Untick it to compare: plain search finds only the one written exactly that way.

BU10 · Scrolling the list — beforeScrollCallback

The dropdown scrolls an option into view on its own: a keyboard move (keyboard), a navigate-mode match (search), the selected option of a single-select on open (open) and the scrollTo*() methods (api). Only the list moves, never the page. beforeScrollCallback runs first: return false to skip the scroll, { block, behavior } to change it, or nothing for the defaults. Open the picker, arrow down, try the buttons — the read-out shows each call.
