Theming & Sizing

Customize appearance with CSS custom properties — dark mode and theme presets, the --base-* typography integration, and REM-based sizing of inputs and fonts.

TH01 · Built-in Color Scheme — auto / light / dark

Every picker ships dark-ready: all --ms-* color defaults are wrapped in CSS light-dark(), keyed on the host's color-scheme. You never override --base-* to go dark (that's what the theme cards further down do, for custom palettes) — you just signal the scheme and the component picks the right branch. Three ways, in priority order:

  • Per-instance — data-theme="dark" / "light" on the <web-multiselect> itself (highest priority; overrides any ancestor).
  • Framework class on an ancestor — .dark (Tailwind), [data-bs-theme="dark"] (Bootstrap 5.3+), or [data-theme="dark"].
  • Follow the OS — set no explicit signal and let the page opt into color-scheme: light dark; both the page and the picker track the system setting.
Open the dropdown — the panel, options, checkboxes, badges and scrollbar all flip with the scheme. No per-instance color overrides in play.
Show code 
<!-- 1. Per-instance (wins over everything) -->
<web-multiselect data-theme="dark"></web-multiselect>

<!-- 2. Framework class on an ancestor -->
<html class="dark">                    <!-- Tailwind -->
<html data-bs-theme="dark">           <!-- Bootstrap 5.3+ -->
<div data-theme="dark"> … <web-multiselect></web-multiselect> … </div>

<!-- 3. Follow the OS: opt the page into system switching -->
<style> html { color-scheme: light dark; } </style>
<web-multiselect></web-multiselect>   <!-- no signal → tracks prefers-color-scheme -->

// switch at runtime — it's just an attribute
picker.setAttribute('data-theme', 'dark');   // or 'light'
picker.removeAttribute('data-theme');        // back to inherit/OS

TH02 · Grouped options + fullscreen mode switch

Everything at once: grouped options (group-member) rendered in the fullscreen overlay, with the built-in filter↔navigate toggle (show-search-mode-toggle) in the search header — all following the same built-in color scheme. Pick a scheme, tick Preview as fullscreen, open the picker, then tap the leading icon in the search bar (magnifier = navigate, funnel = filter). Group headers, matched rows, checkboxes, badges and the N of M match navigator all stay themed with zero per-instance color overrides.

Grouped by Frontend / Runtimes / Languages. In the fullscreen sheet, tap the leading search icon to switch filter ↔ navigate.
Show code 
<web-multiselect
    group-member="group"          <!-- render options under group headers -->
    search-mode="navigate"        <!-- start in navigate; typing jumps between matches -->
    show-search-mode-toggle>      <!-- fullscreen: leading icon flips filter↔navigate live -->
</web-multiselect>

<!-- Theme it exactly like everything else: just signal the scheme. -->
<div data-theme="dark"> … </div>   // or data-theme="light", or OS-auto

TH03 · Sizing — scale the whole picker with --ms-rem

There's no size attribute — the component scales everything (input height, font, padding, checkboxes, badges, dropdown) off a single base unit, --ms-rem (default 10px). Set it on the element (or a theme layer) and the whole picker scales proportionally. For one-off tweaks, override the individual --ms-input-* variables instead. The presets below are just different --ms-rem values.

Preset --ms-rem Input height (3.5×) Font (1.4×)
xs 8px 28px 11px
sm 9px 31px 13px
md (default) 10px 35px 14px
lg 12px 42px 17px
xl 14px 49px 20px

Note: the input height is calc(3.5 * var(--ms-rem)) and font calc(1.4 * var(--ms-rem)), so both track the base unit. For Pure Admin, set --ms-rem: 1rem (with html { font-size: 10px }).

TH12 · Global Scaling with --ms-rem

The --ms-rem CSS variable (default: 10px) controls the base unit for all dimensions. Change it to scale the entire component proportionally.

<!-- Scale entire component by changing --ms-rem -->
<web-multiselect style="--ms-rem: 8px;"></web-multiselect>  <!-- 80% size -->
<web-multiselect style="--ms-rem: 12px;"></web-multiselect> <!-- 120% size -->

<!-- Or via CSS class -->
<style>
  web-multiselect.compact { --ms-rem: 8px; }
  web-multiselect.large { --ms-rem: 15px; }
</style>

Compact (--ms-rem: 8px)

80% of default size - great for dense UIs

Default (--ms-rem: 10px)

Standard sizing - balanced for most uses

Large (--ms-rem: 12px)

120% of default - better touch targets

Extra Large (--ms-rem: 15px)

150% of default - accessibility focused

TH14 · Narrow Input, Wide Dropdown

For dense forms where input space is limited: show just a code in the input, but use dropdown-min-width to ensure the dropdown is comfortable for selection.

<!-- Narrow input with wide dropdown -->
<web-multiselect
  style="width: 4rem;"
  dropdown-min-width="20rem"
  multiple="false">
</web-multiselect>

<script>
  // Show just the code in the closed input
  select.renderSelectedContentCallback = (item) => item.code;
  // Show full label in dropdown
  select.getDisplayValueCallback = (item) => `${item.flag} ${item.name}`;
</script>

TH17 · Key CSS Variables

Important variables for sizing and typography:

Variable Default Description
--ms-rem 10px Base unit - scales everything proportionally
--ms-input-font-size calc(1.4 * var(--ms-rem)) Input text size (14px default)
--ms-input-padding calc(0.8 * var(--ms-rem)) calc(1.2 * var(--ms-rem)) Input padding
--ms-option-title-font-size calc(1.4 * var(--ms-rem)) Option text size
--ms-badge-font-size calc(1.2 * var(--ms-rem)) Badge text size

Note: CSS variables must be set on the <web-multiselect> element itself (or via inherited CSS), not on wrapper divs, due to Shadow DOM encapsulation.
