Open the DevTools Console (F12). On load the component registers itself on window.components['web-multiselect']. Try window.components['web-multiselect'] in the console, then use the buttons below — everything here goes through that global, nothing else.

LG01 · The registry entry

Every Keenmate component publishes one entry via core's registerComponent(). Below is a live view of window.components['web-multiselect'], refreshed automatically as instances connect and disconnect.

window.components['web-multiselect']

LG02 · Logging controls — via .logging

The .logging object is the flattened logger bundle. These buttons call it directly (e.g. window.components['web-multiselect'].logging.setCategoryLevel('DATA','debug')). The active category level is reflected in the registry panel above. Interact with the pickers to produce logs.

LG03 · Live instances — .getInstances()

getInstances() returns the connected elements of this tag — maintained automatically (added on connect, removed on disconnect). Add and remove pickers below and watch the count in the registry panel change; then fan a call out across every live instance.

LG04 · Log categories

  • INIT — initialization, config parsing, RTL detection, destruction
  • DATA — async loading, option parsing, adding options, errors
  • UI — dropdown/popover/tooltip rendering, positioning, badges
  • INTERACTION — clicks, selections, keyboard, close-on-select

LG05 · Usage

// No import needed at call sites — the registry is a global, populated the // moment the component module is loaded anywhere on the page. const ms = window.components['web-multiselect']; ms.version(); // "2.0.0-rc01" ms.config; // { name, version, author, license, … } ms.getInstances(); // live <web-multiselect> elements // Logging (a flattened view of the core logger bundle) ms.logging.getCategories(); // ["INIT", "DATA", "UI", "INTERACTION"] ms.logging.enableLogging(); // all categories → debug ms.logging.setLogLevel('info'); // all → info ms.logging.setCategoryLevel('DATA', 'debug'); ms.logging.disableLogging(); // silence everything (production default) // Fan out across instances for (const el of ms.getInstances()) console.log(el.id, el.selectedOptions); // Advanced: BlissElement also supports a per-instance override — // el.enableLogging('debug') makes ONE element verbose for a devtools overlay // (targets el.log; the shared category loggers above stay unchanged).
