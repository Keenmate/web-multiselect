Tree of Options

Render options as an always-expanded hierarchy, indented by depth

TR01 · Basic Tree

Give each option a materialized dot-path ("1", "1.1", "1.1.1", …) and set path-member. Tree mode auto-enables: the component derives parent and depth from the path and renders the options depth-first, indented by level. The model is a trimmed lift of @keenmate/web-treeview's ltree. 

el.options = [
  { value: 'fruit', label: 'Fruit', path: '1' },
  { value: 'pome',  label: 'Pome fruit', path: '1.1' },
  { value: 'apple', label: 'Apple', path: '1.1.1' },
  { value: 'veg',   label: 'Vegetables', path: '2' }
];
el.pathMember = 'path';   // <web-multiselect path-member="path">
No collapse:
The tree is always fully expanded — there is no chevron/toggle. Reach for @keenmate/web-treeview when you need expand/collapse.

TR02 · Single-Select & Checkboxes

Every node — branch or leaf — is a normal, selectable option. Selection, single/multi mode, and checkboxes all behave exactly as they do for a flat list.

TR03 · Ancestor-Preserving Search

Typing filters the hierarchy to the matching nodes plus their ancestors, so the indentation of the results still makes sense.

TR04 · Custom Path Separator

When your paths use a different separator (e.g. 1/1/2), set tree-path-separator. 

<web-multiselect path-member="path" tree-path-separator="/"></web-multiselect>

TR05 · Full Breadcrumb on Badges

A full title is a fully-qualified label that ships with the data (never computed here). Set full-title-member (or getFullTitleCallback) and turn on show-badge-full-title, and badges render Fruit / Pome fruit / Apple instead of just Apple — disambiguating leaves that share a name across branches. An explicit getBadgeDisplayCallback still wins. 

<web-multiselect path-member="path" full-title-member="fullTitle" show-badge-full-title="true">

TR06 · Selectable Leaves Only

A node can be marked non-selectable — set is-selectable-member (a data flag) or getIsSelectableCallback (a predicate that receives the built node, so it can read node.hasChildren). Non-selectable nodes render normally — they are not greyed out like disabled — but they drop their checkbox, are skipped by keyboard arrows, and can't be toggled or picked by Select All. The classic use is a tree where only the leaves are real choices and the branches are pure structure. 

// Only leaves are selectable — the callback sees the derived hasChildren.
el.getIsSelectableCallback = (node) => !node.hasChildren;

// …or drive it from the data:
// <web-multiselect path-member="path" is-selectable-member="selectable">

TR07 · Styling the Indentation

Each row is indented via an inline --ms-tree-depth custom property (0 at the top level). Tune the step with --ms-tree-indent and the first-level offset with --ms-tree-base-indent. Branch/leaf rows also carry .ms__option--tree-branch / .ms__option--tree-leaf theming hooks. 

web-multiselect {
  --ms-tree-indent: 1.25rem;      /* per-level step */
  --ms-tree-base-indent: 0.75rem; /* first-level inline-start padding */
}

TR08 · Row Height & Long Labels

Deep indentation eats horizontal space, so long labels matter. By default a title wraps to multiple lines (rows grow). Set a consistent row height with --ms-option-min-height, and/or truncate long titles to a single line with an ellipsis by flipping the three --ms-option-title-* variables. .ms__option-title is the label hook (the analog of web-treeview's .wtv__node-label). Pair truncation with enable-option-tooltips to reveal the full text on hover. These apply to flat lists too — they're option-level, not tree-only. 

web-multiselect {
  --ms-option-min-height: 56px;                 /* consistent row height */

  /* truncate long titles to one line + ellipsis */
  --ms-option-title-white-space: nowrap;
  --ms-option-title-overflow: hidden;
  --ms-option-title-text-overflow: ellipsis;
}

TR09 · Real Data — Full ISCO-08 Classification

Everything at once on real data: the whole International Standard Classification of Occupations (ISCO-08) — 619 groups (10 major → 43 sub-major → 130 minor → 436 unit). The ISCO code is the hierarchy (2211 → path 2.22.221.2211), so it drops straight into path-member. Only the unit groups (leaves) are selectable — you pick an occupation, not a category. A custom badge shows just the leaf title (prefixed .. / when it has ancestors), with the full breadcrumb in the badge tooltip; long titles truncate; virtual scroll keeps 600+ rows smooth. A getSearchValueCallback widens the built-in filter to match the title, ISCO code, and full breadcrumb (matches keep their ancestors), so you can search by any of them. 

const isco = await (await fetch('./examples-data/isco08.json')).json();
el.pathMember = 'path';               // "2.22.221.2211"
el.isSelectableMember = 'selectable'; // only 4-digit unit groups (leaves)
el.options = isco;

// Badge shows only the last segment; ".. /" hints at hidden ancestors.
el.getBadgeDisplayCallback = (item) => {
  const segs = String(item.fullTitle || item.label).split(' / ');
  const last = segs[segs.length - 1];
  return segs.length > 1 ? `.. / ${last}` : last;
};
// Full breadcrumb in the badge tooltip (needs enable-badge-tooltips).
el.getBadgeTooltipCallback = (item) => item.fullTitle || item.label;

Source: International Standard Classification of Occupations, ISCO-08 (© International Labour Organization) — demo data.

TR09b · Scroll-to API in a tree

The tree is always fully expanded, so scrollToValue reaches any node by its value (here the ISCO code) — and it works with virtual scroll (the row need not be rendered). scrollToGroup does not apply in tree mode and returns false. If a search has filtered the tree, the node may be hidden — call clearSearch() first to reveal it, then scroll.

scrollTo* results log here…
el.open();
el.scrollToValue('2211');        // any node by value — tree is always expanded
el.scrollToIndex(el /* count-1 */); // last visible node
el.scrollToGroup('x');           // → false in tree mode

// If a search filtered the node out, reveal it first:
el.clearSearch();
el.scrollToValue('2211');

TR10 · Cascade Checkboxes & Value Policy

Two orthogonal knobs. checkbox-mode controls how checking a branch behaves; cascade-select-policy controls which values the selection emits (badges / form / change). Flip them below on a single live picker, then check Fruit and try removing a badge — watch how the emitted value changes in each mode.

  • checkbox-mode="independent" (default) — each node toggles on its own; checking a branch selects only that node. Removing a badge removes exactly that one node.
  • checkbox-mode="cascade" — checking a branch checks its whole subtree; a partial branch shows a tristate (dash) box. Removing a branch badge clears its whole subtree.
  • rolled-up (default) — minimal cover: a fully-selected subtree collapses to its root; a partial branch emits its individually-checked descendants.
  • leaves — only the checked leaf nodes.
  • all — every fully-checked node (branches + leaves), like @keenmate/web-treeview.
checkbox-mode:
cascade-select-policy:
Emitted getValue():
[]
const el = document.querySelector('web-multiselect');
el.checkboxMode = 'cascade';            // independent (default) | cascade
el.cascadeSelectPolicy = 'rolled-up';   // rolled-up (default) | leaves | all
// Both are live: flip them any time and the current selection re-projects.

TR11 · Action Buttons

Action buttons work with tree mode. The built-in select-all / clear-all honour selectability (non-selectable branches are skipped), and in cascade mode Select All emits the same rolled-up shape a click would — here selecting everything collapses to just the two roots (Fruit, Vegetables), not one badge per node. Add custom actions with an onClick(ms) that receives the picker instance. 

el.actionButtons = [
  { action: 'select-all', text: 'Select All' },
  { action: 'clear-all',  text: 'Clear All' },
  // custom action — receives the picker instance. setSelected is silent by default;
  // { notify: true } announces the result as a single `change` (so the server hears it).
  { action: 'custom', text: 'All fruit', onClick: (ms) => ms.setSelected(['fruit'], { notify: true }) }
];

TR12 · Custom Node Rendering

renderOptionContentCallback works on tree rows too — it replaces the inner content of a node (icon / title / subtitle), while the component still draws the tree chrome around it: the checkbox, depth indentation, and the branch/leaf/selected/indeterminate state classes. In tree mode the callback's context carries tree metadata so you can branch on it without re-deriving anything from your data:

  • isTreeNode — true on tree rows (false for flat options).
  • isBranch / isLeaf — has children, or not.
  • childCount — number of direct children (0 for a leaf).
  • level / depth — 1-based level and 0-based indent depth (--ms-tree-depth).
  • path — the node's materialized path ("1.1.2").
  • isSelectable — false for structure-only branches.
  • isIndeterminate — cascade tristate (a partially-checked branch).

Two mechanisms working together. The content comes from renderOptionContentCallback (here just the label plus a muted ctx.childCount). The full-row background per node type comes from the branch/leaf theming hooks via customStylesCallback — the render callback only fills the content area (after the checkbox), so a background belongs on the .ms__option--tree-branch / .ms__option--tree-leaf row classes. 

// 1) Content — compact label + child count. Style via a CSS class, not inline styles.
el.renderOptionContentCallback = (item, ctx) => ctx.isBranch
  ? `<span><strong>${item.label}</strong> <small class="node-count">${ctx.childCount}</small></span>`
  : `<span>${item.label}</span>`;

// 2) All styling lives in one shadow-DOM stylesheet — full-row backgrounds via the
//    branch/leaf theming hooks, plus the .node-count class used above.
el.customStylesCallback = () => `
  .ms__option--tree-branch { background: #eef2ff; font-weight: 600; }  /* branches: tinted */
  .ms__option--tree-leaf   { background: #fff; }                      /* leaves: plain    */
  .node-count { opacity: .55; font-weight: 400; }
`;

// Compact: scale the whole picker down with --ms-rem (default 10px → 8px = 80%):
// <web-multiselect style="--ms-rem: 8px; --ms-tree-indent: 1rem;">

TR13 · No Badges — Selections in a Popover

For a deep tree, a wall of badges gets noisy fast. Set badges-display-mode="count" and the component drops the individual badges for a single “N selected” chip. Click it to open the selected-items popover — the full list, each with its own remove button — without touching the options dropdown. The popover reuses badge rendering, so a full-title-member + getBadgeDisplayCallback gives each row its breadcrumb, which is what makes leaves that share a name distinguishable.

Want zero chrome instead?
Use badges-display-mode="none" together with show-counter="true": no badges and no “N selected” text — just a compact [N] counter next to the toggle that opens the same popover. 
<web-multiselect badges-display-mode="count" show-counter="true"></web-multiselect>

// Breadcrumb per popover row (popover reuses badge rendering):
el.fullTitleMember = 'fullTitle';
el.getBadgeDisplayCallback = (item) => item.fullTitle || item.label;

// show-counter adds a compact [N] chip next to the toggle — independent of the
// display mode, it opens the same selected-items popover. Drop the "N selected"
// text entirely with badges-display-mode="none" to leave only the [N] chip.

TR14 · Independent Panel Widths

The control, the options dropdown, and the selected-items popover are three separate panels — and they can each have their own width. Here the input is a narrow 15rem, the tree dropdown opens to a roomy 60rem (deep breadcrumbs need the space), and the “badges” popover sits at 30rem. Both panel widths are just CSS variables (--ms-dropdown-width, --ms-selected-popover-width); the dropdown-width / selected-popover-width attributes are sugar that set those variables on the element.

Theme once, override locally:
Set the variables at app/theme level — web-multiselect { --ms-dropdown-width: 60rem } — and every picker follows; the attributes then override a single instance. Defaults: the dropdown tracks the input width, the popover is an intrinsic 32rem. 
<!-- Per-instance: attributes set the CSS variables on this element -->
<web-multiselect
    style="width: 15rem;"             // the control (input)
    dropdown-width="60rem"            // → --ms-dropdown-width
    selected-popover-width="30rem">  // → --ms-selected-popover-width
</web-multiselect>

/* Or theme every picker at once — the same variables, at app level: */
web-multiselect {
    --ms-dropdown-width: 60rem;
    --ms-selected-popover-width: 30rem;
}

TR15 · Navigate Mode — Jump Between Matches

Section 3 shows the default filter search (the hierarchy narrows to matches plus their ancestors). search-mode="navigate" is the alternative: the whole tree stays visible and typing jumps focus between matching nodes instead of hiding anything — handy on a tree, where filtering can hide the structure you were reading. Matched rows keep a highlight; step through them with Ctrl+↑/↓ on desktop. In the fullscreen overlay (touch, or the preview toggle below) a N of M count with prev/next buttons appears under the search box, since touch has no keyboard shortcut.

This picker also sets show-search-mode-toggle, which adds a built-in mode switch to the fullscreen search bar: the leading icon (magnifier = navigate, funnel = filter) flips the mode in place on tap — no reopen. Enable fullscreen preview, then tap the icon to switch without touching the host-page radios.

Search mode: 
<!-- keep the whole tree on screen; jump focus between matches -->
<web-multiselect path-member="path" search-mode="navigate"></web-multiselect>

<!-- add a built-in filter<->navigate toggle to the fullscreen search bar -->
<web-multiselect path-member="path" search-mode="navigate" show-search-mode-toggle></web-multiselect>

/* Fullscreen (phones) adds a count + prev/next match navigator automatically;
   desktop steps with Ctrl+ArrowUp / Ctrl+ArrowDown. */
