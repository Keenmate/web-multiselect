STYLING & THEMING
=================

CRITICAL: 150+ CSS variables for customization
- Shadow DOM encapsulation
- CSS variables penetrate Shadow boundary
- --base-* tokens (@keenmate/base-css-variables) page-wide
- Custom styles via callback
- Complete theme control

CSS VARIABLES OVERVIEW
----------------------
Component uses CSS custom properties (variables):

Basic usage:
<style>
  web-multiselect {
    --ms-accent-color: #3b82f6;
    --ms-text-color-1: #111827;
    --ms-border-radius: 0.5rem;
  }
</style>

All variables prefixed with --ms-

COLORS
------
Primary colors (defaults; most read a --base-* token first, then fall back):

--ms-accent-color: var(--base-primary-color, #3b82f6)   /* Primary brand color */
--ms-accent-color-hover: var(--base-primary-color-hover, <derived from --ms-accent-color>)
--ms-text-color-1: var(--base-text-color-1, light-dark(#334155, #f1f5f9))  /* Main text */
--ms-text-color-3: var(--base-text-color-3, <--ms-text-color-1 mixed 55% into --ms-main-bg>)  /* Muted text */
--ms-border-color: var(--base-border-color, <derived from --ms-main-bg>)  /* Borders / dividers */
--ms-main-bg: var(--base-main-bg, light-dark(#ffffff, #1e293b))  /* Main background */

SIZING / SCALING WITH --ms-rem
------------------------------
There is no size attribute. All sizes are multiples of --ms-rem (default: var(--base-rem, 10px)):

<!-- Compact (80%) -->
<web-multiselect style="--ms-rem: 8px;"></web-multiselect>

<!-- Default (100%) -->
<web-multiselect></web-multiselect>

<!-- Large (120%) - everything scales proportionally; input height = 3.5 x 12 = 42px -->
<web-multiselect style="--ms-rem: 12px;"></web-multiselect>

For targeted control override the individual --ms-input-* variables (see INPUT STYLING), e.g.:
<style>
  web-multiselect {
    --ms-input-height: calc(4.2 * var(--ms-rem));  /* 42px at the default rem */
  }
</style>

Consistent with web-daterangepicker:
Both components use the same --*-rem scaling approach (--ms-rem / --drp-rem).

INPUT STYLING
-------------
Input field variables (defaults):

--ms-input-bg: var(--base-input-bg, var(--ms-main-bg))              /* Input background */
--ms-input-color: var(--base-input-text-color, var(--ms-text-color-1))  /* Input text color */
--ms-input-border-color: var(--base-input-border-color, <--ms-text-color-1 mixed into --ms-main-bg>)
--ms-input-border-focus: var(--base-input-border-focus, var(--ms-border-width) solid var(--ms-accent-color))
--ms-input-padding-h: calc(1.2 * var(--ms-rem))                     /* Horizontal padding */
--ms-input-font-size: calc(var(--base-font-size-sm, 1.4) * var(--ms-rem))  /* Text size */
--ms-input-border-radius: var(--ms-border-radius-md)                /* Border radius */
--ms-input-height: calc(var(--base-input-size-md-height, 3.5) * var(--ms-rem))  /* Height */
--ms-input-placeholder-color: var(--base-input-placeholder-color, var(--ms-text-color-3))

Example:
<style>
  web-multiselect {
    --ms-input-border-radius: 0.5rem;
    --ms-input-height: 3rem;
    --ms-input-padding-h: 1rem;
  }
</style>

DROPDOWN STYLING
----------------
Dropdown/popover variables (defaults):

--ms-dropdown-bg: var(--base-dropdown-bg, var(--ms-main-bg))
--ms-dropdown-border-color: var(--ms-border-color)
--ms-dropdown-box-shadow: var(--base-dropdown-box-shadow, 0 8px 16px var(--ms-shadow-color))
--ms-dropdown-border-radius: var(--ms-border-radius-lg)
--ms-options-max-height: calc(32 * var(--ms-rem))   /* Max height of the options list */
--ms-dropdown-width: var(--ms-input-current-width)  /* Width = the live input width */
--ms-options-padding: 0
--ms-z-index-dropdown: var(--base-z-dropdown, 7500)

Width: set --ms-dropdown-width to fix the panel width (e.g. 60rem). To bound it instead,
use the dropdown-min-width / dropdown-max-width attributes (any CSS length):
<web-multiselect dropdown-min-width="20rem" dropdown-max-width="40rem"></web-multiselect>

Shadow example:
<style>
  web-multiselect {
    --ms-dropdown-box-shadow: 0 10px 15px -3px rgba(0, 0, 0, 0.1);
  }
</style>

<style>
  web-multiselect {
    --ms-badge-text-bg: #eff6ff;
    --ms-badge-text-color: #3b82f6;
    --ms-badge-counter-text-bg: #d1d5db;  /* Different for count mode */
    --ms-badge-counter-text-color: #6b7280;
  }
</style>

CHECKBOX STYLING
----------------
Checkbox variables (defaults):

--ms-checkbox-size: calc(1.6 * var(--ms-rem))        /* Checkbox size */
--ms-checkbox-border-color: var(--base-checkbox-border-color, var(--ms-input-border-color))
--ms-checkbox-bg: var(--ms-input-bg)                 /* Background */
--ms-checkbox-checked-bg: var(--ms-accent-color)     /* Checked background */
--ms-checkbox-checked-border: var(--ms-checkbox-border-width-scaled) solid var(--ms-accent-color)
--ms-checkbox-scale: var(--base-checkbox-scale, 1)   /* Scale multiplier */
--ms-checkbox-margin-top: 0                          /* Top spacing */
--ms-checkbox-align: center                          /* Vertical alignment */

Alignment: use the checkbox-align attribute (top | center (default) | bottom):
<web-multiselect checkbox-align="top"></web-multiselect>

The attribute marks each row with data-checkbox-align, and options.css overrides
--ms-checkbox-align per row (top = first baseline: the checkbox sits on the first text line) - so prefer the
attribute over setting --ms-checkbox-align on the host.

Example:
<style>
  web-multiselect {
    --ms-checkbox-size: 18px;
  }
</style>

      /* Text */
      --ms-text-color-1: #f9fafb;
      --ms-text-color-3: #d1d5db;

      /* Borders */
      --ms-border-color: #374151;

      /* Input */
      --ms-input-bg: #374151;

      --ms-input-border-color: #4b5563;

      /* Dropdown */
      --ms-dropdown-bg: #374151;
      --ms-dropdown-border-color: #4b5563;

      /* Options */

      --ms-option-bg-focused: #1e3a8a;

</style>

STYLESHEET CUSTOMIZATION (NO SCSS)
----------------------------------
There is no SCSS entry point (the SCSS source was replaced by plain CSS + --ms-* variables).
Theme with the --ms-* variables above (set on the <web-multiselect> element itself), page-wide
--base-* tokens from @keenmate/base-css-variables, or getCustomStylesCallback. The plain CSS
source ships as '@keenmate/web-multiselect/css' (src/css/main.css) for bundlers that process CSS.

CUSTOM STYLES CALLBACK
----------------------
Inject CSS into Shadow DOM:

select.getCustomStylesCallback = (ctx) => {
  return `
    .custom-option {
      display: flex;
      align-items: center;
      gap: 0.5rem;
    }

    .option-focused {
      background: linear-gradient(to right, #3b82f6, #8b5cf6);
      color: white;
    }

    .badge-urgent {
      --ms-badge-text-bg: #fee2e2;
      --ms-badge-text-color: #dc2626;
      font-weight: 600;
    }

    .custom-checkbox {
      border-radius: 50%;  /* Round checkboxes */
    }
  `;
};

RESPONSIVE STYLING
------------------
Adjust for different screen sizes:

<style>
  web-multiselect {
    --ms-input-height: 3rem;
    --ms-badge-height: 36px;
  }

  @media (max-width: 768px) {
    web-multiselect {
      --ms-input-height: 2.5rem;
      --ms-badge-height: 32px;
      --ms-option-padding: 0.5rem 1rem;
      --ms-options-max-height: 15rem;
    }
  }
</style>

RTL STYLING
-----------
Variables automatically flip for RTL:

<style>
  web-multiselect[dir="rtl"] {
    /* Text alignment automatic */
    /* Badge positioning automatic */
    /* Icons flipped automatic */
  }
</style>

See rtl-support.txt for details

SHADOW DOM LIMITATIONS
----------------------
Cannot style internal elements directly:

❌ Doesn't work:
<style>
  web-multiselect .option {
    color: red;
  }
</style>

✅ Use CSS variables instead:
<style>
  web-multiselect {
    --ms-option-text-color: red;
  }
</style>

Or getCustomStylesCallback for complex styling

BROWSER COMPATIBILITY
---------------------
The standalone colour fallbacks use relative-colour syntax (oklch(from ...) / color(from ...)),
so the floor is the same as @keenmate/base-css-variables 2.x:
- Chrome/Edge 119+
- Firefox 128+
- Safari 18+

PERFORMANCE
-----------
CSS variable changes are fast:
- No style recalculation
- Hardware accelerated
- Smooth transitions

Changing many variables:
<style>
  web-multiselect.custom-theme {
    --ms-accent-color: #10b981;
    --ms-accent-color-hover: #059669;
    /* ... 20+ variables */
  }
</style>

Performance impact: Minimal

THEMING FRAMEWORKS
------------------
Tailwind CSS:
No direct integration (Shadow DOM)

Use CSS variables:
<style>
  web-multiselect {
    --ms-accent-color: theme('colors.blue.500');
    --ms-border-radius: theme('borderRadius.lg');
  }
</style>

Bootstrap:
Similar approach with CSS variables

DEBUGGING STYLES
----------------
Inspect Shadow DOM:

1. Open DevTools
2. Find <web-multiselect> element
3. Expand #shadow-root
4. Inspect internal elements
5. See applied CSS variables

Check variable values:
const select = document.querySelector('web-multiselect');
const styles = getComputedStyle(select);
console.log(styles.getPropertyValue('--ms-accent-color'));

BEST PRACTICES
--------------
✅ Use CSS variables for customization
✅ Create theme classes for variations
✅ Test dark mode
✅ Test responsive layouts
✅ Use getCustomStylesCallback for complex styles
✅ Keep consistent color scheme
✅ Test accessibility (contrast)

❌ Don't try to pierce Shadow DOM
❌ Don't use !important (usually not needed)
❌ Don't forget dark mode
❌ Don't set too many variables
❌ Don't ignore contrast ratios
