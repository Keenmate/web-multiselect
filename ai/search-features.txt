SEARCH FEATURES
===============

CRITICAL: Two search modes with different behaviors
- Filter mode (default): Hides non-matching options
- Navigate mode: Jumps to matches, keeps all visible
- Async search: Load options dynamically from server
- Hybrid search: Initial options + dynamic search

ENABLING SEARCH
---------------
Search is enabled by default:

<web-multiselect enable-search="true">
  <option value="1">JavaScript</option>
  <option value="2">TypeScript</option>
</web-multiselect>

Disable search:
<web-multiselect enable-search="false">
</web-multiselect>

Programmatic:
select.enableSearch = true;  // or false

SEARCH PLACEHOLDER
------------------
Customize search input placeholder:

<web-multiselect labels='{"searchPlaceholder": "Search languages..."}'>
</web-multiselect>

Programmatic:
select.labels = { searchPlaceholder: 'Type to search...' };

FILTER MODE (DEFAULT)
---------------------
Hides options that don't match search:

<web-multiselect search-mode="filter">
  <option value="1">JavaScript</option>
  <option value="2">TypeScript</option>
  <option value="3">Python</option>
</web-multiselect>

Behavior:
- Type "script" → Shows JavaScript, TypeScript
- Type "python" → Shows Python only
- Clear search → Shows all options
- Non-matching options hidden

Use when:
- Filtering large lists
- Finding specific items
- Reducing visual clutter

NAVIGATE MODE
--------------
Jumps to first match, keeps all options visible:

<web-multiselect search-mode="navigate">
  <option value="1">JavaScript</option>
  <option value="2">TypeScript</option>
  <option value="3">Python</option>
</web-multiselect>

Behavior:
- Type "script" → Highlights JavaScript
- Ctrl+↓ → Jumps to next match (TypeScript)
- All options remain visible
- Matching items highlighted

Use when:
- Quick keyboard navigation
- Users need to see all options
- Dropdown has contextual grouping

INTERNAL SEARCH vs YOUR OWN SEARCH
----------------------------------
Two separate paths:
- Internal search (no searchCallback): search-behavior + search-match + getSearchTermCallback.
- Own search (searchCallback): you normalize/match however you want; search-behavior and
  search-match do NOT apply.

Internal pipeline:
  option: searchValueMember / getSearchValueCallback (string) → else display value
          → normalizeSearchText per search-behavior — PREPARED ONCE per option (cached)
  term:   beforeSearchCallback → getSearchTermCallback (or trim + normalize) → match per search-match

SEARCH BEHAVIOR (NORMALIZATION)
<web-multiselect search-behavior="normalized">   <!-- default -->
- Ignores case AND diacritics: "ces" finds "Český", "muller" finds "Müller", "lodz" finds "Łódź"
<web-multiselect search-behavior="case-insensitive">
- Ignores case only: "čes" finds "Český", "ces" does not
<web-multiselect search-behavior="exact">
- Case- and diacritic-sensitive
All modes compare Unicode NFC text; the <mark> highlight follows the same rules.

SEARCH MATCH
<web-multiselect search-match="contains">          <!-- default: anywhere -->
<web-multiselect search-match="equals">            <!-- whole value, e.g. codes: "haxkl324" finds "HAxKL324" -->
<web-multiselect search-match="starts-with">       <!-- start of the whole value -->
<web-multiselect search-match="word-starts-with">  <!-- start of any word: "kru" finds "Český Krumlov" -->
<web-multiselect search-match="ends-with">         <!-- end of the whole value -->
<web-multiselect search-match="word-ends-with">    <!-- end of any word -->
<web-multiselect search-match="regex">             <!-- term is a pattern -->
WARNING: regex is tested against the RAW search value — search-behavior is NOT applied, so
case/accents are up to the pattern. An invalid typed pattern keeps the last valid result.

Both search-behavior and search-match are live: changing them re-runs the current search.

getSearchTermCallback({ term, target, behavior, match }):
- target 'internal': return a string (used as-is; normalize it yourself) or a RegExp
  (tested against the raw value). null / '' = no search.
    select.getSearchTermCallback = ({ term }) =>
      new RegExp(term.split(/[^a-z0-9]+/i).filter(Boolean).join('[^a-z0-9]*'), 'i');
    // "ha-324/56" finds "HA 324-56", "HA32456"
- target 'callback': return anything (objects too) — arrives as ctx.term.

searchCallback({ term, signal, entries }) — sync or async (signal is aborted
when a newer search supersedes this one):
- entries: [{ data, searchValue }] with the RAW getSearchValueCallback output (may be an
  object). Built on first access, each value computed once, SAME array until options change.
    select.getSearchValueCallback = ({ option }) => ({ title: normalizeSearchText(option.name), zip: option.zip });
    select.searchCallback = ({ term, entries }) =>
      entries.filter(e => e.searchValue.zip.startsWith(term.zip)).map(e => e.data);
- An object search value WITHOUT searchCallback: internal search uses the display value (warns).

normalizeSearchText(text, behavior = 'normalized') is exported for custom search:
    import { normalizeSearchText } from '@keenmate/web-multiselect';

MINIMUM SEARCH LENGTH
---------------------

</web-multiselect>

Programmatic:

Behavior:
- Search doesn't activate until threshold met
- Shows all options below threshold
- Useful for large datasets
- Reduces unnecessary filtering

Use cases:
- Large option lists
- Async search (reduce API calls)

SEARCH VALUE CUSTOMIZATION
---------------------------
Control what text is searched:

Default (searches display value):
select.options = [
  { value: 1, label: 'JavaScript' }
];
// Searches "JavaScript"

Member property:
select.searchValueMember = 'searchTerm';
select.options = [
  {
    value: 1,
    label: 'JavaScript',
    searchTerm: 'javascript js ecmascript'
  }
];
// Searches "javascript js ecmascript"

Callback:
select.getSearchValueCallback = ({ option }) => {
  return `${option.name} ${option.aliases.join(' ')} ${option.tags.join(' ')}`;
};
// Searches name + aliases + tags

ASYNC SEARCH
------------
Load options from server based on search term:

select.searchCallback = async ({ term, signal }) => {
  const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });
  const results = await response.json();
  return results;
};

IMPORTANT: Return array of options or Promise<options[]>

Debouncing is built in (search-debounce, async searchCallback only); a superseded
request is aborted via ctx.signal:
<web-multiselect search-debounce="300"></web-multiselect>

HYBRID SEARCH
-------------
Combine static initial options with dynamic search:

<web-multiselect keep-options-on-search="true">
</web-multiselect>

select.options = [
  // Top 10 popular items
  { value: 1, label: 'JavaScript' },
  { value: 2, label: 'Python' },
  { value: 3, label: 'TypeScript' }
];

select.searchCallback = async ({ term, signal }) => {
  // Load additional results from server
  const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });
  return await response.json();
};

Behavior:
- Shows initial options when dropdown opens
- When user searches, adds dynamic results
- Initial options remain visible
- Perfect for "popular items + search all"

SEARCH PRE-PROCESSING
---------------------
Modify search term before searching:

Return a string to replace the term, false to skip the search (the full list shows),
or nothing to continue unchanged.

select.beforeSearchCallback = ({ term }) => {
  // Remove accents
  return term.normalize('NFD').replace(/[\u0300-\u036f]/g, '');
};

Or validate:
select.beforeSearchCallback = ({ term }) => {
  // Only allow alphanumeric
  const cleaned = term.replace(/[^a-z0-9]/gi, '');
  return cleaned || false;  // Return false to skip the search
};

Or transform:
select.beforeSearchCallback = ({ term }) => {
  return term.toLowerCase().trim();
};

SEARCH MATCHING
---------------
Default: Case-insensitive substring match

Custom matching (via searchCallback):
select.searchCallback = async ({ term: raw, controller }) => {
  const term = raw.toLowerCase();

  return controller.options.filter(option => {
    const searchValue = option.label.toLowerCase();

    // Fuzzy match
    return searchValue.includes(term) ||
           levenshteinDistance(searchValue, term) < 3;
  });
};

Or exact match:
select.searchCallback = ({ term, controller }) => {
  return controller.options.filter(option =>
    option.label.toLowerCase() === term.toLowerCase()
  );
};

ADDING NEW OPTIONS
------------------
Allow users to add custom values:

<web-multiselect allow-add-new="true">
</web-multiselect>

beforeAddCallback({ value }) → return the option (appended + selected, then the `add`
event fires), false to cancel, or nothing to only fire `add` (create it yourself).

select.beforeAddCallback = ({ value }) => {
  // Create new option
  return {
    value: value.toLowerCase(),
    label: value,
    icon: '➕'
  };
};

Or async:
select.beforeAddCallback = async ({ value }) => {
  // Save to server (a spinner shows meanwhile)
  const response = await fetch('/api/items', {
    method: 'POST',
    body: JSON.stringify({ name: value })
  });
  const newItem = await response.json();

  return {
    value: newItem.id,
    label: newItem.name
  };
};

SEARCH CACHING
--------------
Cache async search results:

const searchCache = new Map();

select.searchCallback = async ({ term, signal }) => {
  // Check cache
  if (searchCache.has(term)) {
    return searchCache.get(term);
  }

  // Fetch from API
  const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });
  const results = await response.json();

  // Cache results
  searchCache.set(term, results);

  return results;
};

SEARCH HIGHLIGHTING
-------------------
Matching text is automatically highlighted in navigate mode

Custom highlighting (via renderOptionContentCallback):
let searchTerm = '';
select.beforeSearchCallback = ({ term }) => { searchTerm = term; };  // remember the term

select.renderOptionContentCallback = ({ option, isMatched }) => {
  if (!isMatched || !searchTerm) {
    return option.label;
  }

  const label = option.label;
  const index = label.toLowerCase().indexOf(searchTerm.toLowerCase());

  if (index === -1) return label;

  const before = label.substring(0, index);
  const match = label.substring(index, index + searchTerm.length);
  const after = label.substring(index + searchTerm.length);

  return `${before}<mark>${match}</mark>${after}`;
};

SEARCH ANALYTICS
----------------
Track search behavior:

select.searchCallback = async ({ term }) => {
  // Log search
  analytics.track('search', { term });

    count: results.length

};

BEST PRACTICES
--------------
✅ Use filter mode for large lists
✅ Use navigate mode for keyboard-heavy users
✅ Set min-search-length for async search
✅ Debounce async search (300ms)
✅ Cache frequent searches
✅ Show loading indicator
✅ Provide helpful empty message
✅ Use hybrid search for popular items
✅ Normalize search terms (accents, case)

❌ Don't search without min length on huge datasets
❌ Don't forget error handling in async search
❌ Don't make too many API calls
❌ Don't block UI during search
❌ Don't forget to handle empty results
