EVENTS & CALLBACKS
==================

CRITICAL: Two ways to handle component interactions
- DOM Events: select, deselect, change, ready (CustomEvent)
- Callback Functions: All get*/render*/before* callbacks
- Events for listening, callbacks for side effects
- Both provide access to component state

DOM EVENTS
----------
Three main selection events:

select event:
Fired when option is selected

select.addEventListener('select', (e) => {
  console.log('Selected:', e.detail.option);
  console.log('All selected:', e.detail.selectedOptions);
});

Event detail:
{
  option: { value, label, ... },        // Newly selected option
  selectedOptions: [{ value, label }]   // All selected options
}

deselect event:
Fired when option is deselected

select.addEventListener('deselect', (e) => {
  console.log('Deselected:', e.detail.option);
  console.log('Remaining:', e.detail.selectedOptions);
});

Event detail:
{
  option: { value, label, ... },        // Deselected option
  selectedOptions: [{ value, label }]   // Remaining selected options
}

change event:
Fired when selection changes (any select/deselect)

select.addEventListener('change', (e) => {
  console.log('Selected options:', e.detail.selectedOptions);
  console.log('Selected values:', e.detail.selectedValues);
});

Event detail:
{
  selectedOptions: [{ value, label }],  // All selected option objects
  selectedValues: [value1, value2]      // All selected values
}

ready event:
Fired once, right after the FIRST build — synchronously during upgrade for a
normal element, or when a `defer` render gate is released (via ready() / removing
the attribute) for a deferred one. No detail. Bubbles + composed.

select.addEventListener('ready', () => {
  // the picker is built and painted — safe to read state, focus it, etc.
});

// See advanced-patterns.txt (DEFERRED INITIALIZATION) for defer / ready() / isReady.

CALLBACK FUNCTIONS
------------------
All available callbacks:

Data extraction:
- getValueCallback(item): Extract value
- getDisplayValueCallback(item): Display text
- getBadgeDisplayCallback(item): Badge text
- getSearchValueCallback(item): Search text
- getIconCallback(item): Icon
- getSubtitleCallback(item): Subtitle
- getGroupCallback(item): Group name
- getDisabledCallback(item): Disabled state

Custom rendering:
- renderOptionContentCallback(item, context): Dropdown option HTML
- renderBadgeContentCallback(item, context): Badge HTML
- renderSelectedItemContentCallback(item): Popover item HTML
- renderSelectedContentCallback(item): Single-select text
- getBadgeClassCallback(item): Badge CSS classes
- getSelectedItemClassCallback(item): Popover item classes
- customStylesCallback(): Inject CSS

Interaction:
- searchCallback(searchTerm): Async search
- beforeSearchCallback(searchTerm): Pre-process search
- addNewCallback(value): Handle new option
- selectCallback(option): Before select
- deselectCallback(option): Before deselect
- changeCallback(selectedOptions): After change

Formatting:
- getCounterCallback(count, moreCount): Counter text
- getBadgeTooltipCallback(item): Badge tooltip
- getValueFormatCallback(values): Form value format

SELECTION CALLBACKS
-------------------
React to selection changes:

selectCallback:
Called AFTER an option has been added to the selection (same commit() pass
that dispatches the 'select' event). Selection is already committed — the
callback CANNOT cancel it. Returning early has no effect on the selection.

select.selectCallback = (option) => {
  console.log('Just selected:', option);
};

deselectCallback:
Called AFTER an option has been removed from the selection. Cannot cancel
the removal. For "are you sure?" style flows see PREVENTING ACTIONS below
— the only option is post-commit rollback via setSelected().

select.deselectCallback = (option) => {
  console.log('Just deselected:', option);
};

changeCallback:
Called after selection changes

select.changeCallback = (selectedOptions) => {
  console.log('Selection changed:', selectedOptions);

  // Update UI
  updateRelatedFields(selectedOptions);

  // Analytics
  trackSelection(selectedOptions);
};

SEARCH CALLBACKS
----------------
Handle search interactions:

searchCallback:
Load options dynamically

select.searchCallback = async (searchTerm) => {
  if (searchTerm.length < 3) return [];

  const response = await fetch(`/api/search?q=${searchTerm}`);
  const results = await response.json();

  return results;  // Must return array of options
};

beforeSearchCallback:
Pre-process search term

select.beforeSearchCallback = (searchTerm) => {
  // Remove accents
  const normalized = searchTerm.normalize('NFD')
    .replace(/[\u0300-\u036f]/g, '');

  // Return processed term or null to cancel
  return normalized.toLowerCase();
};

ADD NEW CALLBACK
----------------
Handle custom option creation:

select.addNewCallback = (value) => {
  console.log('Adding new:', value);

  // Create new option
  return {
    value: value.toLowerCase(),
    label: value,
    icon: '➕',
    isNew: true
  };
};

Or async:
select.addNewCallback = async (value) => {
  // Save to server
  const response = await fetch('/api/items', {
    method: 'POST',
    body: JSON.stringify({ name: value })
  });

  const item = await response.json();

  return {
    value: item.id,
    label: item.name
  };
};

Dropdown display text

select.getDisplayValueCallback = (option) => {
  return `${option.firstName} ${option.lastName}`;

getBadgeDisplayCallback:
Badge display text (can differ from dropdown)

select.getBadgeDisplayCallback = (option) => {

COUNTER CALLBACK
----------------
Customize counter text:

select.getCounterCallback = (count, moreCount) => {
  // Count mode
  if (!moreCount) {
    return count === 1 ? '1 selected' : `${count} selected`;
  }

  // Compact/partial mode
  return `+${moreCount} more`;
};

Internationalization:
select.getCounterCallback = (count, moreCount) => {
  const locale = 'es';  // Spanish

  const translations = {
    en: {
      single: '1 selected',
      multiple: (n) => `${n} selected`,
      more: (n) => `+${n} more`
    },
    es: {
      single: '1 seleccionado',
      multiple: (n) => `${n} seleccionados`,
      more: (n) => `+${n} más`
    }
  };

  const t = translations[locale];

  if (moreCount) {
    return t.more(moreCount);
  }

  return count === 1 ? t.single : t.multiple(count);
};

TOOLTIP CALLBACK
----------------
Customize badge tooltips:

select.getBadgeTooltipCallback = (option) => {
  return `${option.label}\n${option.description}`;
};

Or return HTMLElement:
select.getBadgeTooltipCallback = (option) => {
  const div = document.createElement('div');
  div.innerHTML = `
    <strong>${option.label}</strong><br>
    <small>${option.description}</small>

VALUE FORMAT CALLBACK
---------------------
Custom form value serialization:

select.getValueFormatCallback = (values) => {
  // Pipe-separated
  return values.join('|');

Or with metadata:
select.getValueFormatCallback = (values) => {
  return JSON.stringify({

};

EVENT VS CALLBACK
-----------------
When to use each:

Use DOM Events when:
✅ Listening from outside component
✅ Multiple listeners needed
✅ Framework event binding
✅ Bubbling/capturing needed

Use Callbacks when:
✅ Side effects during operation
✅ Modifying behavior
✅ Single handler sufficient
✅ Performance critical

Example - Both together:
// Callback: Update dependent field
select.changeCallback = (selected) => {
  updateDependentField(selected);
};

// Event: Update multiple parts of UI
select.addEventListener('change', (e) => {
  updateChart(e.detail.selectedOptions);
  updateSummary(e.detail.selectedOptions);
});

EVENT BUBBLING
--------------
Events DO bubble and DO cross shadow DOM boundaries.
Dispatched as `new CustomEvent(name, { detail, bubbles: true, composed: true })`
— see web-component.ts dispatch sites.

This means:
- addEventListener can be attached to the <web-multiselect> host OR any ancestor
- Framework delegation works out of the box:
    Svelte 5: onchange={handler}   (callback prop)
    Svelte 4: on:change={handler}  (directive — also still works in Svelte 5)
    React:    onChange={handler}
    Vue:      @change="handler"
- composed: true lets the event escape an enclosing shadow DOM (e.g. when
  this component is wrapped by another web component)

COLLISION WARNING — 'change' and 'select' are also native DOM event names:
- Form-level listeners using event delegation will receive both native
  form-control changes and our 'change' events. Filter by target:
    form.addEventListener('change', (e) => {
      if (e.target.tagName === 'WEB-MULTISELECT') return; // or handle separately
      // ... handle native input/select/textarea change
    });
- 'select' collides with the native text-selection event from
  <input>/<textarea>. Same filter pattern applies if delegating at a
  container level.

CANCELLATION:
- Events fire AFTER the selection is committed, so preventDefault() does
  nothing — there is nothing to cancel. cancelable is false.
- stopPropagation() DOES work and will prevent ancestor listeners (including
  framework delegation roots) from seeing the event. Use sparingly — calling
  stopPropagation in a handler can break framework-level event routing.

If you want to react to selection changes WITHOUT also receiving native
form/text events at the same handler, attach the listener directly on the
<web-multiselect> host:
const select = document.querySelector('web-multiselect');
select.addEventListener('change', (e) => { ... });

PREVENTING ACTIONS
------------------
Callbacks fire AFTER the selection has been committed — they cannot cancel.
The "prevent" pattern is a silent rollback via setSelected().

Workaround for preventing deselection:
select.deselectCallback = (option) => {
  if (option.required) {
    alert('Cannot remove required item');

    // Re-add after a tick. NOTE: setSelected is SILENT (see
    // PROGRAMMATIC SELECTION — WHICH METHODS FIRE EVENTS below).
    // The rollback restores the visual state but does NOT fire a fresh
    // 'select'/'change' event, so downstream listeners won't see the rebound.
    setTimeout(() => {
      const current = select.getValue();
      const arr = Array.isArray(current) ? current : (current != null ? [current] : []);
      select.setSelected([...arr, option.value]);
    }, 0);
  }
};

SINGLE-SELECT EVENT SEMANTICS
-----------------------------
In single-select mode (multiple="false") replacing the current selection
is NOT modeled as deselect-then-select. Picking a different item when
one is already selected:

- DOES fire: 'select' (new item) → 'change'
- DOES NOT fire: 'deselect' for the displaced item

The previous item is cleared silently inside the picker's internal state
(multiselect.ts toggleOption single-mode branch — selectedValues.clear()
runs without going through deselectOption). Do not rely on 'deselect' to
detect "the previous item is gone" in single-select mode.

Clicking the already-selected item DOES fire 'deselect' + 'change' (the
selection becomes empty — single-select tolerates 0 items).

If you need to react to replacement in single mode, diff against your
own previous value in the 'change' handler:

let lastValue = null;
select.addEventListener('change', (e) => {
  const newValue = e.detail.selectedValues[0] ?? null;
  if (lastValue !== null && lastValue !== newValue) {
    console.log('Replaced:', lastValue, '→', newValue);
  }
  lastValue = newValue;
});

PROGRAMMATIC SELECTION — WHICH METHODS FIRE EVENTS
---------------------------------------------------
Not every programmatic state change is observable via events. The rule
is "anything that goes through the commit() helper fires events":

setSelected(values):    SILENT  (no select/deselect/change)
clearAll():             FIRES   ('deselect' per removed + one 'change')
"Select All" action:    FIRES   ('select' per added + one 'change')
"Clear All" action:     FIRES   (calls clearAll internally)
User click / keyboard:  FIRES

setSelected is silent BY DESIGN — it's the right tool for "update state
without re-triggering my own listeners":
  - action-menu reset after handling a pick
  - parent-driven state sync from a store
  - silent rollback in preventing-action workarounds

clearAll is the right tool for "clear AND notify":
  - reset buttons users see
  - form.reset() — the component's formResetCallback uses clearAll

If you need "setSelected but with events", re-dispatch a 'change' manually:

select.setSelected(values);
select.dispatchEvent(new CustomEvent('change', {
  detail: {
    selectedOptions: select.getSelected(),
    selectedValues: (() => {
      const v = select.getValue();
      return Array.isArray(v) ? v : (v != null ? [v] : []);
    })()
  }
}));

ASYNC CALLBACKS
---------------
Handle async operations:

select.changeCallback = async (selectedOptions) => {
  // Save to server
  await fetch('/api/save', {
    method: 'POST',
    body: JSON.stringify({
      selections: selectedOptions.map(o => o.value)
    })
  });

  console.log('Saved');
};

ERROR HANDLING
--------------
Handle errors in callbacks:

select.searchCallback = async (searchTerm) => {
  try {
    const response = await fetch(`/api/search?q=${searchTerm}`);

    if (!response.ok) {
      throw new Error('Search failed');
    }

    return await response.json();
  } catch (error) {
    console.error('Search error:', error);
    return [];  // Return empty array on error
  }
};

CALLBACK CONTEXT
----------------
Access component in callbacks:

select.changeCallback = (selectedOptions) => {
  // Access component properties
  const allOptions = select.options;
  const searchTerm = select.searchTerm;
  const isMultiple = select.multiple;

  console.log('Selected:', selectedOptions.length);
  console.log('Total:', allOptions.length);
  console.log('Search:', searchTerm);
  console.log('Multiple:', isMultiple);
};

MULTIPLE CALLBACKS
------------------
Set multiple callbacks:

// Data callbacks
select.getValueCallback = (item) => item.id;
select.getDisplayValueCallback = (item) => item.name;
select.getSearchValueCallback = (item) => `${item.name} ${item.email}`;

// Interaction callbacks
select.selectCallback = (option) => console.log('Select:', option);
select.changeCallback = (selected) => updateUI(selected);

// Rendering callbacks
select.renderOptionContentCallback = (item, ctx) => `${item.name}`;
select.getBadgeDisplayCallback = (item) => item.code;

CALLBACK PERFORMANCE
--------------------
Optimize callbacks for performance:

❌ Slow: Expensive operation every render
select.renderOptionContentCallback = (option) => {
  const data = expensiveCalculation(option);  // Called many times!
  return `<div>${data}</div>`;
};

✅ Fast: Cache results
const cache = new Map();
select.renderOptionContentCallback = (option) => {
  if (!cache.has(option.value)) {
    cache.set(option.value, expensiveCalculation(option));
  }
  return `<div>${cache.get(option.value)}</div>`;
};

REMOVING CALLBACKS
------------------
Clear callbacks:

select.selectCallback = null;
select.deselectCallback = null;
select.changeCallback = null;

DEBUGGING
---------
Log all events and callbacks:

// Log all events
['select', 'deselect', 'change'].forEach(eventName => {
  select.addEventListener(eventName, (e) => {
    console.log(`Event: ${eventName}`, e.detail);
  });
});

// Log callbacks
select.changeCallback = (selected) => {
  console.log('Callback: change', selected);
};

BEST PRACTICES
--------------
✅ Use events for UI updates
✅ Use callbacks for data transformation
✅ Handle async errors gracefully
✅ Keep callbacks fast
✅ Cache expensive calculations
✅ Use both events and callbacks when needed
✅ Clean up event listeners when done

❌ Don't do heavy computation in callbacks
❌ Don't forget error handling
❌ Don't rely on callback execution order
❌ Don't mutate data in callbacks
❌ Don't forget to remove event listeners

select.changeCallback = (selected) => {
  dependentSelect.options = getFilteredOptions(selected);

select.selectCallback = (option) => {
  analytics.track('option_selected', {
