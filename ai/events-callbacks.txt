EVENTS & CALLBACKS
==================

CRITICAL: Two ways to handle component interactions
- DOM Events: select, deselect, change, add, action, ready (CustomEvent, detail in e.detail)
- on* property twins: onSelect, onDeselect, onChange, onAdd, onAction, onReady, onOpen, onClose,
  onValueFormatError —
  receive the DETAIL (not the CustomEvent): el.onSelect = (detail) => detail.option
- Callback Functions: all get*/render*/before* callbacks take ONE `ctx` argument
  (per-option callbacks read ctx.option; selectedOrderCompareCallback({ a, b }))
- Before-hooks: return false to cancel, nothing to continue, a value to replace
- Every ctx and every event detail carries `controller` (the public facade, also
  el.controller) and `element` (the host) — both non-enumerable, so JSON.stringify / logs /
  LiveView pushEvent see only the data — plus presentation, isFullscreen, isModal

DOM EVENTS
----------
Selection events:

select event:
Fired when an option is selected

select.addEventListener('select', (e) => {
  console.log('Selected:', e.detail.option);
  console.log('All selected:', e.detail.selectedOptions);
});

Event detail (SelectEventDetail):
{
  option: { value, label, ... },        // Newly selected option
  selectedOptions: [{ value, label }],  // All selected options
  selectedValues: [value1, value2]      // All selected values
}

deselect event:
Fired when an option is deselected

select.addEventListener('deselect', (e) => {
  console.log('Deselected:', e.detail.option);
  console.log('Remaining:', e.detail.selectedOptions);
});

Event detail (DeselectEventDetail): same shape as select.

change event:
Fired when the selection changes (any select/deselect; a bulk gesture fires ONE change)

select.addEventListener('change', (e) => {
  console.log('Selected options:', e.detail.selectedOptions);
  console.log('Selected values:', e.detail.selectedValues);
});

Event detail (ChangeEventDetail):
{
  selectedOptions: [{ value, label }],  // All selected option objects
  selectedValues: [value1, value2]      // All selected values
}

add event:
Fired when the user creates an option from the typed text (requires allow-add-new).
detail (AddEventDetail): { value, option?, selectedOptions, selectedValues } — `option` is
set when beforeAddCallback returned one.

action event:
Fired for every action button (built-in or custom) and every `data-action` element inside
rendered option content (source 'option'), badge content (source 'badge') or a showMessage
element (source 'message'). See action-buttons.txt.
detail (MultiSelectActionEventDetail): action, id, item, source, option?, sourceEvent,
triggerElement, dataset, plus the selection snapshot (selectedValues, selectedOptions,
options, selectedCount, optionCount, isOpen, searchTerm).

ready event:
Fired once, on the microtask after the FIRST build (a listener added right after
createElement / the import still catches it) — for a normal element at upgrade, or when a `defer` render gate is released (via release() / removing
the attribute) for a deferred one. detail: { controller, element, presentation… }.
Bubbles (not composed).

select.addEventListener('ready', (e) => {
  // the picker is built and painted — safe to read state, focus it, etc.
  e.detail.controller.open();
});

// See advanced-patterns.txt (DEFERRED INITIALIZATION) for defer / release() / isReady.

open / close events:
Fired when the dropdown opens / closes (any reason, incl. open() / close()). detail:
{ controller, element, presentation… }. Twins: onOpen / onClose.

select.addEventListener('close', (e) => saveDraft(e.detail.controller.selectedValue));

ON* PROPERTY TWINS
------------------
Each event has a camelCase property twin, called with the DETAIL right before the event
is dispatched:

select.onSelect   = (detail) => console.log('Selected', detail.option);
select.onDeselect = (detail) => console.log('Deselected', detail.option);
select.onChange   = ({ selectedValues }) => console.log('Now', selectedValues);
select.onAdd      = ({ value, option }) => console.log('Added', value, option);
select.onAction   = ({ action, id, source }) => console.log('Action', action, id, source);
select.onReady    = ({ controller }) => controller.focusFirst();
select.onOpen     = ({ presentation }) => console.log('Opened as', presentation);
select.onClose    = ({ controller }) => console.log('Closed with', controller.selectedValue);

// OLD (pre-interaction-model): el.onSelect = (e) => e.detail.option  — no longer valid.

CALLBACK FUNCTIONS
------------------
All available callbacks (every one takes ONE ctx argument):

Data extraction (ctx.option = the option):
- getValueCallback({ option }): Extract value
- getDisplayValueCallback({ option }): Display text
- getBadgeDisplayCallback({ option, displayMode, isInPopover }): Badge text
- getSearchValueCallback({ option }): Search text (or object for searchCallback)
- getIconCallback({ option }): Icon
- getSubtitleCallback({ option }): Subtitle
- getGroupCallback({ option }): Group name
- getFullTitleCallback({ option }): Full title
- getIsDisabledCallback({ option }): Disabled state
- getIsSelectableCallback({ option, node }): Tree node selectable
- getPathCallback({ option }): Tree path
- getSelectedOrderCallback({ option }): Selected-order sort key
- selectedOrderCompareCallback({ a, b }): Comparator (Array.prototype.sort result contract)

Custom rendering:
- renderOptionContentCallback({ option, optionIndex, isSelected, isFocused, … }): Dropdown option HTML
- renderBadgeContentCallback({ option, displayMode, isInPopover }): Badge HTML
- renderBadgeCallback({ option, displayMode, isInPopover }): Whole badge HTML
- renderSelectedItemContentCallback({ option, … }): Popover item HTML
- renderSelectedContentCallback({ option }): Single-select text
- renderGroupLabelContentCallback({ groupName, members, selectedCount, … }): Group header
- getBadgeClassCallback({ option, … }): Badge CSS classes
- getSelectedItemClassCallback({ option, … }): Popover item classes
- getCustomStylesCallback(ctx): Inject CSS

Before-hooks (false cancels, nothing continues, a value replaces):
- beforeSearchCallback({ term }): string replaces the term, false skips the search
- beforeSelectCallback({ option, selectedOptions, selectedValues, source }): false vetoes
- beforeDeselectCallback({ option, selectedOptions, selectedValues, source }): false vetoes
- beforeAddCallback({ value }): return the new option, false cancels, nothing → only `add`
- beforeKeydownCallback(ctx): false suppresses the built-in key handling (synchronous)
- beforeActionCallback(detail): false cancels an action item

Search:
- getSearchTermCallback({ term, target, behavior, match }): Prepare the term
- searchCallback({ term, signal, entries }): Custom / async search (term = getSearchTermCallback result when set)

Formatting:
- getCounterCallback({ count, moreCount }): Counter text
- getCountLabelCallback({ selectedCount, totalCount, groupName }): Count chip
- getBadgeTooltipCallback({ option, … }): Badge tooltip
- getOptionTooltipCallback({ option, … }): Option tooltip
- getRemoveButtonTooltipCallback({ option, … }): Remove-button tooltip
- getValueFormatCallback({ selectedValues, selectedOptions }): Form value format (a throw → '' submitted,
  host invalid, `value-format-error` { error, value } / onValueFormatError)
- getAddNewTextCallback({ value }): "Add new" prompt text

SELECTION VETOES
----------------
beforeSelectCallback / beforeDeselectCallback run BEFORE a user gesture changes the
selection — once per option, also for bulk gestures (Select-All, Clear-All, group checkbox,
tree cascade, inline ✕, count ×, "+N more" ×). ctx.source tells which gesture:
'option' | 'badge' | 'group' | 'select-all' | 'clear-selection' | 'clear'.
Vetoed options are skipped; the rest apply in ONE change. May be async.
setSelected() and form reset are veto-free.

A returned string does NOT veto. Explain a veto with showMessage, then return false:

select.beforeSelectCallback = ({ option, selectedOptions, controller }) => {
  if (selectedOptions.length >= 3) {
    controller.showMessage('You can pick at most 3 items', { type: 'warning' });
    return false;
  }
};

select.beforeDeselectCallback = ({ option, controller }) => {
  if (option.required) {
    controller.showMessage(`${option.label} is required`, { type: 'warning' });
    return false;
  }
};

Async confirmation:
select.beforeDeselectCallback = async ({ option }) => {
  const ok = await confirmDialog(`Remove ${option.label}?`);
  if (!ok) return false;
};

REACTING TO SELECTION
---------------------
Use the events or their on* twins (they fire AFTER the selection is committed):

select.onSelect = ({ option }) => {
  console.log('Just selected:', option);
};

select.onChange = ({ selectedOptions }) => {
  // Update UI
  updateRelatedFields(selectedOptions);
  // Analytics
  trackSelection(selectedOptions);
};

SEARCH CALLBACKS
----------------
Handle search interactions:

searchCallback:
Load options dynamically. ctx.signal is aborted when a newer search supersedes this one.

select.searchCallback = async ({ term, signal }) => {
  if (term.length < 3) return [];

  const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });
  const results = await response.json();

  return results;  // Must return array of options
};

beforeSearchCallback:
Pre-process the search term

select.beforeSearchCallback = ({ term }) => {
  // Skip the search entirely for 1-char input (full list shows)
  if (term.length === 1) return false;

  // Return a rewritten term
  return term.normalize('NFD').replace(/[\u0300-\u036f]/g, '').toLowerCase();
};

ADD NEW CALLBACK
----------------
Handle custom option creation (requires allow-add-new):

select.beforeAddCallback = ({ value }) => {
  console.log('Adding new:', value);

  // Return the new option → appended + selected, then `add` fires
  return {
    value: value.toLowerCase(),
    label: value,
    icon: '➕',
    isNew: true
  };
};

Or async (a spinner shows meanwhile):
select.beforeAddCallback = async ({ value }) => {
  const response = await fetch('/api/items', {
    method: 'POST',
    body: JSON.stringify({ name: value })
  });

  if (!response.ok) return false;   // false cancels (no `add` event)

  const item = await response.json();
  return { value: item.id, label: item.name };
};

Return nothing → only the `add` event fires and you create the option yourself:
select.onAdd = ({ value }) => openCreateDialog(value);

DISPLAY CALLBACKS
-----------------
Control text display:

getDisplayValueCallback:
Dropdown display text

select.getDisplayValueCallback = ({ option }) => `${option.firstName} ${option.lastName}`;

getBadgeDisplayCallback:
Badge display text (can differ from dropdown)

select.getBadgeDisplayCallback = ({ option }) => {
  // Show initials in badges
  return option.firstName[0] + option.lastName[0];
};

COUNTER CALLBACK
----------------
Customize counter text:

select.getCounterCallback = ({ count, moreCount }) => {
  // Count mode
  if (moreCount === undefined) {
    return count === 1 ? '1 selected' : `${count} selected`;
  }

  // Compact/partial mode
  return `+${moreCount} more`;
};

Internationalization:
select.getCounterCallback = ({ count, moreCount }) => {
  const locale = 'es';  // Spanish

  const translations = {
    en: {
      single: '1 selected',
      multiple: (n) => `${n} selected`,
      more: (n) => `+${n} more`
    },
    es: {
      single: '1 seleccionado',
      multiple: (n) => `${n} seleccionados`,
      more: (n) => `+${n} más`
    }
  };

  const t = translations[locale];

  if (moreCount !== undefined) {
    return t.more(moreCount);
  }

  return count === 1 ? t.single : t.multiple(count);
};

Count chip (in-input counter + group headers):
select.getCountLabelCallback = ({ selectedCount, totalCount, groupName }) =>
  `${selectedCount}/${totalCount}`;

TOOLTIP CALLBACK
----------------
Customize badge tooltips:

select.getBadgeTooltipCallback = ({ option }) => `${option.label}\n${option.description}`;

Or return HTMLElement:
select.getBadgeTooltipCallback = ({ option }) => {
  const div = document.createElement('div');
  div.innerHTML = `
    <strong>${option.label}</strong><br>
    <small>${option.description}</small>
  `;
  return div;
};

select.getValueFormatCallback = ({ selectedValues }) => {
  // Pipe-separated
  return selectedValues.join('|');

Or with metadata:
select.getValueFormatCallback = ({ selectedValues }) => JSON.stringify({

EVENT VS CALLBACK
-----------------
When to use each:

Use DOM Events (or on* twins) when:
✅ Listening from outside component
✅ Multiple listeners needed (addEventListener)
✅ Framework event binding
✅ Bubbling needed

Use Callbacks when:
✅ Modifying behavior (before* hooks, render*, get*)
✅ Single handler sufficient
✅ Performance critical

Example - Both together:
// Twin: update dependent field
select.onChange = ({ selectedOptions }) => {
  updateDependentField(selectedOptions);
};

// Event: update multiple parts of UI
select.addEventListener('change', (e) => {
  updateChart(e.detail.selectedOptions);
  updateSummary(e.detail.selectedOptions);
});

EVENT BUBBLING
--------------
Events DO bubble but are NOT composed: dispatched on the <web-multiselect> host with
{ bubbles: true, composed: false }.

This means:
- addEventListener can be attached to the <web-multiselect> host OR any ancestor in the
  same tree
- Framework delegation works out of the box:
    Svelte 5: onchange={handler}   (callback prop)
    Svelte 4: on:change={handler}  (directive — also still works in Svelte 5)
    React:    onChange={handler}
    Vue:      @change="handler"
- composed: false — the event does NOT escape an enclosing shadow root. If this component
  is wrapped by another web component, the wrapper must listen on the element (inside its
  shadow root) and re-dispatch.

COLLISION WARNING — 'change' and 'select' are also native DOM event names:
- Form-level listeners using event delegation will receive both native
  form-control changes and our 'change' events. Filter by target:
    form.addEventListener('change', (e) => {
      if (e.target.tagName === 'WEB-MULTISELECT') return; // or handle separately
      // ... handle native input/select/textarea change
    });
- 'select' collides with the native text-selection event from
  <input>/<textarea>. Same filter pattern applies if delegating at a
  container level.

CANCELLATION:
- Events fire AFTER the selection is committed, so preventDefault() does
  nothing — cancelable is false. To cancel, use beforeSelectCallback /
  beforeDeselectCallback (return false) — see SELECTION VETOES.
- stopPropagation() DOES work and will prevent ancestor listeners (including
  framework delegation roots) from seeing the event. Use sparingly.

If you want to react to selection changes WITHOUT also receiving native
form/text events at the same handler, attach the listener directly on the
<web-multiselect> host:
const select = document.querySelector('web-multiselect');
select.addEventListener('change', (e) => { ... });

SINGLE-SELECT EVENT SEMANTICS
-----------------------------
In single-select mode (multiple="false") replacing the current selection
is NOT modeled as deselect-then-select. Picking a different item when
one is already selected:

- DOES fire: 'select' (new item) → 'change'
- DOES NOT fire: 'deselect' for the displaced item

Do not rely on 'deselect' to detect "the previous item is gone" in single-select mode.

Clicking the already-selected item DOES fire 'deselect' + 'change' (the
selection becomes empty — single-select tolerates 0 items).

If you need to react to replacement in single mode, diff against your
own previous value in the 'change' handler:

let lastValue = null;
select.addEventListener('change', (e) => {
  const newValue = e.detail.selectedValues[0] ?? null;
  if (lastValue !== null && lastValue !== newValue) {
    console.log('Replaced:', lastValue, '→', newValue);
  }
  lastValue = newValue;
});

PROGRAMMATIC SELECTION — WHICH METHODS FIRE EVENTS
---------------------------------------------------
el.setSelected(values):                  SILENT, veto-free (no select/deselect/change)
el.setSelected(values, { notify: true }): one aggregate 'change', veto-free
el.controller.clearSelection():                FIRES ('deselect' per removed + one 'change'); vetoes apply
el.controller.selectAll():               FIRES ('select' per added + one 'change'); vetoes apply
el.controller.toggleValue / selectValue / deselectValue: FIRES; vetoes apply
"Select All" / "Clear All" buttons:      FIRES (plus the `action` event)
User click / keyboard:                   FIRES

setSelected is silent BY DESIGN — it's the right tool for "update state
without re-triggering my own listeners":
  - action-menu reset after handling a pick
  - parent-driven state sync from a store

controller.clearSelection is the right tool for "clear AND notify":
  - reset buttons users see

ASYNC HANDLERS
--------------
select.onChange = async ({ selectedValues }) => {
  // Save to server
  await fetch('/api/save', {
    method: 'POST',
    body: JSON.stringify({ selections: selectedValues })
  });

  console.log('Saved');
};

ERROR HANDLING
--------------
Handle errors in callbacks:

select.searchCallback = async ({ term, signal }) => {
  try {
    const response = await fetch(`/api/search?q=${encodeURIComponent(term)}`, { signal });

    if (!response.ok) {
      throw new Error('Search failed');
    }

    return await response.json();
  } catch (error) {
    console.error('Search error:', error);
    return [];  // Return empty array on error
  }
};

A before-hook that throws cancels (the error is logged).

CALLBACK CONTEXT
----------------
Every ctx / detail carries the controller and the host element:

select.onChange = ({ selectedOptions, controller, element }) => {
  const allOptions = controller.options;
  const isOpen = controller.isOpen;

  console.log('Selected:', selectedOptions.length);
  console.log('Total:', allOptions.length);
  console.log('Open:', isOpen);
  console.log('Host id:', element.id);
};

controller (also el.controller): selectedOptions, selectedValue, getOptions(), isOpen,
getOptionByValue(v), setSelected(values, { notify }), selectAll(), clearSelection(), toggleValue(v), selectValue(v),
deselectValue(v), toggleFocused(), open(), close(), toggle(), search(term), clearSearch(),
scrollToValue/Group/Index(), refresh(), focusNext/Previous/First/Last/PageUp/PageDown(),
focusNextMatch/PreviousMatch(), focusIndex(i), showMessage(content, { type, autoHideMs,
placement }), hideMessage().

MULTIPLE CALLBACKS
------------------
Set multiple callbacks:

// Data callbacks
select.getValueCallback = ({ option }) => option.id;
select.getDisplayValueCallback = ({ option }) => option.name;
select.getSearchValueCallback = ({ option }) => `${option.name} ${option.email}`;

// Interaction (event twins)
select.onSelect = ({ option }) => console.log('Select:', option);
select.onChange = ({ selectedOptions }) => updateUI(selectedOptions);

// Rendering callbacks
select.renderOptionContentCallback = ({ option }) => `${option.name}`;
select.getBadgeDisplayCallback = ({ option }) => option.code;

CALLBACK PERFORMANCE
--------------------
Optimize callbacks for performance:

❌ Slow: Expensive operation every render
select.renderOptionContentCallback = ({ option }) => {
  const data = expensiveCalculation(option);  // Called many times!
  return `<div>${data}</div>`;
};

✅ Fast: Cache results
const cache = new Map();
select.renderOptionContentCallback = ({ option }) => {
  if (!cache.has(option.value)) {
    cache.set(option.value, expensiveCalculation(option));
  }
  return `<div>${cache.get(option.value)}</div>`;
};

REMOVING CALLBACKS
------------------
Clear callbacks / twins:

select.onSelect = null;
select.onDeselect = null;
select.onChange = null;
select.beforeSelectCallback = null;

DEBUGGING
---------
Log all events:

['select', 'deselect', 'change', 'add', 'action'].forEach(eventName => {
  select.addEventListener(eventName, (e) => {
    console.log(`Event: ${eventName}`, e.detail);   // controller/element are hidden (non-enumerable)
  });
});

BEST PRACTICES
--------------
✅ Use events / on* twins for UI updates
✅ Use before* callbacks to veto / rewrite (return false to cancel)
✅ Explain a veto with ctx.controller.showMessage(…, { type: 'warning' })
✅ Use callbacks for data transformation
✅ Handle async errors gracefully
✅ Keep callbacks fast
✅ Cache expensive calculations
✅ Clean up event listeners when done

❌ Don't return a string from beforeSelectCallback expecting a veto (it no longer vetoes)
❌ Don't read e.detail inside on* twins — they receive the detail itself
❌ Don't do heavy computation in callbacks
❌ Don't mutate data in callbacks

---------------

select.addEventListener('change', (e) => {

select.onSelect = ({ option }) => {
  analytics.track('option_selected', {
