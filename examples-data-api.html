Drive the dropdown open state from your own code — wizards, "open on step", or custom trigger buttons. Calling open() from a button's own click handler works directly: the component ignores that opening click so it won't immediately re-close.

DA04 · Async Search / Lookup

Load options dynamically as users type. Perfect for large datasets, API searches, or real-time filtering. 

// searchCallback receives { term, signal, … } — forward ctx.signal (an AbortSignal).
// Forward it to fetch — when a newer keystroke supersedes this
// request (or the element is destroyed), the in-flight fetch is
// cancelled instead of racing the newer one.
multiselect.searchCallback = async ({ term: query, signal }) => {
    const response = await fetch(`/api/users?search=${query}`, { signal });
    return await response.json();
};

// Pair with search-debounce="300" to also coalesce keystroke bursts.

API09 · Deferred initialization — defer / release()

Add the defer attribute and the component builds nothing on upgrade — it only reserves space. Wire everything from JS first (options, callbacks like getCustomStylesCallback, event listeners), then call el.release() to build once with all of it already in place. This closes the classic custom-element flash where the component paints with its default styles for a beat before a post-upgrade getCustomStylesCallback (or a framework's shared-stylesheet adoption) restyles it — the styled result appears in one shot.

  • defer — boolean attribute; present = hold the first render
  • release() — release the gate and build once (latched — it never re-closes)
  • Removing the defer attribute also releases it — handy for server-driven frameworks (e.g. Phoenix LiveView) that patch attributes without a JS hook
  • isReady — boolean getter; reflected as the ready attribute (CSS hook :host([defer]:not([ready])) reserves space while held)
  • ready — event dispatched once, right after the first build
state:
held — waiting for data…

Framework integration (e.g. Phoenix LiveView):

<!-- server-rendered markup: `defer` holds the build through the upgrade race -->
<web-multiselect defer phx-update="ignore" id="skills"></web-multiselect>

// in the phx-hook `mounted()` — everything is wired BEFORE the first paint:
const el = this.el;
el.options = JSON.parse(el.dataset.options);
el.getCustomStylesCallback = () => `.ms__badge { background: var(--brand); color: #fff; }`;
el.addEventListener('change', (e) => this.pushEvent('changed', e.detail));
el.release();                       // build once, flash-free
// (or, driven from the server: patch the attribute off — remove `defer`)

API10 · In-place options update & refresh()

Assigning options updates the list in place — the picker is not torn down, so an open dropdown stays open and the selection, scroll and search survive. Handing a fresh-but-equivalent array on every parent re-render (React / Lit / LiveView) is cheap and no longer closes the dropdown. When the option objects are mutated in place, or external state a render callback reads changes, call refresh() to re-render without re-ingesting.

  • el.options = data — the set changed (new array / add / remove): ingest + repaint, in place
  • el.refresh() — same objects mutated, or callback state changed: repaint only (silent — no events)
  • prune-missing-selection — on replace, drop a selected value whose option left the list (default: keep)

The contract — assign when the set changed, refresh when it didn't:

// the SET changed (new array, add/remove) → assign; it repaints itself
el.options = await fetchFromServer();

// same objects mutated in place, or callback state changed → refresh (no new array)
option.disabled = true;           // or: disabledIds.add(id)
el.refresh();                     // silent repaint — never call both after an assign
